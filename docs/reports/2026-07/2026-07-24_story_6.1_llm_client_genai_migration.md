## 1. 문제 요약

`LLMClient`(`src/ai_voicebot/ai_pipeline/llm_client.py`)가 `google-generativeai==0.8.6`
(공식 deprecated) SDK를 사용했고, thinking 비활성화 코드가 이 SDK에 없는 `ThinkingConfig`
타입을 참조하다 조용히 실패해 Gemini 2.5 Flash의 thinking이 단 한 번도 꺼진 적이 없었다
(2026-07-24 근본 원인 확정 리포트). 이로 인해 통화 응대·의도 분류 등 `LLMClient`를 쓰는 모든
경로에서 불필요한 3~9초대 TTFT 지연이 발생했다.

## 2. 근본 원인

- `_thinking_off()`가 `genai.types.ThinkingConfig(thinking_budget=0)`을 생성하려 했으나,
  `google-generativeai==0.8.6`에는 이 타입 자체가 없어 `AttributeError` 발생 → 넓은
  `except (AttributeError, TypeError): pass`가 이 실패를 완전히 침묵시켜왔다.

## 3. 수정 내용

`llm_client.py`를 `google-genai`(v1.75.0, 이미 venv 설치됨) SDK로 전환했다.

1. **임포트/클라이언트**: `import google.generativeai as genai` → `from google import genai`,
   `genai.configure()`+`genai.GenerativeModel()` → `genai.Client(api_key=...)`.
2. **호출부 무변경 원칙(CR1) 준수**: `self.model`을 신규 `_GenAIModelAdapter`(모듈 레벨 얇은
   래퍼 클래스)로 대체 — `generate_content(contents, generation_config=, stream=)` 동일
   시그니처를 유지해, 8개 공개 메서드 본문의 `self.model.generate_content(...)` 호출부는
   **단 한 줄도 수정하지 않았다**.
3. **`GenerationConfig` → `GenerateContentConfig`**: 저장소 내 6개 호출부 전부 치환(필드명
   동일이라 kwargs 변경 없음).
4. **`finish_reason` 정규화**: `google-genai`의 `finish_reason`은 정수가 아니라
   `FinishReason` enum이며 `int(finish_reason)`이 `TypeError`를 낸다는 것을 실제 API 호출로
   직접 확인(추측 금지 원칙 준수). 신규 `_finish_reason_name(response)` 헬퍼(`.name` 속성
   기반)로 기존 `fr_map`+`int()` 매핑 로직 3곳을 모두 대체.
5. **`_thinking_off()` 실패 처리 강화**: 조용한 `except: pass` → `logger.error`로 격상(향후
   유사 문제가 재발해도 로그로 즉시 드러나도록).
6. **`requirements-ai.txt`**: `google-genai==1.75.0` 명시적 의존성 추가. `google-generativeai`는
   Story 6.2(Tool-calling)/6.3(knowledge 모듈 등)이 아직 참조 중이므로 유지.
