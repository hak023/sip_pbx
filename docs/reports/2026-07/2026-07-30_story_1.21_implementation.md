## 설계 원칙 준수 확인

1. **판단 로직 무변경**: `_SELF_SERVICE_SYSTEM_PROMPT_TEMPLATE`/`_TOOL_USAGE_INSTRUCTION` 등
   기존 프롬프트·응답 생성 로직은 한 줄도 수정하지 않았다 — 순수 관측 추가.
2. **응답 경로 비차단(NFR6)**: `schedule_rationale_capture()`는 `asyncio.create_task()`만 호출하고
   반환된 Task를 어디서도 `await`하지 않는다(코드 리뷰로 확인). 실제 지연 실측(Task 7)은 실서버
   검증(Task 8)에서 진행 예정.
3. **캡처 실패 시 응답 흐름 무영향(FR30)**: `_capture_and_log()` 내부의 모든 단계(LLM 호출,
   DB 기록, call_data_record 로깅)가 개별 `try/except`로 감싸여 있으며, 단위 테스트로 "LLM
   호출이 예외를 던져도 `matched_type=unknown`으로 안전하게 기록됨"을 직접 검증했다.
4. **개인정보 최소 노출**: `record_decision_rationale()`이 `reasoning_summary`를 200자로
   강제 절단하고, 원본 발화 전문은 별도로 저장하지 않는다.
5. **conversation_history 오염 방지**: 분류 호출은 `llm_client.generate_response(...,
   update_history=False)`를 사용해 2026-07-29에 수정한 메타 JSON 유출 결함과 동일 클래스의
   문제가 재발하지 않도록 했다.
