## 1. 배경

Story 6.1이 `LLMClient`를 `google-genai`로 전환했으나, Gemini 네이티브 Tool-calling 헬퍼
(`booking_gemini_fc.py`)는 여전히 `google.ai.generativelanguage`(`glm`, protobuf 기반)를 사용해
`google-generativeai` 의존이 완전히 제거되지 않은 상태였다. 본 Story는 이 헬퍼를 `google.genai.types`
로 재구현한다.

## 2. 수정 내용

1. **스키마 변환**: `_json_schema_to_glm_schema()` → `_json_schema_to_genai_schema()`.
   2026-07-21에 확정된 `Any` 타입 파라미터 오분류 버그 수정 로직(타입 정보 없는 필드를 OBJECT가
   아닌 STRING으로 취급)을 그대로 유지했다.
2. **Tool/FunctionDeclaration**: `_langchain_tools_to_glm_tool()` 내부를 `genai_types.Tool`/
   `FunctionDeclaration`으로 교체(함수명은 하위 호환 위해 유지).
3. **직렬화 단순화**: 실제 SDK 확인 결과 `FunctionCall.args`/`FunctionResponse.response`가
   protobuf `Struct`가 아니라 **일반 Python dict**임을 확인 → `struct_pb2`/`ParseDict`/
   `MessageToDict` 기반 코드를 전부 제거하고 단순 dict 정제 함수(`_dict_from_jsonable`,
   `_sanitize_for_gemini_json`)로 대체(복잡도 감소).
4. **모델 생성/호출 재설계**: google-genai에는 "tools가 바인딩된 재사용 모델 객체" 개념이 없어
   (매 호출 `config.tools`로 전달하는 stateless 방식), `_GenAIToolModel`(client/model_name/tool
   컨테이너)을 신설. `build_booking_generative_model()`은 `LLMClient._client`/`.model_name`
   (Story 6.1에서 노출)을 재사용하도록 변경. **호출부(`booking_agent.py`,
   `self_service_agent.py`)는 반환값을 항상 opaque하게 `invoke_booking_model_with_gemini_fc()`
   에만 전달하므로 코드를 한 줄도 수정하지 않았다**(CR1 준수).

## 3. 검증 결과

### 3.1 실 API 2라운드 Tool-calling 검증

"지금 페르소나 설정이 어떻게 되어있는지 조회해줘. owner는 9001이야."로 실제 Gemini API 호출:

1. 1라운드: `_get_self_service_settings(domain=persona, owner=9001)` function_call 정상 생성.
2. FunctionResponse 피드백(`{"domain": "persona", "description": "친절한 상담원 페르소나", ...}`).
3. 2라운드: "네, 현재 페르소나 설정은 '친절한 상담원 페르소나'로 되어 있습니다." 최종 자연어
   응답 생성, `calls=[]`로 루프 정상 종료.
