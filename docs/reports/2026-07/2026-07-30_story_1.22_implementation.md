## 구현 요약

`frontend/app/settings/ai-assistant/docs/page.tsx`의 기존 "AI 의사결정 로직" 탭(Story 1.18 축
C-1/C-2) 하단에 **"최근 판단 이력"** 섹션을 추가했다.

- `DecisionLogItem`/`DecisionLogResponse` 타입 및 `loadDecisionLog()` 로더 추가
  (`GET /api/self-service/decision-log?owner=&limit=20` 호출).
- 판단 이력을 표(시각/유형/근거 요약)로 표시하며, 유형 코드는 `intentTypes`(기존
  `/intellidecision-policy` 응답)와 조인해 코드+한글명을 함께 노출한다(예: "B · 실행성").
- 빈 상태·에러 상태를 명시적으로 처리(데이터 없음 시 안내 문구, API 실패 시 에러 박스).
- 신규 npm 의존성 없이 기존 표 스타일(Tailwind 클래스)만 재사용.

## 검증 결과

- `npx tsc --noEmit`, `npx eslint app/settings/ai-assistant/docs/page.tsx` 모두 오류 없음.
- **실서버 브라우저 검증(2026-07-30)**: 백엔드(포트 8000)·프론트엔드(포트 3000) 모두 사용자가
  재시작한 프로세스 확인 후,
  1. `localStorage.tenant_id='9003'`로 접속 → "AI 의사결정 로직" 탭 클릭 → "최근 판단 이력"에
     Story 1.21에서 실제로 생성된 3건(B·실행성 1건, F·모호성 해소 2건)이 근거 요약과 함께
     정확히 렌더링됨을 접근성 스냅샷으로 확인.
  2. 원본 발화 전문이 화면 어디에도 노출되지 않음을 확인(근거 요약만 표시, FR30 요구사항).
  3. `localStorage.tenant_id='9099'`(판단 이력 없는 owner)로 재접속 → 동일 탭에서 "아직 기록된
     판단 이력이 없습니다" 빈 상태가 정상 표시되고 owner=9003의 데이터가 전혀 섞이지 않음을
     확인(owner 격리, IV2 실증).
  4. 기존 "AI 의사결정 로직" 표/그래프 뷰(유형 A~I 9종)는 신규 섹션 추가 후에도 동일하게
     렌더링됨을 확인(IV1, 회귀 없음).
  - **참고**: 2026-07-20에 이미 기록된 "앱 전역 WebSocket(8001) 재연결 루프발 자동화 클릭
    불안정" 이슈가 이번 세션에서는 재현되지 않아 tsc/eslint 대체 없이 실제 클릭으로 검증
    완료했다.
