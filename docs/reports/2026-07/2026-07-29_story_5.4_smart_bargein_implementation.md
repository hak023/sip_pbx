## 구현 내용

1. **`src/ai_voicebot/pipecat/smart_barge_in_turn_strategy.py`(신규)**
   - `SmartBargeInUserTurnStartStrategy(BaseUserTurnStartStrategy)` — 죽은 `SmartBargeInProcessor`
     (FrameProcessor)를 되살리지 않고, 그 판단 로직(키워드/맞장구·단어수/LLM 판단 3단계)만 추출해
     pipecat의 `user_turn_strategies` API로 재구현.
   - 봇이 조용할 때는 기존과 동일(즉시 트리거), 봇이 말하는 중(barge-in 상황)에만 3단계 필터 적용.
   - interim 프레임은 컨텍스트로만 누적, LLM 호출은 final 프레임에서만 수행(기존 설계 원칙 유지).
   - LLM 판단 실패 시 fail-safe로 interrupt 처리(사용자 발화를 놓치지 않는 안전한 쪽 선택).

2. **`src/ai_voicebot/pipecat/pipeline_builder.py`(수정)**
   - `config.yaml`의 `ai_voicebot.barge_in.smart_judge_enabled`(기본 `false`)를 읽어 `false`면
     기존 `MinWordsUserTurnStartStrategy(min_words=3)`, `true`면 신규 전략으로 **교체**(병행 아님).
   - **중요 발견**: pipecat의 `UserTurnStrategies(start=[...])`는 리스트 내 각 전략이 독립적으로
     `trigger_user_turn_started()`를 호출할 수 있어(OR 동작), 두 전략을 동시에 등록하면 오히려
     더 민감해지기만 한다 — 반드시 하나로 교체해야 함을 실제 pipecat 소스 확인으로 검증.

3. **`config/config.yaml`(수정)**: `ai_voicebot.barge_in.smart_judge_enabled: false` 추가(옵트인
   스위치, 실통화 검증 전 반드시 false 유지하도록 주석 명시).

4. **`tests_new/unit/test_ai_voicebot/test_smart_barge_in_turn_strategy.py`(신규, 10건)**
   - 봇 조용할 때 즉시 트리거, 키워드 즉시 트리거, 맞장구/단어수 미달 무시, LLM
     interruption/맞장구 판단, LLM 오류 시 fail-safe, interim 누적, BotStopped 리셋 — 전 케이스
     검증.

## 안전성 설계

- **기본 비활성**: 코드가 배포돼도 `smart_judge_enabled=false`인 한 기존 파이프라인 동작과
  100% 동일 — 이번 커밋 자체는 회귀 위험이 없다.
- **활성화는 반드시 사용자 승인 + 실통화 검증 후**: NFR5("턴테이킹 임계값 변경은 실제 통화 샘플
  기반 검증 없이 배포하지 않는다") 원칙에 따라, `true`로 전환하는 것은 별도 승인 단계로 남겨둔다.
