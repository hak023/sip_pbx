## 문제 요약

매뉴얼 RAG(ChromaDB `self_service_manual` doc_type)에 실제로 어떤 문서가 몇 개 청크로
색인되어 있고 마지막으로 언제 갱신됐는지를 확인하려면 지금까지는 `_check_emb_meta.py` 같은
1회성 진단 스크립트를 직접 실행해야 했다 — 운영자/개발자가 화면에서 확인할 방법이 없었다.

## 근본 원인 / 배경

"지식베이스 구성 현황이 투명하게 안 보인다"는 지적(2026-07-30 RAG·IntelliDecision 고도화
리서치)의 근거를 코드로 직접 확인한 결과, 매뉴얼 RAG 색인 결과를 owner/도메인 단위로 집계해
반환하는 API가 존재하지 않았다(카탈로그·IntelliDecision 정책은 이미 Story 1.18/2.4로
투명성이 확보되어 있었으나, RAG 색인 자체만 공백이었음).

## 수정 내용

1. **`src/ai_voicebot/self_service/knowledge_base_inventory.py`(신규)**: `summarize_inventory(raw_items, owner)`
   순수 함수. `knowledge_service.list_knowledge()`/`get_all_knowledge()`가 반환하는 표준 형식
   (`{"id", "text", "metadata"}` 리스트)을 그대로 받아 owner+`doc_type=self_service_manual`로
   필터링한 뒤 총 청크 수, 도메인별 분포, 소스 문서(섹션) 수, 최근 색인 시각을 집계한다.
   ChromaDB 클라이언트를 직접 열지 않고 기존 조회 결과를 재사용해 결합도를 낮췄다.
2. **`src/api/routers/settings_ai_assistant.py`**: `GET /api/settings/ai-assistant/knowledge-base/inventory?owner=`
   신설. 기존 `_knowledge_service()` 헬퍼로 `KnowledgeService`를 얻어 `get_all_knowledge()` 호출 후
   `summarize_inventory()`에 위임하는 순수 조회 엔드포인트(색인/검색 로직 무변경).
3. **`frontend/app/settings/ai-assistant/docs/page.tsx`**: `Tab` 타입에 `"kb"` 추가, 기존
   "AI 의사결정 로직" 탭과 동일한 카드/표 UI 패턴으로 "지식베이스 현황" 탭 신설(총 청크 수·
   소스 문서 수·최근 색인 시각 카드 3개 + 도메인별 분포 표). 신규 npm 의존성 없음.
