## 3. 개선 방안

### 우선순위 1: help 응답 개선 (긴급)

**문제**: 사용자가 "뭘 할 수 있어?" 물었을 때, 구체적인 답변이 없음.

**방안 A**: capability 데이터 추가
1. **1004 테넌트용 capability 등록**  
   - VectorDB 또는 tenant_config에 **"기상청 날씨 정보 제공, 태풍 정보 안내, 지진 속보"** 등 구체적인 항목 추가.
   - 그러면 `org_manager.load_capabilities()` → 0건이 아닌 실제 목록이 나오고,  
     Phase2 인사말 / help 응답에서 **"저는 ~, ~, ~을 도와드릴 수 있어요."** 로 바뀜.

**방안 B**: help_response 템플릿 개선
- `src/ai_voicebot/langgraph/nodes/template_responses.py` (또는 해당 파일)에서  
  `help` 템플릿을 **capability가 없을 때도** 최소한의 안내가 나오도록 수정:
  
  ```python
  # 현재 (추정)
  "어떤 내용이 궁금하신지 말씀해 주시면 안내해 드릴게요."
  
  # 개선안
  "현재 기본 정보 안내를 도와드릴 수 있어요. 궁금하신 내용을 말씀해 주세요."
  ```

- 또는 **capability가 0건이면** help intent를 question으로 바꿔서 LLM에게 넘겨 자유 응답하게 함.

**방안 C**: 반복 감지 + 에스컬레이션
- 같은 의도(help)에 같은 응답을 **2회 이상** 반복하면,  
  3회째는 **다른 표현**으로 응답하거나, **"지금은 안내할 정보가 제한적이에요. 구체적인 질문을 주시면 더 도와드릴게요."** 처럼 솔직하게 안내.

### 우선순위 2: LLM 지연 모니터링 강화

- 이미 앞서 작업한 **llm_request_sent / llm_response_received** 로그가 추가되어 있음.
- 다음 통화부터 5초 이상 구간이 나오면 로그를 보고 API 지연인지 재시도인지 판단 가능.
- 필요 시 **타임아웃 정책**(예: classify_intent는 5초 초과 시 fallback) 도입 검토.

### 우선순위 3: RTP 타이밍 안정화

- `rtp_interval_violation` 다수 발생 → **음질 지터** 가능성.
- 개선 방안:
  - (A) TTS 청크 수신 간격을 더 일정하게 (Google TTS API 설정 확인).
  - (B) asyncio sleep + busy-wait 조합으로 20ms 간격을 더 정밀하게 유지.
  - (C) 시스템 부하 낮추기 (불필요한 로그 줄이기, 파이프라인 최적화).
- 이건 품질 개선 차원이므로, **UX 문제(help 응답) 해결 후** 진행 권장.
