### RTP 전송은 정상

- **시퀀스 번호 연속성 정상**

### 끊김 원인 추정

사용자가 보고한 **"평일 오전 9시......부.........터...."** 끊김 증상은 **RTP 패킷 전송 문제가 아닙니다**. 

가능한 원인:
1. **수신 측(SIP 단말/폰) 지터 버퍼 이슈**: RTP는 정상 전송되었으나, 단말에서 재생 시 지터 버퍼가 고갈되거나 재생 타이밍 문제 발생
2. **네트워크 패킷 손실**: 서버에서 정상 전송했으나, 네트워크 구간에서 일부 패킷이 드롭됨
3. **단말 오디오 코덱 디코딩 지연**: G.711 디코딩은 경량이지만, 단말 CPU 부하 등으로 순간 지연 발생 가능
4. **초기 6.87초 갭의 여파**: 이전 TTS 종료 후 긴 공백이 있었고, 새 TTS 시작 시 단말 지터 버퍼가 안정화되지 않은 상태에서 재생 시작

### 뒤 문장 미재생 ("긴급 기상 상황...")

- RTP는 전체 96자 텍스트에 대응하는 **약 5-6초 분량의 패킷**을 정상 전송했습니다.
- 단말에서 **일부만 재생하고 조기 종료**했을 가능성:
  - STT 재시작으로 인한 **Barge-in 트리거**
  - 단말 자체 타임아웃 또는 버퍼 언더런

## 4. 권장 조치

### 즉시 가능

1. **Silence Keepalive 활성화** (이미 수정 완료): 긴 무음 갭을 8초 간격 무음 RTP로 완화
2. **초기 갭 모니터링**: 첫 TTS 패킷의 interval이 1초 이상이면 경고 로깅

### 추가 검토

1. **단말 로그 확인**: 실제 수신 패킷과 재생 타이밍, 손실률 확인 필요
2. **네트워크 품질 측정**: RTCP RR(Receiver Report)로 패킷 손실률, 지터 확인
3. **Jitter Buffer 설정**: 단말 또는 미디어 게이트웨이의 지터 버퍼 크기 조정
