## 1. 현상 (로그 요약)

시스템은 **단순 긍정(affirm)** 으로 처리해 엉뚱한 템플릿 응답이 나감.

---

## 2. 근본 원인

### 2.1 `네` 부분 문자열 오탐

키워드 매칭이 `if "네" in query_lower` 형태라서, **대명사 `네가`(너가)** 안의 **`네`**가 긍정 **`네`**와 동일하게 매칭됨.

- `INTENT_KEYWORDS` 순서상 **`affirm`이 `repeat`보다 앞**에 있어, “방금 **네가** … **다시** 얘기해”처럼 **다시**가 있어도 **먼저 `affirm`에 걸림** (한국어에서 `in` 부분 일치).

### 2.2 `repeat` 키워드·순서

- `다시`, `뭐라고`는 이미 `repeat`에 있으나, **`affirm` 이후에만 검사**되어 활용되지 못함.
- “기억나”, “다시 얘기”, “뭐라 그랬” 등 **직전 발화 회상** 표현이 부족함.

## 3. 대응 방향 (설계)

| 방안 | 내용 |
|------|------|
| **P0 (적용)** | `INTENT_KEYWORDS` 순서: **`repeat`·`clarification`을 `affirm`보다 앞**에 두어 “다시/뭐라고/…”가 우선. |
| **P0 (적용)** | `affirm`의 **`네`·`예`** 만: `네가`/`네는`/`네도`, `예를` 등 **형태소 단위로 오탐 제외** (`_keyword_matches_intent`). |
| **P1 (선택)** | `repeat_response_node`가 **HITL 폴백·고정 멘트만 있을 때** “직전 안내를 다시 말씀드릴게요” 등으로 바꾸거나, **사용자 질문형**이면 `question`/짧은 LLM으로 요약 답변 (별도 스토리). |
| **P2** | 장기적으로 **직전 user 발화 기준 반복** vs **assistant 기준 반복**을 구분하는 슬롯·의도(`recall_assistant`) 검토. |

## 6. 검증 시나리오 (수동)

- “방금 네가 얘기한 거 다시 얘기해 줘.” → `repeat`
- “방금 네가 뭐라고 그랬는지 기억나?” → `repeat` (또는 `뭐라고`·`기억나` 매칭)
- “네, 알겠습니다” / 문장 선두 “네 그래요” → `affirm` 유지
