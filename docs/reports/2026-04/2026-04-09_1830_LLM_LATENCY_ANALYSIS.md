## 1. 분석 개요

Call Data Record 로그에 기록된 `timing` 및 `llm` 카테고리 이벤트를 기반으로 AI 보이스봇의 각 LLM 호출 단계별 응답 시간을 분석하였다.

총 분석 로그 파일: 12개 (20260321 ~ 20260406)

---

## 2. AI 파이프라인 단계별 구조

```
[사용자 발화] → STT → [intent_classify] → [rewrite_query] → RAG 검색 → [llm_generate_response] → TTS → [응답]
                                                                   ↕
                                                         agent_graph_total (전체 소요)
```

## 7. 요약 및 시사점

### 정상 구간 기준 응답 시간 (3월 27일 이후)

| 파이프라인 단계 | 중앙값 | P90 |
|----------------|--------|-----|
| intent 분류 (LLM) | ~1.3s | ~1.9s |
| 쿼리 재작성 | ~2.1s | ~2.9s |
| 응답 생성 | ~3.9s | ~9.2s |
| **전체 처리 (question)** | **~8.9s** | **~14.5s** |

### 개선 포인트

1. **응답 생성이 가장 큰 병목** (중앙값 4초, P90 9초)
   - 프롬프트 길이 최적화 또는 더 빠른 모델 적용 검토 필요

2. **캐시 히트율 2.4%로 낮음**
   - Semantic Cache 임계값 조정 또는 캐싱 전략 보완 시 체감 응답 속도 개선 가능

3. **P95 이상 구간에서 10~20초 소요**
   - 복잡한 RAG 쿼리나 긴 프롬프트에서 발생하는 것으로 추정
   - 타임아웃 기준 및 응답 대기 UI 경험 개선 고려

4. **`question` intent가 전체의 약 48% 차지**
   - 가장 빈번하면서 가장 느린 의도 — 최우선 최적화 대상
