# 전화 주문 시스템 결제 방안 리서치

**작성일**: 2026-04-14  
**상태**: 리서치 완료  
**주제**: 전화 주문 시스템에서 활용 가능한 결제 방식 조사

---

## 개요

전화로 주문을 받는 시스템에서 결제를 처리하는 방법을 조사한다.  
핵심 문제는 "전화 통화 중 혹은 직후에 어떻게 결제를 받을 것인가"이며,  
크게 **① 직접 API 연동 (카카오페이/토스 등 대형 PG)** 과 **② SMS 링크 결제 전문 서비스** 두 갈래로 나뉜다.

---

## 전화 주문 결제의 핵심 문제

전화 주문은 본질적으로 **비대면·비동기 결제**다.  
고객이 전화로 상품을 주문하지만, 결제 행위는 고객 스스로 디바이스에서 직접 해야 한다.  
따라서 주문이 확정된 직후 **고객 휴대폰으로 결제 링크를 SMS/카카오톡으로 전송**하는 방식이 가장 현실적이다.

---

## 방법 A: 대형 간편결제 API 직접 연동

> 직접 개발 비용이 있지만, 브랜드 신뢰도가 높고 수수료가 가장 낮다.

### A-1. 카카오페이

| 항목 | 내용 |
|------|------|
| 방식 | 서버에서 결제 준비 API 호출 → `next_redirect_mobile_url` 획득 → SMS로 전송 |
| API | `POST https://open-api.kakaopay.com/online/v1/payment/ready` |
| 핵심 응답 | `next_redirect_mobile_url` (이 URL을 SMS로 고객에게 전송) |
| 결제 완료 | 고객이 링크 접속 → 카카오페이 앱으로 결제 → `approval_url`로 리다이렉트 → 서버에서 승인 API 호출 |
| 문서 | https://developers.kakaopay.com/docs/payment/online/single-payment |
| 수수료 | 카드사/간편결제 1.9%대 (PG 계약 조건에 따라 상이) |
| 단점 | 링크 유효시간 제한 있음, 카카오계정 없는 고객은 사용 불가 |

**전화 주문 연동 흐름:**
```
① 상담원이 주문 확정
② 서버 → 카카오페이 ready API 호출 (주문번호, 금액, 상품명)
③ 응답의 next_redirect_mobile_url을 고객 휴대폰으로 SMS 전송
④ 고객이 링크 클릭 → 카카오페이 앱 결제
⑤ 카카오페이 → approval_url로 리다이렉트 (pg_token 포함)
⑥ 서버에서 approve API 호출 → 결제 완료
```

---

### A-2. 토스페이 (링크결제)

| 항목 | 내용 |
|------|------|
| 방식 | 서버에서 결제 생성 API 호출 → `checkoutPage` URL 획득 → SMS로 전송 |
| API | `POST https://pay.toss.im/api/v2/payments` |
| 핵심 응답 | `checkoutPage` (이 URL을 SMS로 고객에게 전송) |
| 자동승인 | `autoExecute: true` 설정 시 고객 인증 완료 후 자동 결제 (권장) |
| 결제완료 통보 | `resultCallback` URL로 웹훅 수신 |
| 유효시간 | 최대 60분 (기본 15분), `expiredTime`으로 설정 가능 |
| 문서 | https://docs-pay.toss.im/guide/create |
| 수수료 | 별도 계약 (토스페이먼츠 가맹 필요) |
| 장점 | 토스 앱 없이도 카드 직접 입력 가능, 한국 내 결제 수단 다양 |

**전화 주문 연동 흐름:**
```
① 상담원이 주문 확정
② 서버 → POST https://pay.toss.im/api/v2/payments (orderNo, amount, productDesc)
③ 응답의 checkoutPage URL을 고객 휴대폰으로 SMS 전송
④ 고객이 링크 클릭 → 토스 결제창에서 결제 수단 선택 후 결제
⑤ resultCallback으로 결제 완료 웹훅 수신
⑥ retUrl로 고객 리다이렉트 (선택)
```

> 토스페이 링크결제는 **전화 주문에 가장 잘 맞는 방식**이다.  
> `checkoutPage` URL 하나만 SMS로 보내면 되고, autoExecute 덕분에 승인 처리도 자동이다.

### A-3. 네이버페이

| 항목 | 내용 |
|------|------|
| 방식 | JS SDK 기반 결제창 호출 (웹 페이지 필요) |
| 비대면 지원 | 직접적인 SMS 링크 결제 API 없음 |
| 현실적 활용 | 자체 결제 페이지 생성 후 URL을 SMS로 전송하는 우회 방식 |
| 단점 | 네이버 계정 필수, 전화 주문 특화 기능 없음 |
| 평가 | **전화 주문 시스템에는 비권장** |

## 방법 B: SMS 링크결제 전문 서비스

> 개발 공수가 적고 전화 주문에 최적화되어 있다. 수수료는 A보다 높은 경향.

### B-1. 페이앱 (PayApp) — **가장 추천**

| 항목 | 내용 |
|------|------|
| 특징 | 한국 최초 원격결제 솔루션. SMS/카카오톡 알림톡으로 결제 링크 자동 전송 |
| API | `POST https://api.payapp.kr/oapi/apiLoad.html` |
| 핵심 파라미터 | `userid`, `goodname`, `price`, `recvphone` (수신번호), `smsuse=y` |
| 지원 결제수단 | 신용카드, 카카오페이, 네이버페이, 토스페이, 스마일페이, 계좌이체, 가상계좌, 휴대폰, 애플페이 등 |
| 결제 완료 통보 | `feedbackurl`로 웹훅 수신 |
| 수수료 | 카드/간편결제 1.9%~3.4% (영세 기준 1.9%), 가상계좌 220원/건 |
| 등록비 | 현재 무료 이벤트 중 |
| 문서 | https://payapp.kr/dev_center/quick_start.html |

**전화 주문 연동 흐름:**
```
① 상담원이 주문 확정 (고객 전화번호 확보)
② 서버 → POST api.payapp.kr/oapi/apiLoad.html
   { userid, goodname, price, recvphone: "01012345678", smsuse: "y", feedbackurl }
③ 페이앱 서버가 고객 휴대폰으로 SMS/카카오톡 자동 전송
④ 고객이 링크 클릭 → 원하는 결제수단 선택 후 결제
⑤ feedbackurl로 결제 완료 웹훅 수신
```

> `smsuse=y` 하나로 SMS 자동 발송까지 처리된다. 전화 주문 시스템에 가장 간단하게 붙일 수 있다.

---

### B-2. 이노페이 (ARS 전화주문 특화)

| 항목 | 내용 |
|------|------|
| 특징 | ARS 자동응답 + SMS 결제링크 전송 통합 솔루션. 상담원 없이도 자동 주문/결제 가능 |
| 방식 | ARS 카드결제 API 또는 SMS 카드결제 API |
| API | `INNOPAY ARS결제 연동매뉴얼`, `INNOPAY SMS 카드결제 연동매뉴얼` 참조 |
| 수수료 | 신용카드 영세 1.5%~2.6%, 일반 3.2% |
| 가입비 | 132,000원 (이벤트 기간 면제) |
| 문서 | https://web.innopay.co.kr/guide/ |
| 장점 | 전화 주문 시스템 전체(ARS+결제)를 원스톱 구축 가능 |
| 단점 | 커스터마이징 시 개발 견적 별도 협의 필요, 고객센터 문의 기반 |

---

### B-3. 위즈페이, 텔레페이 (소규모)

| 서비스 | 특징 |
|--------|------|
| 위즈페이 | 앱/웹 관리자에서 문자결제 URL 발송, 소규모 자영업자 대상 |
| 텔레페이 | 전화 주문 후 결제 링크 전송, 영수증·거래내역 자동 저장 |
| 공통 단점 | API 문서 공개 미흡, 대규모 시스템 연동 부적합 |

## 권장 구성

### 시나리오 1: 빠른 개발, 소규모 운영
**페이앱 SMS 링크결제 API** 단독 사용  
→ API 한 줄로 SMS 발송까지 처리, 결제수단도 다양

### 시나리오 2: 자체 개발, 비용 최적화
**토스페이 링크결제 API** + 자체 SMS 발송 (알리고, 솔라피 등)  
→ 수수료 낮고, checkoutPage URL만 SMS로 보내면 됨  
→ SMS 발송은 알리고(건당 약 8원) 또는 솔라피 이용

### 시나리오 3: 완전 자동화 (ARS 포함)
**이노페이 ARS 전화주문 시스템**  
→ ARS가 주문 받고 결제 링크까지 자동 발송  
→ 상담원 인건비 절감 가능

## 참고: SMS 발송 서비스 (결제 링크 전송용)

결제 링크를 SMS로 보낼 때 별도의 문자 발송 서비스가 필요하다.

| 서비스 | 건당 단가 | 특징 |
|--------|---------|------|
| 알리고 (aligo.in) | 약 8원/건 | REST API, 카카오 알림톡 지원 |
| 솔라피 (solapi.com) | 약 9원/건 | REST API, 다양한 채널 |
| 카카오 알림톡 직연동 | 약 8~15원/건 | 카카오 공식, 템플릿 승인 필요 |

## 잔여 과제

- 어떤 결제 방식을 채택할지 결정 후 PG 가맹 신청 진행
- SMS 발송 서비스 선택 및 발신번호 등록 (010 번호 or 대표번호)
- 결제 링크 만료 시간 정책 결정 (예: 주문 후 30분 이내)
- 미결제 주문에 대한 재발송 / 주문 취소 정책 수립
