# 3rd Party 예약 시스템 연동 기획 리포트 (네이버 · 카카오)

- **작성일**: 2026-04-13
- **최종 수정**: 2026-04-13 (카카오 비교 추가)
- **상태**: 기획/설계
- **분류**: 3rd Party 연동 전략
- **관련 도메인**: 예약(Reservation) 모듈

---

## 개요

현재 SIP PBX 서비스는 자체 예약 관리 시스템을 보유하고 있으며, 네이버 스마트플레이스 및 카카오톡 예약하기를 3rd party로 선택적 연동하려 한다.
본 리포트는 두 서비스의 로그인(인증) 방식 및 예약 데이터 연동 방식에 대한 리서치 결과와 채택 전략을 정리한다.

---

## 1. 네이버 예약(스마트플레이스) API 현황 — 핵심 결론

> **네이버 스마트플레이스 예약은 일반 공개 API가 없다.**

| 구분 | 내용 |
|------|------|
| 공개 예약 API | **없음** (2026년 현재 미공개) |
| 공식 연동 경로 | 네이버 제휴 제안(파트너 계약) 후 별도 API 제공 |
| 비공식 방법 | 계정 크롤링 / 이메일·문자 파싱 / 자동화 툴 (Sendman 등) |
| 네이버 커머스 API | 스마트스토어(주문·상품) 전용, 예약과 무관 |
| 네이버 페이 API | 결제 예약(reserveId 발급)만 해당, 일정 예약과 다름 |

공식적으로 외부 시스템이 네이버 예약 데이터를 가져오거나 쓰려면 **네이버 측과 파트너 계약**이 필수다.
기존 파트너 사례: 아하소프트, 뷰카프로, 핸드SOS (스마트플레이스 파트너 솔루션 마켓에 등록된 업체).

## 2. 로그인(인증) — 네이버 OAuth 2.0

예약 연동과 별개로, 사용자 인증에 **네이버 로그인 OAuth 2.0**을 사용할 수 있으며 이는 공개 API로 즉시 적용 가능하다.

### 2.1 엔드포인트

| 역할 | URL |
|------|-----|
| 인증 요청 | `https://nid.naver.com/oauth2.0/authorize` |
| 토큰 발급/갱신/삭제 | `https://nid.naver.com/oauth2.0/token` |
| 사용자 프로필 조회 | `https://openapi.naver.com/v1/nid/me` |

### 2.2 제공 프로필 정보

- 이름, 이메일, 휴대전화번호, 생일, 성별, 연령대, 프로필 사진

### 2.3 적용 절차

1. [NAVER Developers](https://developers.naver.com)에 애플리케이션 등록
2. Client ID / Client Secret 발급
3. OAuth 2.0 Authorization Code Flow 구현
4. Access Token으로 프로필 API 호출

### 2.4 평가

- 즉시 적용 가능, 무료
- 회원가입 간소화, 기존 네이버 사용자 UX 우수
- **예약 데이터 접근 권한은 포함되지 않음** (별도 파트너 계약 필요)

## 3. 예약 데이터 연동 — 방식별 비교

### 방식 A: 네이버 공식 파트너 API (권장)

| 항목 | 내용 |
|------|------|
| 방법 | 네이버 제휴 제안 신청 → 검토 → 파트너 계약 → API 접근 |
| 신청 URL | `https://www.navercorp.com/naver/proposalRegister` (제휴 구분: 스마트플레이스(예약/주문) API 연동) |
| 소요 기간 | 영업일 5일 내 1차 검토, 이후 협의 |
| 장점 | 안정적·공식적·약관 준수, 실시간 데이터 |
| 단점 | 소규모 서비스는 승인이 어려울 수 있음, 파트너 계약 필요 |
| 비용 | 별도 협의 |

**이 방식이 장기적으로 가장 안정적이고, 실서비스 운영에 적합하다.**

---

### 방식 B: 폴링 기반 간접 연동 (단기 임시)

공식 API 없이 운영자가 수동으로 네이버 예약을 자체 시스템에 입력하는 방식.
혹은 자동화 툴(Sendman 등)을 이용해 예약 알림을 수신 후 웹훅으로 자체 DB에 저장.

| 항목 | 내용 |
|------|------|
| 방법 | 네이버 계정 + 비즈니스 ID 입력 → 3rd party 봇이 예약 수집 |
| 예시 툴 | Sendman, IFTTT (메일 파싱 방식) |
| 장점 | 파트너 계약 불필요, 빠른 적용 |
| 단점 | **2단계 인증 해제 필요(보안 위험)**, 약관 위반 소지, 네이버 정책 변경 시 즉시 중단 위험, 비공식 |
| 권장 여부 | **비권장 (프로덕션 사용 부적합)** |

---

### 방식 C: MCP(Model Context Protocol) 연동

MCP는 AI 에이전트가 외부 도구/데이터에 표준화된 방식으로 접근하게 하는 프로토콜이다.
현재 네이버 예약 전용 MCP 서버는 공식 존재하지 않으며, 커스텀 구현이 필요하다.

| 항목 | 내용 |
|------|------|
| 적합 시나리오 | AI 에이전트(챗봇, 음성봇)가 예약 조회/생성을 자연어로 처리해야 할 때 |
| 구현 방법 | 자체 MCP 서버 구축 → 방식 A의 공식 API를 MCP 툴로 래핑 |
| 장점 | AI 에이전트와의 자연스러운 연동, 표준 인터페이스 |
| 단점 | 기반 API(방식 A)가 선행 확보되어야 함, 추가 개발 비용 |
| 권장 여부 | **방식 A 확보 후 2단계로 적용** |

## 10. 로그인(인증) — 카카오 OAuth 2.0

예약 연동과 별개로, 사용자 인증에 **카카오 로그인 OAuth 2.0**을 사용할 수 있으며 공개 API로 즉시 적용 가능하다.

### 10.1 엔드포인트

| 역할 | URL |
|------|-----|
| 인증 요청 | `https://kauth.kakao.com/oauth/authorize` |
| 토큰 발급/갱신/삭제 | `https://kauth.kakao.com/oauth/token` |
| 사용자 프로필 조회 | `https://kapi.kakao.com/v2/user/me` |

### 10.2 제공 프로필 정보

- 이름, 이메일, 휴대전화번호, 성별, 생일, 연령대, 프로필 사진, **배송지** (네이버 대비 추가)

### 10.3 적용 절차

1. [Kakao Developers](https://developers.kakao.com)에서 앱 생성
2. REST API 키 / Client Secret 발급
3. 카카오 로그인 활성화, Redirect URI 등록
4. OAuth 2.0 Authorization Code Flow 구현
5. Access Token으로 프로필 API 호출

### 10.4 카카오싱크 (네이버 대비 우위)

카카오는 **카카오싱크**를 통해 로그인과 회원가입을 단일 동의 화면에서 처리할 수 있다.
서비스 약관 동의까지 한 번에 받을 수 있어, 신규 사용자 가입 전환율이 네이버 로그인보다 높다.

- 비즈 앱 + 비즈니스 채널 연결 후 신청·검수 필요 (무료)
- 카카오톡 채널 자동 친구 추가 연동 → 마케팅 채널로 활용 가능

### 10.5 평가

- 즉시 적용 가능, 무료
- 카카오싱크로 회원가입 UX가 네이버보다 매끄러움
- SDK: Web, Android, iOS, **Flutter** 지원 (네이버보다 넓음)
- **예약 데이터 접근 권한은 포함되지 않음** (파트너 계약 별도)

## 11. 카카오 예약 데이터 연동 — 방식별 비교

### 방식 A: 파트너센터 직접 입점 (네이버 대비 진입 장벽 낮음)

| 항목 | 내용 |
|------|------|
| 방법 | 파트너센터 가입 → 사업자 정보·채널·매장 등록 → 입점 심사 → 승인 후 운영 |
| 신청 URL | `https://partner-booking.kakao.com` |
| 심사 기간 | **영업일 2~5일** |
| 장점 | 누구나 직접 신청 가능 (별도 제휴 협의 불필요), 예약 기능 자체는 **무료** |
| 단점 | 파트너센터 UI에서만 예약 관리 가능, **자체 시스템과 API 동기화 불가** |
| 비용 | 예약 기능 무료, 결제 기능 연동 시 수수료만 부과 |

> 입점 자체는 쉽지만, 이 방식만으로는 자체 시스템과 예약 데이터를 양방향 동기화할 수 없다.

### 방식 B: 공식협력사 시스템 연동 (API 연동의 공식 경로)

숙소·티켓·레저 등 특정 업종은 카카오 **공식협력사**(OTA, 예약관리 솔루션 업체)를 통해 자체 시스템과 카카오 예약을 API로 연동할 수 있다.

| 항목 | 내용 |
|------|------|
| 방법 | 공식협력사 목록에서 파트너 선정 → 협력사 시스템 경유 연동 |
| 공식협력사 확인 | `https://partner-booking.kakao.com` > 공식협력사 확인 |
| 대상 업종 | 숙소, 티켓/레저, 식당, 클래스 등 특정 업종 |
| 장점 | 자체 예약 시스템 ↔ 카카오 예약 **양방향 동기화 가능** |
| 단점 | 협력사 선정·계약 필요, 협력사 의존도 발생 |
| 비용 | 협력사별 상이 |

### 방식 C: 비공식 봇/크롤링

| 항목 | 내용 |
|------|------|
| 권장 여부 | **비권장** (약관 위반, 불안정, 보안 위험 — 네이버와 동일) |

### 방식 D: MCP 서버 연동 (AI 에이전트용, 2단계)

| 항목 | 내용 |
|------|------|
| 적합 시나리오 | AI 음성봇이 "카카오 예약 확인해줘"를 자연어로 처리 |
| 구현 방법 | 방식 B(공식협력사 API) 확보 후 → 커스텀 MCP 서버로 래핑 |
| 권장 여부 | **방식 B 확보 후 2단계로 적용** |

## 12. 네이버 vs 카카오 종합 비교

### 로그인(인증)

| 항목 | 네이버 | 카카오 |
|------|--------|--------|
| 공개 API | ✅ 즉시 가능 | ✅ 즉시 가능 |
| 인증 방식 | OAuth 2.0 | OAuth 2.0 + OpenID Connect |
| 제공 프로필 | 이름·이메일·전화·성별·생일 | 이름·이메일·전화·성별·생일·**배송지** |
| SDK 지원 플랫폼 | Web, Android, iOS | Web, Android, iOS, **Flutter** |
| 회원가입 간소화 | 네이버 로그인 | **카카오싱크** (더 강력) |
| 마케팅 채널 연계 | 제한적 | **카카오톡 채널 자동 연결** |
| **권장 우선순위** | 2순위 | **1순위** |

### 예약 데이터 연동

| 항목 | 네이버 스마트플레이스 | 카카오톡 예약하기 |
|------|----------------------|-----------------|
| 공개 예약 API | ❌ 없음 | ❌ 없음 |
| 직접 입점 신청 | 제휴 제안(협의 필요) | **파트너센터 직접 신청 가능** |
| 심사 기간 | 영업일 5일 이상 | **영업일 2~5일** |
| 소규모 서비스 진입 | 장벽 높음 | **개방적** (사업자 등록만 있으면 가능) |
| 자체 시스템 연동 | 파트너 계약 후 API | 공식협력사 경유 |
| API 연동 비용 | 협의 | 예약 기능 **무료** (결제 수수료만) |
| 기존 파트너 사례 | 아하소프트, 뷰카프로, 핸드SOS | 공식협력사 다수 (숙소·티켓 등) |
| **권장 우선순위** | 2순위 | **1순위** |

> **결론**: 예약 API 공개 여부는 둘 다 동일하게 없으나,
> 카카오가 진입 장벽이 낮고 입점 절차가 명확하므로 **카카오를 먼저 진행하는 것이 유리하다.**

## 13. 통합 로드맵 (네이버 + 카카오)

### Phase 0 — 즉시 가능 (계약 불필요)

- [ ] **카카오 로그인(OAuth 2.0) 적용** → 소셜 로그인 (1순위)
- [ ] **네이버 로그인(OAuth 2.0) 적용** → 소셜 로그인 (2순위)
- [ ] 자체 예약 시스템에 `kakao_id`, `naver_id` 필드 추가

### Phase 1 — 카카오 예약 연동 (우선)

- [ ] 카카오톡 예약하기 파트너센터 직접 입점 신청
- [ ] 업종에 따라 공식협력사 선정 및 시스템 연동 계약
- [ ] 공식협력사 API 스펙 기반 예약 통합 레이어 개발
  - 카카오 예약 목록 조회 / 동기화
  - 슬롯 가용 여부 조회
  - 자체 시스템 예약 생성 시 카카오 동기화 (양방향)

### Phase 2 — 네이버 예약 연동

- [ ] 네이버 스마트플레이스 제휴 제안 신청
  - URL: `https://www.navercorp.com/naver/proposalRegister`
  - 제휴 구분: 스마트플레이스(예약/주문) API 연동
- [ ] 파트너 API 스펙 수신 후 예약 통합 레이어 확장

### Phase 3 — AI 에이전트 연동 (MCP)

- [ ] 예약 통합 레이어를 MCP 서버로 노출
- [ ] AI 음성봇에서 자연어로 예약 조회/생성 처리

```sql
ALTER TABLE reservations
  ADD COLUMN source VARCHAR(20) NOT NULL DEFAULT 'self'
    CHECK (source IN ('self', 'naver', 'kakao')),
  ADD COLUMN external_id VARCHAR(100),         -- 외부 시스템 예약 ID
  ADD COLUMN external_synced_at TIMESTAMP,     -- 마지막 동기화 시각
  ADD COLUMN naver_business_id VARCHAR(50),    -- 네이버 스마트플레이스 비즈니스 ID
  ADD COLUMN kakao_partner_id VARCHAR(50);     -- 카카오 예약하기 파트너 ID

ALTER TABLE users
  ADD COLUMN naver_id VARCHAR(100),
  ADD COLUMN kakao_id VARCHAR(100);
```

## 15. 주요 결정 사항 (네이버 + 카카오 통합)

| 결정 | 이유 |

| MCP는 공식 API 확보 후 적용 | 기반 API 없이 MCP만 구축하는 것은 의미 없음 |
