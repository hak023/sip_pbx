## 1. 배경

Epic 3(FR34) 계획(§7)에서 사용자가 "응답 시뮬레이터는 재검토가 아니라 삭제 확정, 대신 평소
숨겨진 `GlobalSmsDock`을 상시 노출해 관리자가 자기 자신에게 실제 메시지를 보내게 하라"고
확정 요청했다. 착수 순서 권고(§7)에 따라 Story 1.39를 가장 먼저 구현했다(1.38의 데이터 출처가
되므로 선행 필요).

## 2. 구현 내용

### AC1 — 시뮬레이터 프론트엔드 제거

`frontend/app/settings/ai-assistant/docs/page.tsx`에서 다음을 전부 제거:

- 타입: `SimulateMatchedDocument`/`SimulateHopEdge`/`SimulateResponse`/`SimulateTurn`
- 상태: `simulateQuery`/`simulating`/`simulateTurns`/`simulateError`
- 핸들러: `handleSimulate`/`handleSimulateFromPolicy`
- 탭: `Tab` 유니온의 `"simulate"` → `"chat"`으로 교체, 탭 버튼 라벨 "응답 시뮬레이터" → "실제 채팅"
- 시뮬레이터 결과 렌더링 JSX(멀티턴 카드 전체)

백엔드 `src/api/routers/knowledge_base_simulate.py`는 Story 1.38 Dev Notes에 이미 "이 화면에서
호출하지 않는다"고 명시되어 있어 다른 Story의 재사용처가 없음을 확인 — 무리하게 삭제하지 않고
그대로 남겨둠(기존 단위테스트 보존, 회귀 위험 없음).

### AC2/AC3 — 실제 채팅 패널

- `useActiveSmsDockStore`(기존 store, 신규 API 없음)의 `openThreadFromCall({owner, peer: owner})`를
  재사용 — `owner === peer`(자기 자신)로 스레드를 열어 `phase`를 `"idle"→"open"`으로 전환.
- 신규 "실제 채팅" 탭 진입 시(`useEffect(tab === "chat")`) 자동으로 위 호출을 실행해 평소 수신
  시에만 열리는 `GlobalSmsDock`(이미 `layout.tsx`→`GlobalLeftDockStack`에 전역 마운트되어 있음)을
  강제로 활성화. 컴포넌트 자체는 한 줄도 수정하지 않음(표시 조건 `phase`/`dockExpanded`/
  `userMinimized` 로직 무변경 — Dev Notes의 회귀 방지 지침 준수).
- IntelliDecision 정책 탭의 질문 예시 버튼도 시뮬레이터 대신 이 탭으로 이동 + 입력창에 예시 문구를
  채워주도록 변경(`handleChatFromPolicy`) — 자동 전송은 하지 않고 사용자가 직접 눌러야 실제 SIP
  MESSAGE가 나가도록 설계(오발신 방지).

### AC3(전송 재사용) / AC4(로그 반영)

`GlobalSmsDock`이 이미 `/api/chat/send`(=`frontend/app/chat/page.tsx`와 동일 엔드포인트)로 전송하므로
신규 전송 코드 불필요. 전송된 메시지는 일반 SIP MESSAGE 흐름 그대로 `self_service_decision_log`/
`call_data_record`에 기록되어 Story 1.38에서 그대로 재사용 가능.

- 프로세스 시작 시각(16:18:26)이 코드 수정 시각보다 늦음을 확인해 최신 코드 반영 확인.
- 브라우저(Playwright, `localStorage.tenant_id=9001`)로 `/settings/ai-assistant/docs` 접속 →
  "실제 채팅" 탭 클릭(이 저장소 상시 WebSocket 재연결 불안정으로 `page.evaluate` 네이티브

- 메시지 "이번 달 AI 몇 번 응대했어?" 전송 → `logs/app.log`에 `chat_message_saved`/
  `chat_send_done(code=sender_not_registered)` 기록 — **동일 오류가 `/chat?owner=9001&
  thread=9001`(기존 `chat/page.tsx`)에서도 동일 메시지로 동일하게 재현됨을 확인**해, "실제 채팅"
  탭이 `chat/page.tsx`와 정확히 동일한 `/api/chat/send` 경로를 공유함을 실증(AC3).
- **환경 제약(Story 1.39 결함 아님)**: 이 개발/QA 환경에는 owner 9001을 REGISTER한 실제 SIP

  AC1(시뮬레이터 제거)·AC2(상시 노출)·AC3(전송 로직 재사용)는 모두 실증 완료. AC4(decision_log
  반영)는 실제 SIP UA가 등록된 다음 세션에서 종단 검증 권장.
