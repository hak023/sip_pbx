# FR33 계획 리포트 — 업로드 통합·지식베이스 자동 구성·응답 시뮬레이터 고도화·유형 C 하이브리드 RAG

**작성일**: 2026-08-04
**작성자**: Copilot (BMAD PM/Architect 역할)
**상태**: 계획 수립 완료(코드 변경 없음) — PRD/architecture/Story 문서 증분 반영 완료

## 1. 요청 요약

사용자가 FR32(Story 1.26~1.29, 도메인 비종속 지식베이스 플랫폼) 완료 후에도 남아있는 4가지
문제를 지적하며 BMAD 절차로 계획을 수립해달라고 요청했다.

1. **업로드 이원화**: "설정 관리" 탭(카탈로그/화면안내 구성 export/import)과 "지식 업로드" 탭
   (테넌트 지식 문서)이 분리되어 있어 하나의 지식 업로드로 통합되어야 한다.
2. **플랫폼 전환**: 현재 셀프서비스 AI는 "이 시스템(SIP PBX)"에 종속적으로 개발되어 있으나,
   궁극적으로는 업로드된 상세 데이터(API/Tool 정보·매뉴얼·화면 안내)만으로 **임의의 다른 시스템**
   이라도 지식베이스(이용 매뉴얼 Q&A/AI 변경 가능 설정/화면 안내)가 자동 구성되어야 한다. 단,
   실제 Tool 실행 매칭은 추후 과제로 명시적으로 후순위임을 사용자가 밝혔다.
3. **공통 고정 콘텐츠**: 테넌트/도메인 공통으로 쓸 수 있는 내용(예: IntelliDecision 유형 정의)은
   고정으로 유지해도 된다.
4. **응답 시뮬레이터×IntelliDecision UX 고도화**: 유형 A~I 탭 + 유형별 질문 예시 리스트(RAG/Tool
   필요 여부 표시) + 질문 선택 시 hop 연결·RAG 매칭·최종 AI 응답을 투명하게 시각화 + AI 응답
   확인 후에도 대화가 이어지는 멀티턴 시뮬레이션.
5. **유형 C 하이브리드 RAG**: 여러 도메인에 걸친 검색이 필요한 유형 C를 위한 방안 수립.

## 2. 현황 진단(코드/문서 직접 확인)

- `frontend/app/settings/ai-assistant/docs/page.tsx`를 직접 읽어 확인: "지식 업로드"(Story 1.26,
  `knowledge_documents` 테이블+`/api/knowledge-base/documents`)와 "설정 관리"(Epic 2 Story 2.4/2.5,
  `self_service_catalog_config`+`/catalog-config/*`)는 **서로 다른 저장소·목적**을 가진 별개
  기능이다 — 둘을 데이터 모델까지 강제로 합치는 것은 과설계이며 목표와도 맞지 않는다고 판단.
  실제 사용자 문제는 "화면 진입점이 나뉘어 헷갈린다"는 UX 문제로 재정의.
- Story 1.27(응답 시뮬레이터)/1.18(IntelliDecision 정책)/1.24(RAG 매칭 정책 메타데이터)/1.28
  (n-hop 그래프)이 모두 Done 상태로 이미 구현되어 있음을 확인 — 신규 요구사항 4번은 이 4개
  기존 기능을 프론트엔드 UX 레벨에서 통합·재구성하는 문제로 정의 가능함을 확인.
- PRD FR32-B Dev Notes에 이미 "get_fn/update_fn 실제 실행부 매칭은 Non-Goal"이라는 원칙이
  없었으나, 요청 2번의 "매칭은 추후 고려 사항" 발언과 Epic 2의 화이트리스트 레지스트리(임의
  코드 실행 방지) 설계 원칙이 정확히 부합함을 확인 — 신규 FR에 이 경계를 명시적으로 반영.

### FR33 하위 요구사항 매핑

- **FR33-A(업로드 진입점 통합)**: 데이터 모델은 유지, "지식 업로드" 탭 안에 소스 유형 전환
  UI(① 테넌트 지식 문서 ② 시스템 공통 설정/구성)를 두어 "설정 관리" 탭을 흡수 → Story 1.30.
- **FR33-B(업로드 데이터 기반 지식베이스 자동 구성)**: 업로드된 매뉴얼/OpenAPI 스펙에서 (1) 매뉴얼
  Q&A (2) 설정 항목 목록 (3) 화면 안내 노드를 도메인 비종속적으로 자동 추출·구성 → Story 1.31.
  Tool 실제 실행 매칭은 명시적 Non-Goal.
- **FR33-C(테넌트/도메인 공통 고정 콘텐츠)**: `intellidecision_policy.py`의 유형 정의 등은 시스템
  표준으로 분류, 업로드 통합 탭에서 "시스템 표준" 배지로 구분 표시 → Story 1.30에 통합 구현.
- **FR33-D(응답 시뮬레이터×IntelliDecision UX 고도화)**: 유형 A~I 탭 + 지식베이스 기반 동적
  질문 예시 리스트 + RAG/Tool 필요 여부 배지(Story 1.24 메타데이터 재사용) + 질문 선택 시 유형
  판정·hop 경로(Story 1.28)·RAG 매칭 근거·최종 응답 시각화 + 세션 내 멀티턴 계속 질의 → Story 1.32.
- **FR33-E(유형 C 하이브리드 RAG)**: `rag_strategy_hint="hybrid_multi_domain"` 신설, 다중 도메인
  `asyncio.gather` 병렬 검색+카테고리별 집계, 시뮬레이터에서 병렬 hop 시각화로 구분 → Story 1.33.

## 4. 실행 순서 권고

1. **Story 1.30**(업로드 진입점 통합) — 순수 UX 재편, 회귀 위험 최소, 사용자 체감 즉시.
2. **Story 1.31**(지식베이스 자동 구성) — 플랫폼 전환의 핵심, 임의 시스템 지원 요구사항의 본체.
3. **Story 1.32**(시뮬레이터 UX 고도화) — 1.31의 동적 질문 목록에 의존(단, 정적 폴백으로 선착수
   가능하도록 설계됨).
4. **Story 1.33**(유형 C 하이브리드 RAG) — 독립적으로 착수 가능, 우선순위 최하위.

## 5. Non-Goal(명시적 범위 제외)

- 업로드 데이터 기반 "설정 항목"의 실제 쓰기 Tool(get_fn/update_fn) 자동 생성·실행 매칭(FR33-B
  Non-Goal, 사용자 지시로 후순위 확정).
- "지식 업로드"/"설정 관리" 데이터 모델·API의 물리적 통합(NFR8, UX 계층 통합만 수행).
- Full GraphRAG 자동 커뮤니티 클러스터링(유형 C 하이브리드도 경량 병렬 검색 수준으로 한정).
