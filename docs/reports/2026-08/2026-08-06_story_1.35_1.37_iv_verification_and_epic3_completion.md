## 1. 검증 내용

가상 OpenAPI 문서("Demo Order API", GET/POST `/orders`, domain_tags=`demo-orders`)를 owner=9001로
업로드해 Story 1.34~1.37 전체 파이프라인을 종단 검증했다.

1. **업로드+색인**: `POST /api/knowledge-base/documents` → 2청크 색인 성공.
2. **Story 1.34 승인 API**: `PATCH /api/knowledge-base/documents/{id}/approve-methods`로
   POST/DELETE 승인 → 응답 `approved_methods: [GET, DELETE, POST]` 확인.
3. **Story 1.37 hop-path API**: `GET /knowledge-base/documents/{id}/hop-path` →
   `catalog_domain:demo-orders`를 시작점으로 `writable`(유형 A/C/F/H/I) + `relates_to`(document)
   엣지 6건 정상 반환.
4. **Story 1.36 IA**: 브라우저로 `/ai-agent` 접속 → 3섹션 카드 정상 렌더링, 헤더 "AI 에이전트"
   메뉴 노출 확인.
5. **Story 1.37 프론트엔드**: "지식베이스 현황" 탭에 "업로드 문서별 상세 카드" 섹션이 실제
   업로드 문서로 렌더링되고, "hop 경로" 토글 클릭 시 API와 동일한 hop 칩 6개가 표시됨을 확인.

## 2. 발견·수정한 버그

`GET /api/knowledge-base/documents` 목록 응답에 `approved_methods` 필드가 누락되어, Story 1.37
카드의 "쓰기 승인" 배지가 표시되지 않는 문제를 발견했다. DB 계층(`knowledge_documents_db.py::
_row_to_dict`)은 이미 올바르게 필드를 포함하고 있었으나, API 라우터 계층
(`KnowledgeDocumentItem`/`_to_document_item()`)에서 누락되어 있었다. `KnowledgeDocumentItem`에
`approved_methods: List[str] = []` 필드를 추가하고 매핑 함수를 수정해 해결했다. 기존 DB 단위테스트
32건 재실행 통과. 이 수정은 다음 서버 재시작 시 반영된다(라이브 재검증은 다음 세션 권장).
