# Story 1.31 구현 리포트 — 업로드 데이터 기반 지식베이스 자동 구성

**Story**: [1.31.upload-driven-knowledge-base-auto-assembly.story.md](../../stories/1.31.upload-driven-knowledge-base-auto-assembly.story.md)
**상태**: Review(구현+단위테스트+정적검증 완료, 실서버 IV만 잔여)

## 요구사항 요약(FR33-B)

업로드된 상세 데이터(API/Tool 스펙, 매뉴얼 텍스트)만으로 (1) 이용 매뉴얼 Q&A (2) AI 변경 가능
설정 목록 (3) 화면 안내 3종 지식베이스가 도메인 비종속적으로 자동 구성되어야 한다. 실제
get_fn/update_fn 실행 매칭은 명시적 Non-Goal.

## 현황 진단(코드 직접 확인)

- Story 1.25/1.26이 이미 `OpenApiSpecAdapter`/`MarkdownManualAdapter`로 업로드 텍스트에서
  Q&A 페어를 자동 추출해 ChromaDB에 색인하고 있음을 확인 — AC1-a(매뉴얼 Q&A 자동 추출)는
  이번 Story 이전에 이미 충족되어 있었다.
- Story 1.28이 이미 `knowledge_graph.py`에 `document` 노드 타입 + `relates_to` 엣지
  (catalog_domain→document, `domain_tags` 문자열 매칭만으로 동작하는 도메인 비종속 구조)를
  구현해뒀음을 확인 — AC1-c(화면 안내 노드 등록)도 이미 충족.
- 남은 실질적 공백은 AC1-b(설정 항목 분류)와 AC3(지식베이스 현황 탭에서 조회 가능)였다.
- `knowledge_service.py::add_knowledge()`를 직접 읽어 `answer`/`section_title`이 메타데이터로
  저장되지 않음을 확인(그 값들은 greeting/help 캐싱 신호에만 쓰임) — 대신 `text` 필드에
  `"Q: ...\nA: ..."` 원문이 그대로 저장되므로, 이를 파싱해 질문/답변을 복원하는 방식으로 설계.

## 구현 내용

- 신규 `src/ai_voicebot/self_service/knowledge_base_assembler.py`:
  - `classify_setting_item(question, answer)`: `OpenApiSpecAdapter`가 생성하는 질문 포맷
    (`"METHOD path 엔드포인트는 무엇을 하나요?"`)을 정규식으로 인식해 POST/PUT/PATCH/DELETE는
    writable, GET 등은 read-only로 분류. 매칭 실패 시 일반 매뉴얼 Q&A로 간주(`None` 반환).
  - `summarize_auto_assembled_knowledge_base(raw_items, owner, document_records=)`: Story 1.23
    `summarize_inventory()`와 동일한 패턴(이미 조회된 raw 항목 리스트를 받는 순수 함수, ChromaDB를
    직접 열지 않음)으로 매뉴얼 Q&A 수/설정 항목 후보 수/쓰기 가능 후보 수/화면 노드 수를 집계.
- `src/api/routers/settings_ai_assistant.py`: 기존 `GET /knowledge-base/inventory` 응답에
  `auto_assembled`(선택적 필드, 기존 필드 무수정) 추가 — 같은 엔드포인트가 이미 가져온 `raw_all`을
  재사용해 추가 ChromaDB 라운드트립 없이 집계.
- `frontend/app/settings/ai-assistant/docs/page.tsx`: "지식베이스 현황" 탭에 자동 구성 통계
  카드 4개(매뉴얼 Q&A/설정 항목 후보/쓰기 가능 후보/화면 노드 수) + 설정 항목 표 추가.

## 명시적 범위 축소(Dev Notes에 기록)

- `api_endpoint` 노드 타입/`documents` 엣지(Story 1.28에서 이미 예약만 되고 리졸버는 빈 상태)는
  이번 Story에서 추가 구현하지 않았다 — AC1-c는 기존 `document` 노드로 이미 충족된다고 판단했고,
  엔드포인트 단위 세밀 노드화는 실수요 확인 후 별도 Story로 이연.
- 실제 설정 변경 Tool 실행 매칭은 Non-Goal(AC4)로 손대지 않음.

## 검증 결과

- 신규 단위테스트 10건(`test_knowledge_base_assembler.py`) 전체 통과 — 특히
  `TestDomainAgnosticEndToEnd`는 SIP PBX와 무관한 가상의 이커머스 주문 API 스펙으로
  Q&A/설정 항목 자동 분류가 정확히 동작함을 실증해 AC2(도메인 비종속)를 검증했다.
- `tests_new/unit/test_ai_voicebot -k "self_service or knowledge"` 54건 전체 통과(회귀 없음).
- `npx tsc --noEmit`/`npx eslint`: 0 에러.
- 라우터 임포트로 `/knowledge-base/inventory` 라우트가 여전히 정상 등록됨을 서버 기동 없이 확인.
- 실행 중이던 기존 서버 프로세스(비-reload)로 API를 직접 호출해 `auto_assembled` 필드가 아직
  반영되지 않았음을 확인(코드 변경 전 프로세스이므로 예상된 결과) — 재시작이 필요함을 재확인.
