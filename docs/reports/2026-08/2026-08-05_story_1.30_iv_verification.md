## 검증 절차 및 결과

1. **최신 코드 반영 확인**: `Get-Process`로 프론트엔드(포트 3000, node)/백엔드(포트 8000·8001,
   python) 프로세스 시작 시각(09:06대)이 `page.tsx` 최종 수정 시각(09:02대)보다 늦음을 확인 —
   재시작 후 프로세스가 Story 1.30 코드를 반영 중임을 확인.
2. **탭 구조 통합 확인**: 브라우저로 `/settings/ai-assistant/docs` 접속 → 최상위 탭이 7개
   (이용 매뉴얼 Q&A/AI 변경 가능 설정/화면 안내/AI 의사결정 로직/지식베이스 현황/지식 업로드/
   응답 시뮬레이터)로 "설정 관리" 탭이 사라진 것을 확인.
3. **세그먼트 토글 확인**: "지식 업로드" 탭 클릭 → "① 테넌트 지식 문서"/"② 시스템 공통 설정/구성"
   세그먼트 버튼으로 정상 전환됨을 스냅샷으로 확인.
4. **FR33-C(시스템 표준 배지) 확인**: "② 시스템 공통 설정/구성" 섹션에 "시스템 표준(읽기 전용)
   vs 테넌트별 편집 가능" 안내 배너가 노출됨을 확인.
5. **Epic 2 기능 회귀 확인**: 같은 섹션의 "설정 다운로드" 버튼 클릭 → 카탈로그 v2/화면 안내 v2
   (둘 다 "DB에 저장된 활성 설정")로 정상 export됨을 확인 — 탭 병합 후에도 기존 Epic 2 export
   기능이 100% 동일하게 동작.
6. **Story 1.26 업로드 기능 회귀 확인**:
   - 브라우저 자동 클릭만으로는 `localStorage.tenant_id`가 비어 있어 owner 미설정 가드로 상호작용
     결과가 보이지 않음을 발견(2026-07-28 기존 메모와 일치하는 이 저장소의 알려진 특성) — 이는
     Story 1.30의 결함이 아니라 owner 주입 방식(로컬스토리지 기반)의 기존 제약.
   - `localStorage.tenant_id = "9001"`로 직접 설정 후 재확인, 동시에 API를 직접 호출(멀티파트
     `POST /api/knowledge-base/documents`)해 업로드 사이클 검증:
     - 업로드: `document_id=50cf04f9...`, 52청크 색인 성공.
     - 목록 조회: 브라우저 "① 테넌트 지식 문서" 테이블에 해당 문서가 정확히 표시됨(owner=9001).
     - 삭제: UI "삭제" 버튼 클릭 → `GET /documents?owner=9001` 결과 `total:0`으로 정리 확인.
   - `logs/app.log` cross-check: `knowledge_document_registered`(09:12:31)/
     `knowledge_document_deleted`(09:13:21) 이벤트가 동일 `document_id`로 기록되어 API 응답과
     100% 일치함을 확인(coding-standards.md §6 방법론).
