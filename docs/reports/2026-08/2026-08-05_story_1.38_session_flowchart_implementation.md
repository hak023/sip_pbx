## 1. 배경

Epic 3(FR34) 계획(§8~9)에서 사용자가 "실제 질의/응답 한 건씩 보여주면 의미 없다 — 여러 턴에
걸쳐 유형이 옮겨가는 과정 자체가 IntelliDecision 핵심"이라 지적했고, 이어서 "채팅은 call_id가
트랜잭션마다 나뉜다"는 지적으로 세션 그룹핑 키를 채널별로 분리하도록 재설계된 Story다.

## 2. Task 1 — 스키마 변경 및 발견된 위험한 버그

- `self_service_decision_log`에 `caller_number` 컬럼 추가(`booking/database.py` DDL+마이그레이션),
  `decision_rationale.py`/`self_service_agent.py` 호출부에 배선(state의 `_caller_number` 재사용).
- **⚠️ 중요 발견·즉시 수정**: 신규 컬럼을 참조하는 `CREATE INDEX`를 `_DDL` 블록에도 함께 넣었다가,
  실제 dev DB(`booking.db`)에 `init_db()`를 직접 호출해보니 `OperationalError: no such column`으로
  **executescript 전체가 중단**되는 것을 발견했다 — 기존 테이블이 있으면 `CREATE TABLE IF NOT
  EXISTS`가 no-op이라 컬럼이 아직 없는데, 같은 스크립트 안의 `CREATE INDEX`가 그 컬럼을 참조해
  실패한 것. 해당 인덱스 생성을 `_DDL`에서 제거하고 `_MIGRATIONS`(ALTER TABLE 직후)에만 남기도록
  즉시 수정 후 재검증 완료(신규 컬럼이 정상 추가됨을 `PRAGMA table_info`로 확인). 단위테스트는
  임시 DB를 새로 만들어서 이 함정을 전혀 잡지 못했다 — 실제 dev DB로 `init_db()`를 직접 호출해본
  것이 유일한 발견 경로였다(교훈을 repo 메모리에 기록).

## 3. Task 2/3/4 — 채널별 세션 그룹핑 백엔드

  `GET /api/self-service/decision-log/sessions/{session_key}`(턴 상세, AC10 2단계).
- **턴별 5단계 서브플로우 데이터**: 기존에 이미 있던 `read_call_data_record_for_call()`(Story
  1.27부터 존재)을 재사용해 `self_service_rag_search`/`self_service_agent_hybrid_rag_merged`/
  `self_service_screen_graph_hit`/`self_service_tool_start`·`_done`/`self_service_agent_response`
  이벤트에서 RAG·hop·Tool·응답 메타를 실제 로그 값 그대로 추출(AC6 — 없으면 None, 프론트가
  "정보 없음"으로 표시, 추정으로 채우지 않음). AC9(유형 C 병렬 분기)는 Story 1.33이 이미 남긴
  `self_service_agent_hybrid_rag_merged` 로그를 그대로 노출하는 수준으로 충족 — 별도의 시각적
  병렬 분기 다이어그램(가지 치는 SVG 등)까지는 이번 범위에서 구현하지 않음(아래 범위 축소 참고).
