## 요구사항 요약(FR33-D)

유형 A~I 탭 + 질문 예시 리스트(RAG/Tool 배지 포함) + 질문 선택 시 판정 유형·hop 경로·RAG 매칭
근거·최종 응답을 투명하게 시각화 + AI 응답 확인 후에도 같은 화면에서 대화를 이어갈 수 있는
멀티턴 시뮬레이터.

## 구현 내용

- **AC1(유형 A~I 탭)**: `frontend/.../docs/page.tsx`의 "AI 의사결정 로직" 탭 내부에
  `activeIntentCode` 상태로 9개 유형 코드 하위 탭을 추가, 선택된 유형 카드만 렌더링.
- **AC2/AC3(질문 예시+RAG/Tool 배지)**: 기존 `GET /intellidecision-policy` 응답이 이미
  `trigger_examples`/`rag_enabled`/`rag_source_scope`/`rag_strategy_hint`/`requires_tool`을
  전부 포함하고 있음을 확인해, **신규 API 없이** 각 예시 문구 옆에 배지를 렌더링. Story 1.31이
  아직 유형별 Q&A 매핑까지는 제공하지 않아 정적 `trigger_examples`를 그대로 사용(하위 호환
  폴백 경로, Dev Notes에 명시된 대로 순서 의존성 없이 착수).
- **AC4(hop 경로 시각화)**: `src/api/routers/knowledge_base_simulate.py`에 `_collect_hop_path()`
  신설 — 매칭 문서의 `related_domain`에서 시작해 `knowledge_graph.traverse_graph()`(Story 1.28)를
  실제 호출해 hop 경로를 수집·직렬화(`HopEdge`)하고 `SimulateResponse.hop_path`로 노출. 개별
  도메인 조회 실패는 다른 도메인 수집을 막지 않는 best-effort 처리.
- **AC5(멀티턴)**: 응답 시뮬레이터 탭의 상태를 단일 `simulateResult`에서 `simulateTurns`(배열)로
  전환 — 매 호출마다 새 턴을 누적 표시하고, 이전 결과가 남은 채로 새 질문을 계속 입력할 수
  있다. 격리 세션 원칙(Story 1.27 AC3)은 유지된다(백엔드는 매 호출마다 여전히 새 격리 에이전트).
- **AC6(기존 API 무변경)**: `GET /intellidecision-policy`는 무수정, 시뮬레이터 엔드포인트는
  `hop_path` 필드만 추가(기존 필드 전부 유지) — 하위 호환.

- 신규 단위테스트 4건(`TestCollectHopPath`) — 실제 "booking" 도메인으로 hop 경로가 실제로

- `tests_new/unit/test_ai_voicebot -k "self_service or knowledge"` 68건 전체 통과(회귀 없음).
- `npx tsc --noEmit`/`npx eslint`: 0 에러.
- 라우터 임포트로 문법/의존성 오류 없음을 서버 기동 없이 확인.
