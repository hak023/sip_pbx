# Story 1.30 구현 리포트 — 지식 업로드 진입점 통합 + 시스템 표준 고정 콘텐츠 구분

**상태**: Review(구현+정적 검증 완료, 실서버 IV만 잔여)

## 문제 요약

`settings/ai-assistant/docs` 페이지의 최상위 탭이 "지식 업로드"(Story 1.26, 테넌트별 매뉴얼/PDF/
OpenAPI 문서)와 "설정 관리"(Epic 2 Story 2.4/2.5, `catalog_config`/`screen_graph` JSON export/
import/버전 이력)로 이원화되어 있어 사용자가 업로드 기능이 어디 있는지 헷갈리는 문제가 있었다.

## 근본 원인 및 방향 결정

두 탭은 저장소(`knowledge_documents` vs `self_service_catalog_config`)와 목적이 근본적으로 다르므로
데이터 모델을 물리적으로 통합하는 것은 과설계로 판단(PRD NFR8). 대신 **UX 진입점만 통합**하는
방향으로 확정 — 하나의 "지식 업로드" 탭 안에 소스 유형 세그먼트(① 테넌트 지식 문서 / ② 시스템
공통 설정·구성)를 두어 전환해 볼 수 있게 했다.

## 수정 내용

- `frontend/app/settings/ai-assistant/docs/page.tsx`:
  - 최상위 `Tab` 타입에서 `"manage"` 제거(8개 탭 → 7개 탭).
  - 신규 `UploadSection`(`"tenant" | "system"`) 상태 + 세그먼트 토글 UI 추가.
  - 기존 "지식 업로드" 탭 콘텐츠(업로드 폼, 문서 목록 테이블)는 `uploadSection === "tenant"`로
    감싸고, 기존 "설정 관리" 탭 콘텐츠(다운로드/업로드/버전 이력)는 `uploadSection === "system"`으로
    감싸 그대로 이전 — 상태 변수·API 호출·이벤트 핸들러는 한 줄도 변경하지 않았다.
  - FR33-C 반영: "시스템 표준(읽기 전용) vs 테넌트별 편집 가능" 안내 배너 추가 — IntelliDecision
    정책(유형 A~I)은 테넌트 무관 고정·읽기 전용이며, 카탈로그/화면 안내는 테넌트별 편집 가능함을
    명시.
  - `useEffect`의 데이터 로딩 트리거를 `tab === "upload" && owner`(문서 목록)/`tab === "manage"`
    (버전 이력)에서 각각 `uploadSection === "tenant"`/`uploadSection === "system"` 조건으로 갱신.

## 검증 결과

- `npx tsc --noEmit`: 0 에러.
- `npx eslint app/settings/ai-assistant/docs/page.tsx`: 초기 2건(`react/no-unescaped-entities`,
  큰따옴표 미이스케이프) 발견 → `&quot;`로 수정 후 0 에러/0 경고.
- 백엔드 API(`/api/knowledge-base/documents`, `/catalog-config/*`)는 무수정 — AC4 충족.
- 기존 두 탭의 상태 변수·이벤트 핸들러·API 호출 코드를 grep/read로 전량 재확인, 로직 변경 없이
  컨테이너만 재배치됐음을 확인 — AC5 충족(코드 레벨).

## 편집 중 발견한 사고 및 복구(투명성 원칙에 따라 기록)

리팩터링 도중 `replace_string_in_file`로 중복된 "설정 다운로드" 텍스트 블록을 병합하려다
`oldString`이 두 곳(신규 삽입분·기존 잔여분)에 모호하게 매칭되어, `{tab === "simulate" && (...)}`
전체 블록이 엉뚱하게 다른 버튼의 JSX 자식 사이에 삽입되는 사고가 발생했다. JSX 문법 자체는
깨지지 않아 `get_errors`가 즉시 잡지 못했고, 수동으로 파일을 순차 읽어 구조를 재확인한 뒤 발견해
정확한 위치로 복구했다. **재발 방지**: 유사 중복 텍스트가 있는 파일에서 큰 JSX 블록을 재배치할
때는 `oldString`이 파일 내에서 유일하게 매칭되는지 사전에 grep으로 확인하고, 편집 직후 반드시
`tsc --noEmit`으로 재검증한다(이번에도 최종적으로는 `tsc --noEmit` 0에러로 정상 구조임을 확인).
