## 문제 요약

Story 1.27 Task 1(아키텍처 설계)에서 확정한 설계대로, 예시 발화를 입력하면 실제 세션에 부수효과
없이 매칭 문서·IntelliDecision 유형/근거·실제 LLM 응답을 함께 반환하는 API를 구현했다.

## 수행 내용

1. **`src/ai_voicebot/langgraph/nodes/self_service_agent.py`**: `self_service_rag_search`
   call_data_record 이벤트에 `matched_doc_ids`/`scores`/`related_domains` 필드를 추가했다(기존
   `self_service_rag_matched` structlog 로그와 동일한 값). 응답 생성 로직은 무변경 — 순수
   관측 필드 추가로, 시뮬레이터가 call_id 기준으로 매칭 문서 정보를 조회할 수 있게 하기 위함.
2. **`src/ai_voicebot/self_service/decision_rationale.py`**: `_capture_and_log()`가
   `(matched_type, reasoning_summary)`를 반환하도록 리팩터링했다. 기존
   `schedule_rationale_capture()`(fire-and-forget 백그라운드 태스크)는 반환값을 그대로
   무시하므로 실서비스 호출부 동작은 무변경이다. 판정 프롬프트/파싱 로직은 한 글자도
   수정하지 않았다.
3. **`src/api/routers/knowledge_base_simulate.py`**(신규): `POST /api/knowledge-base/simulate`.
   - `_get_isolated_agent()`: `self_service_test.py`의 에이전트 생성 로직과 동일하되,
     `_agent_cache`에 등록하지 않는 1회성 인스턴스를 만든다.
   - `caller_number = f"sim-{uuid4()...}"` 형태로 매 호출마다 새 세션 키를 사용해 실 서비스
     세션과 절대 겹치지 않게 격리(AC3).
   - `ConversationAgent.process_utterance()`를 직접 호출(실행 경로 재사용, AC2).
   - `decision_rationale._capture_and_log()`를 직접 `await`해 유형/근거를 즉시 확보.
   - `_extract_matched_documents()`로 call_data_record에서 매칭 문서 정보 조회.
4. **`src/api/main.py`**: 신규 라우터 등록.
5. **`tests_new/unit/test_ai_voicebot/test_knowledge_base_simulate_endpoint.py`**(신규):
   요청 검증(400/503), 매칭 문서 조립(`_extract_matched_documents`), 시뮬레이션 전체 흐름
   (격리 세션 키 검증 포함) 9건.

## 검증 결과

- 신규 단위테스트 9건 전체 통과.
- 기존 `test_self_service_decision_rationale.py`(반환값 리팩터링 영향 확인) 포함 self_service/
  knowledge 관련 회귀 236건 전체 재실행 — 0 FAILED.
- `from src.api.main import app`로 직접 임포트해 `/api/knowledge-base/simulate` 라우트가
  정상 등록됨을 서버 기동 없이 확인.
