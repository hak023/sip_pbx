## 1. 문제

2026-08-07 QA 계획 작성 중 발견된 갭: `self_service_agent.py`의 Tool-calling 루프
(`_try_bind_self_service_tools`/Gemini native FC 폴백)는 정적 `SELF_SERVICE_TOOLS`만 bind하고,
Story 1.35에서 구현된 `dynamic_api_tool.py`(업로드된 OpenAPI 문서 기반 실행기)는 실제 대화 루프에
전혀 연결되어 있지 않았다. 즉 사용자가 업로드+승인한 REST-API라도 대화 중 실제로 호출되지 않았다.

## 2. 구현 내용

### `src/ai_voicebot/self_service/dynamic_api_tool.py`

- `build_dynamic_tools_for_owner(owner)` 신설 — owner의 `knowledge_documents`(source_type=openapi)
  + `knowledge_document_endpoints`를 조회해 LangChain Tool 목록을 만든다.
  - GET은 승인 없이 항상 포함(기본 능동), 쓰기 메서드(POST/PUT/PATCH/DELETE)는 문서의
    `approved_methods`에 있는 경우만 Tool로 노출된다 — **미승인 메서드는 Tool 목록 자체에서
    제외**되어 LLM이 애초에 그 존재를 알 수 없다(Story 1.34 화이트리스트 원칙 그대로 재사용).
  - 각 Tool은 `params`(경로/쿼리 dict)와 `body`(요청 본문 dict)를 받고, `endpoint_path`의
    `{param}` 플레이스홀더를 `params`에서 자동 치환한 뒤 `execute_api_endpoint()`를 호출한다.
  - `self_service/tools.py::_make_tool` 패턴을 로컬에 복제(langchain_core 미설치 시 원본 함수
    그대로 반환, import 안전성 유지).
- `find_last_undoable_document_id(owner)` 신설 — 사용자가 "방금 한 거 취소해줘"라고 말할 때
  document_id를 알 수 없으므로, owner의 문서 전체에서 되돌리지 않은 최근 쓰기 실행을 찾는다.
- 문서가 1개 이상 있으면 제네릭 `_undo_last_dynamic_api_change` Tool을 자동 추가해 유형 E(취소)를
  동적 Tool 실행에도 연결(기존 `undo_last_execution()` 그대로 재사용).

### `src/ai_voicebot/langgraph/nodes/self_service_agent.py`

- `_self_service_tools_for_owner(owner)` 신설 — `SELF_SERVICE_TOOLS` + `build_dynamic_tools_for_owner(owner)`를
  합친 목록을 반환(동적 Tool 빌드 실패 시 경고 로그만 남기고 정적 목록은 그대로 유지, 기존 흐름
  회귀 없음).
- `_try_bind_self_service_tools`/`_try_build_self_service_gemini_fc`/`_execute_self_service_tool`
  3개 함수 모두 이 헬퍼를 사용하도록 수정(시그니처에 `owner` 파라미터 추가).
- 기존 보안 장치(owner 강제 치환, `tool_args["owner"] = owner`)는 Tool 종류와 무관하게 이미
  적용되는 코드라 수정 불필요 — 동적 Tool에도 동일하게 적용된다.

## 3. 검증

- 신규 단위테스트: `TestBuildDynamicToolsForOwner`(4건 — 문서 없음/미승인 메서드 제외/승인
  메서드+Undo Tool 포함/경로 파라미터 치환+execute_api_endpoint 호출 검증),
  `TestFindLastUndoableDocumentId`(2건).
- 기존 `test_self_service_settings_tool.py`의 `_try_bind_self_service_tools`/
  `_try_build_self_service_gemini_fc`/`_execute_self_service_tool` 호출부를 새 시그니처(owner
  추가)에 맞춰 갱신, 동적 Tool 빌드는 `monkeypatch`로 빈 리스트 고정해 기존 어서션(정적 Tool
  개수 기준)이 결정론적으로 유지되도록 함.
- `pytest tests_new/unit -k "self_service or dynamic_api or intellidecision"` — **259건 전체
  통과(0 FAILED)**.
- **잔여**: 실서버 IV — 다음 세션에서 사용자가 QA 계획서(§1~§5)를 실제로 실행할 때, 유형
  B(실행성)/E(취소) 케이스가 실제로 REST-API를 호출하는지가 이 Story의 최종 검증을 겸한다.

## 4. 의도적으로 하지 않은 것

- Tool 목록을 owner/문서 버전 기준으로 캐싱하는 성능 최적화는 하지 않음(매 턴 DB 조회) —
  QA 규모에서는 문제 없으나, 대규모 운영 시 `self_service/rag.py`의 캐싱 패턴을 참고해 후속
  최적화 검토 권장.
- OpenAPI 파라미터의 정교한 타입 스키마(정수/불리언 등) 변환은 하지 않고 `params`/`body`를
  범용 `Dict[str, Any]`로 노출 — Gemini FC 스키마 변환(`booking_gemini_fc.py`) 관점에서는
  `dict` 타입이 명시적 `object` 스키마로 변환되어 2026-07-21 수정(Any→STRING) 대상이 아님을
  확인했으나, 실제 LLM이 파라미터 값을 정확히 채우는지는 실서버 IV에서 최종 확인 필요.
