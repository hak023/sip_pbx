## 검증 절차

동일 발화("뭘 할 수 있어?")가 Story 1.32(시뮬레이터 UX)와 Story 1.33(하이브리드 검색)의 검증
대상을 동시에 만족시키므로, 사용자 서버 재시작 이후 하나의 세션으로 두 Story를 함께 검증했다.

1. **최신 코드 반영 확인**: 프론트(3000)/백엔드(8000·8001) 프로세스 시작 시각(10:49~50대)이
   두 Story의 코드 수정 시각보다 늦음을 확인.
2. **정책 API 확인**: `GET /intellidecision-policy` 실제 호출 결과 유형 C의
   `rag_strategy_hint="hybrid_multi_domain"`가 반영됨을 확인(Story 1.33 AC1).
3. **시뮬레이터 API 확인**: `POST /api/knowledge-base/simulate`(owner=9001,
   query="뭘 할 수 있어?") 실행 결과:
   - `matched_documents`가 4개 서로 다른 `related_domain`(operator-status/ai-escalation/
     call-control/chat-relay)에 걸쳐 반환됨(Story 1.33 AC2, 하이브리드 다중 도메인 검색 실증).
   - `hop_path`가 4개 도메인 각각의 `rendered_by`/`writable` 간선을 포함함(Story 1.32 AC4-②).
   - `logs/app.log`의 `self_service_agent_hybrid_rag_merged`(`hybrid_doc_count=6,
     merged_total=7`)가 API 응답 문서 수(7)와 정확히 일치(cross-check).
4. **프론트엔드 확인**(Playwright, 이 저장소의 상시 WebSocket 재연결 불안정 이슈로
   `force: true` 클릭으로 우회 — 2026-07-20/28/08-04 반복 기록된 기존 이슈):
   - "AI 의사결정 로직" 탭이 유형 A~I 9개 하위 탭으로 정상 렌더링(Story 1.32 AC1).
   - 유형 C 탭의 각 예시 옆에 "RAG · hybrid_multi_domain(self_service_manual(owner))" 배지가
     정확히 표시됨(Story 1.32 AC3, Story 1.33 정책 갱신과 연동 확인).
   - 예시 질문 클릭 → "응답 시뮬레이터" 탭으로 자동 이동 → 턴 1 생성, 4개 도메인 hop_path가
     간선 칩으로 시각화됨(Story 1.32 AC4).
   - **AC5(멀티턴) 실증**: 같은 화면에서 새 질문("착신 규칙을 바꾸고 싶어요")을 입력해 실행한
     결과, 턴 1이 그대로 남은 채 턴 2가 아래에 추가로 표시됨(스크린샷 대체 스냅샷으로 확인).
5. **대조군 확인(하이브리드 게이팅 정상 작동)**: 턴 2("착신 규칙을 바꾸고 싶어요")는 단일
   도메인(call-control) 질문이라 hop_path가 call-control 1개로만 국한됨을 확인 — 휴리스틱
   미일치 시 하이브리드 검색이 실행되지 않아 불필요한 검색 확장이 없음을 실증.
