## 2026-08-06 후속 수정 — 사용자 검증 결과 2건 시정

배포 직후 사용자가 실제 화면을 확인하고 지적한 2가지 문제를 근본 원인부터 조사해 수정했다.

### 1. qa 항목이 같은 제목으로 3번씩 중복 나열됨

**원인**: `items`(qa) 배열은 매뉴얼 문서의 **개별 청크(질문 1개)** 단위이며, 같은 섹션
(`section_title`)에 속한 여러 청크가 통합 리스트에서 각각 별도 행으로 매핑되어(`title =
section_title || question`) 동일 제목이 반복되어 보였다. 기존 `qa` 탭은 사이드바로 섹션을
먼저 선택해야 해당 섹션의 청크만 보여서 이 중복이 눈에 덜 띄었을 뿐, 근본적으로는 원래도
같은 구조였다.

**수정**: `buildUnifiedKnowledgeItems()`가 qa 항목을 `section_title` 기준으로 그룹핑해
섹션당 리스트 행 1개만 생성하도록 변경(`QaGroup` 타입 신설, `entries`에 원본 청크 전체 보존).
상세 패널(Story 1.49)에서 그룹 내 모든 질문/답변을 나열해 정보 손실은 없다.

### 2. RAG(지식) 항목에 hop 연결이 실제로 없었음(계획과 다르게 구현됨)

**원인**: 계획 리포트 와이어프레임은 "연결 경로: 예약관리 > 배송 설정"을 상세 패널에 명시했으나,
실제 구현은 `qa`/`catalog` 탭에 hop 경로 표시 로직 자체가 원래 없었던 것을 "재사용"이라고
잘못 기술하고 넘어갔다(Story 1.49 Dev Notes 오기재). hop 경로 조회는 업로드 문서(Story 1.37,
`document_id` 필요)와 IntelliDecision 매뉴얼 사례(Story 1.40)에만 존재했고, qa/catalog/screen
항목은 `related_domain` 배지만 있을 뿐 실제 지식 그래프 연결을 조회하지 않았다.

**수정**: `traverse_graph()`를 도메인만으로 호출하는 신규 백엔드 엔드포인트
`GET /api/settings/ai-assistant/domain-hop-path`를 추가(`settings_ai_assistant.py`,
`get_document_hop_path()`와 동일 원리, document_id 없이 domain만 사용). 프론트엔드에
`HopPathSection` 컴포넌트를 신설해 qa(대표 도메인 1개)/catalog/screen 상세 패널 전부에서
실제 hop 경로를 조회·표시하도록 연결했다. `DOMAIN_LABEL`/`HopPathTrail`/`humanizeHopNode`는
`page.tsx`와 상세 패널이 공유하도록 `frontend/components/knowledge-base/HopPathTrail.tsx`로
추출했다(중복 정의 제거).

### 3. 리스트 항목 가독성 개선

배지·제목·도메인 태그를 한 줄에 몰아넣던 레이아웃을 세로로 분리(배지 → 제목 → 도메인 태그
순서)하고, 도메인 태그에도 `DOMAIN_LABEL` 한글 라벨을 적용했다.

## 2026-08-06 재설계 — 클릭 기반 리스트+상세를 hop 연결 성분 그룹 테이블로 전면 교체

위 hop 연결 수정을 반영한 뒤에도 사용자가 "이건 원하는 방향이 아니다"라고 재차 지적했다.
정확한 지적: "매뉴얼/설정/화면안내를 유형별로 따로 보여주고 클릭해야 연결을 보는 방식이 아니라,
hop 그래프로 실제 연결된 것들을 클릭 없이 하나의 표로 묶어서 보여달라". 확인 질문을 거쳐
"hop 그래프의 연결 성분(cluster) 기준으로 그룹핑, 요약은 항상 표시하고 상세는 아코디언으로
펼침, 연결 없는 항목도 있는 정보만 표시"로 방향을 확정했다.

**변경 내역**:
- `frontend/components/knowledge-base/KnowledgeClusterTable.tsx` 신설 — qa/catalog/screen에
  등장하는 모든 도메인의 hop 경로를 병렬 조회한 뒤, 경로 압축을 적용한 Union-Find로 hop
  간선(`source_type:id` ↔ `target_type:id`)을 연결 성분으로 묶는다. qa는 `section_title`
  단위로 먼저 그룹핑(기존 중복 행 수정 로직 계승)한 뒤 클러스터에 배정.
- 각 클러스터를 `<details>` 아코디언으로 렌더링 — `<summary>`에 도메인 라벨 + Q&A/설정/화면/
  hop 단계 수 요약을 항상 표시(클릭 불필요), 펼치면 hop 경로·원문·필드 상세가 나온다.
- `frontend/app/settings/ai-assistant/docs/page.tsx`의 `list` 탭을 `KnowledgeClusterTable`
  단일 호출로 교체. 이전 설계 산출물인 `UnifiedKnowledgeList.tsx`/`UnifiedKnowledgeDetailPanel.tsx`는
  더 이상 사용되지 않아 혼동 방지를 위해 삭제.
- `GET /api/settings/ai-assistant/domain-hop-path`(직전 수정에서 추가) 백엔드 엔드포인트는
  그대로 재사용.

**검증**: `npx tsc --noEmit` 재검증 0에러. 실서버 IV는 여전히 미진행(사용자 요청에 따라 후속).

## 2026-08-06 재수정 — 카테고리 박스 제거 + 탭 데치러

사용자가 이번에도 "제대로 안 됐다"고 지적하며, 원하는 화면을 구체 예시로 직접 제시했다:
같은 도메인(예: `ai-escalation`)의 Q&A → 화면 안내 → 설정 정보가 "매뉴얼 Q&A"/"설정"/
"화면 안내" 같은 카테고리 상자로 나뉘지 않고 하나로 이어 붙어 보여야 한다는 것.

**변경 내역**:
- `KnowledgeClusterTable.tsx`의 그룹 본문에서 "매뉴얼 Q&A"/"설정"/"화면 안내" 소제목과 개별
  테두리 상자를 제거하고, Q&A → 화면 안내 → 설정 순서로 `divide-y` 가로줄만으로 구분되는
  하나의 흐름으로 렌더링. 사용자가 제시한 예시 순서(제목 → 질문 → 답변 → 화면명+도메인+링크+
  설명+필드 → 설정명+배지+필드)를 그대로 반영.
- `ScreenRaw`에 `fields`를 추가해 화면 안내에 입력 필드(라디오 등) 정보도 함께 노출.
- `frontend/app/settings/ai-assistant/docs/page.tsx`의 탭 버튼을 `list`/`policy`/`upload`
  3개로 축소(코드/데이터 로딩은 그대로 유지, 노출만 제거) — 지식 "항목"으로서의 qa/catalog/
  screen/kb 탭은 `list`(지식 그룹 테이블)로 흡수되어 같은 정보가 여러 페이지에 중복 노출되는
  것을 방지.
