# Story 1.31 실서버 IV 검증 리포트 — 업로드 데이터 기반 지식베이스 자동 구성

## 검증 절차 및 결과

1. **최신 코드 반영 확인**: 사용자가 `start-all.ps1`로 재시작한 프로세스(프론트 3000/백엔드
   8000·8001) 시작 시각(10:19대)이 Story 1.31 코드 수정 시각보다 늦음을 확인.
2. **도메인 비종속 실증(AC2)**: SIP PBX와 무관한 가상의 이커머스 주문 API OpenAPI 스펙
   (`GET/POST /orders`, `DELETE /orders/{id}/cancel`)을 `owner=9001`로 실제 업로드(3청크 색인).
3. **자동 분류 결과 확인(AC1-b, AC3)**: `GET /knowledge-base/inventory?owner=9001` 호출 결과
   `auto_assembled.setting_item_count=3`, `writable_setting_item_count=2`(POST/DELETE만 집계,
   GET은 제외)로 정확히 분류됨을 확인 — 코드 리뷰 시 예상한 분류 로직이 실제 서버에서도 그대로
   동작.
4. **cross-check**: `logs/app.log`의 `knowledge_document_registered`/`knowledge_document_deleted`
   이벤트가 API 응답의 `document_id`/`chunk` 수와 정확히 일치함을 확인.
5. **테스트 데이터 정리**: 업로드한 테스트 문서를 삭제해 `GET /documents?owner=9001` 결과
   `total:0`으로 원상복구.

## 특이사항

검증 중 첫 업로드 명령이 PowerShell 따옴표 이스케이프 문제로 실패했고, 재시도 과정에서 동일
문서가 2회 업로드되는 해프닝이 있었다(둘 다 정상 색인·정상 삭제됨, 데이터 정합성에는 문제 없음).
분류 로직 자체는 중복 여부와 무관하게 항목별로 독립적으로 정확히 동작함을 재확인했다.
