## 문제 요약

`manual_indexer.py`는 마크다운 매뉴얼 Q&A 파싱 로직만 하드코딩되어 있어, 향후 API 스펙·Tool
docstring 등 다른 유형의 문서를 색인하려면 이 파일 자체를 계속 고쳐야 하는 구조였다.

## 수정 내용

`index_self_service_manual()` 내부에서 `load_manual_qa_pairs()`/`load_manual_qa_with_meta()`를
직접 호출하던 두 지점을 `SourceAdapter` 프로토콜(`load_pairs`/`load_pairs_with_meta`)로 추출하고,
기존 마크다운 파서를 그대로 감싼 `MarkdownManualAdapter`를 기본 구현체로 제공했다.
`index_self_service_manual(..., adapter: Optional[SourceAdapter] = None)` 파라미터를 추가해
호출부(`settings_ai_assistant.py` 2곳)는 전혀 수정하지 않고도(기본값이 기존 동작과 동일) 향후
다른 어댑터를 주입할 수 있는 구조를 마련했다.

신규 소스 어댑터(OpenAPI 스펙 파서 등)의 구체 구현과 Contextual Retrieval(청크별 LLM 자동 맥락
요약) 적용은 이번 Story 범위에 포함하지 않았다(AC4/AC5) — 전자는 실제 수요 확인 후, 후자는 별도
비용·품질 스파이크 이후 결정한다.

## 검증 결과

- `MarkdownManualAdapter.load_pairs()`/`load_pairs_with_meta()`가 동일 입력에 대해 기존 모듈
  레벨 파서(`parse_manual_qa_pairs`/`parse_manual_qa_with_meta`)와 **동일한 반환값**을 내는지
  직접 비교하는 단위 테스트 2건 신규 추가, `adapter=` 파라미터 주입 테스트 1건 추가.
- `test_self_service_manual_rag.py` 전체(25건, 기존 22건+신규 3건) 통과.
- `pytest tests_new/unit/test_ai_voicebot -k "self_service or intellidecision"` 296건 전체
  통과(회귀 없음).
- 기존 `load_manual_qa_pairs`를 `monkeypatch.setattr`으로 패치하던 기존 테스트들도 그대로
  통과 — `MarkdownManualAdapter`가 모듈 레벨 함수를 재참조(delegate)하는 방식이라 패치가 여전히
  유효함을 확인.

## 잔여 작업

- Contextual Retrieval 적용 여부 스파이크(별도 문서, 비용·품질 실측 필요).
- 신규 소스 유형(예: OpenAPI 스펙) 어댑터 구현은 실제 수요가 확인된 후 별도 Story로 진행.
