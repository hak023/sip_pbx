## 요구사항 요약(FR33-E)

유형 C(포괄적 도움 요청)는 특정 도메인 하나로 좁혀지지 않는 질문이므로, RAG 검색이 여러
도메인에 걸쳐 병렬로 실행되고 카테고리별로 집계되어야 한다. NFR1(지연 예산) 보호를 위해
`asyncio.gather` 등으로 병렬화해야 하며, 기존 유형 C 응대 품질에 회귀가 없어야 한다.

## 현황 진단(Task 1, 코드 직접 확인)

`self_service_agent.py`를 직접 읽어 확인한 결과, 유형이 확정되기 전에 `rag_engine.search()`
단일 호출만 수행하고 있었다(도메인별 분리 검색 없음) — Story 1.24 IV 검증에서 이미 발견된
"유형 확정 전에 이미 RAG 검색이 실행되는 구조"와 동일한 패턴임을 재확인했다. 이 구조상 유형
분류 이후에만 하이브리드 검색을 트리거하는 것은 불가능(유형이 아직 없음)하므로, 유형 C의
trigger_examples 어휘를 활용한 **경량 사전 휴리스틱**으로 하이브리드 검색 실행 여부를 결정하는
방식을 채택했다(최종 유형 판정은 여전히 LLM이 담당 — 휴리스틱은 검색 실행 여부만 결정하므로
오탐이 있어도 다른 유형 응대 로직에 영향이 없다).

## 구현 내용

- 신규 `src/ai_voicebot/self_service/hybrid_rag.py`:
  - `looks_like_broad_help_query(query)`: 유형 C `trigger_examples`와 동일 어휘 기반 경량
    휴리스틱("뭘 할 수", "사용법" 등).
  - `search_hybrid_multi_domain(query, owner, vector_db, embedder, top_k_per_domain=2)`:
    `settings_catalog.list_domains()`의 각 도메인마다 ChromaDB를 `related_domain` 메타데이터로
    직접 필터링해 조회하고, 전체를 `asyncio.gather`로 병렬 실행. 개별 도메인 조회 실패는
    best-effort로 건너뛴다.
- `self_service_agent.py`: 휴리스틱이 참일 때만 기존 `rag_engine.search()` 호출과 **병렬로**
  하이브리드 검색을 추가 실행(`asyncio.gather`, NFR1/AC5 지연 예산 보호 — 휴리스틱 불일치 시
  추가 task 자체가 생성되지 않아 지연 영향 0). 결과는 기존 `rag_documents` 리스트에 중복 doc_id
  제거 후 병합된다.
- **파급 효과(설계상 유리한 부수 효과)**: 병합된 `rag_documents`가 프롬프트 조립(`_format_rag_context`)/
  화면 안내(`_format_screen_guidance`)/trace 로깅(`self_service_rag_matched`)/Story 1.32의
  `hop_path` 수집 경로를 전부 기존 그대로 통과하므로, 여러 `related_domain`이 자연스럽게 함께
  발생해 **AC3(시뮬레이터에서 병렬 hop 시각화)가 추가 코드 수정 없이 자동으로 충족**된다.
- `intellidecision_policy.py`: 유형 C `rag_strategy_hint`를 `"hybrid"` → `"hybrid_multi_domain"`로
  갱신(AC1).
