## 문제 요약

Task 2~4에서 구현·단위테스트까지 통과한 응답 시뮬레이터를, 사용자 승인 하에 API 서버를
재시작해 실제 LLM/RAG로 호출한 결과 **`matched_documents`가 항상 빈 배열로 반환**되는 문제를
발견했다. 단위테스트는 `ConversationAgent`를 모킹했기 때문에 이 문제를 잡아내지 못했다.

## 근본 원인

Task 2 구현 당시 "격리 세션"을 만들기 위해 `caller_number = f"sim-{uuid4().hex[:12]}"`처럼
owner와 다른 임의의 값을 사용했다. 그러나 `src/ai_voicebot/self_service/detection.py::
is_self_service_session()`은 **`caller_number`와 `owner`가 정규화 후 동일할 때만 True를
반환**하도록 설계되어 있다(셀프콜 감지 규칙, Story 1.4). `caller_number != owner`이면 셀프서비스
세션으로 인식되지 않아 `self_service_agent` 노드 자체를 거치지 않고 **일반 chitchat 경로로
라우팅**된다 — RAG 검색도, IntelliDecision 판정 컨텍스트도 전혀 다른 흐름을 타게 되어 AC1/AC2가
근본적으로 성립하지 않는 상태였다.

로그로 직접 확인한 증거(추측이 아닌 실측):
- `call_data_record` 로그에서 실제 요청의 `intent_classify` 이벤트가 `"path": "persona_chitchat"`
  로 기록됨(셀프서비스 경로가 아님).
- `self_service_session_detected` 이벤트에서 `"is_self_service": false`가 명시적으로 로깅됨.

## 근본 원인 수정

`caller_number`를 `owner`와 동일하게 설정하도록 변경했다 — 이는 `self_service_test.py`가 이미
채택한 방식과 동일하다(그 파일도 `caller_number = (body.caller_number or owner)`로 기본값을
owner로 둔다). **격리(AC3)는 caller_number가 아니라 다음 두 가지로 보장**하도록 재설계했다:

1. 매 호출마다 새로 생성되는 `call_id`(`f"simtest-{uuid4().hex[:12]}"`) — 실제 통화의 call_id와
   충돌하지 않으므로 LangGraph 체크포인터/CDR이 실 세션과 섞이지 않는다.
2. `self_service_test.py`의 `_agent_cache`(멀티턴 세션 재사용 캐시)에 **등록하지 않는 1회성
   `ConversationAgent` 인스턴스** — 매 요청마다 새로 생성/폐기되므로 대화 맥락이 남지 않는다.

## 재검증 결과 (수정 후, 사용자 승인 하에 서버 재시작 후 실측)

- `POST /api/knowledge-base/simulate`(owner=9001, query="착신 규칙을 어떻게 바꾸나요?")
  → `matched_documents`에 `call-control` 도메인 청크 2건 정상 반환, `intellidecision_type: "A"`,
  실제 안내 응답(화면 경로·평가 순서 설명) 정상 생성.
- **크로스체크(coding-standards §6 방법론)**: 동일 owner/query로 `POST /api/self-service/test/
  converse`를 호출해 비교 — `matched_doc_ids`/`scores`/`related_domains`가 **완전히 일치**하고
  응답 내용도 의미적으로 동일함을 확인(AC2: 실행 경로 재사용 검증 완료).
- `GET /api/self-service/test/status`의 `cached_sessions: 0` 확인 — 시뮬레이터 실행이
  `_agent_cache`를 전혀 오염시키지 않음(AC3 확인).
- 브라우저(`localhost:3000/settings/ai-assistant/docs`)에서 "응답 시뮬레이터" 탭이 정상
  렌더링되고 안내 문구·입력창·실행 버튼(owner 미설정 시 비활성화, 다른 탭과 동일한 가드 패턴)이
  설계대로 동작함을 스냅샷으로 확인.
- 기존 self_service/knowledge 회귀 236건 + 신규 시뮬레이터 단위테스트 9건(caller_number
  단언 수정 포함) 전체 재실행 — 0 FAILED.

## 교훈

- 단위테스트에서 `ConversationAgent`를 모킹하면 "어떤 경로로 라우팅되는지"까지는 검증하지
  못한다 — 실서버 IV(실제 LLM/RAG 호출)가 아니면 발견할 수 없는 배선 버그였다.
- "격리 세션"을 구현할 때 무심코 아무 필드나 무작위 값으로 바꾸면, 그 필드가 다른 판별
  로직(여기서는 셀프콜 감지)의 입력이기도 하다는 사실을 놓칠 수 있다 — 재사용하는 기존 경로의
  판별 조건을 먼저 확인한 뒤 격리 방법을 설계해야 한다.
