## Story

**As a** 셀프서비스 AI 도우미를 운영하는 테넌트 관리자,
**I want** 예시 질문을 입력하면 실제 통화/채팅 세션에 영향 없이 "어떤 지식이 매칭되고, 어떤
IntelliDecision 유형으로 판정되며, 실제로 어떤 응답이 생성될지"를 미리 확인할 수 있고,
**so that** 지식베이스나 정책을 변경한 뒤 실제 사용자에게 노출하기 전에 응대 품질을 검증할 수 있다
(Intercom Fin의 Testing suite와 동등한 수준, §3.2).

## Acceptance Criteria

1. 신규(또는 확장) API `POST /api/knowledge-base/simulate`(가칭)가 `owner`, `query`(예시 발화)를
   입력받아 다음을 함께 반환한다: ①매칭된 지식 문서/청크(문서 ID, 관련 도메인 태그, 유사도 점수)
   ②판정된 IntelliDecision 유형(A~I)과 판단 근거 요약(Story 1.20~1.22 캡처 메커니즘 재사용)
   ③실제 LLM 호출로 생성된 최종 응답 텍스트.
2. 이 엔드포인트는 기존 `POST /api/self-service/test/converse`(Story 1.15~1.19 QA 하네스)와
   동일한 실행 경로(LangGraph 그래프, 실제 owner 데이터)를 재사용해야 한다 — 시뮬레이터 전용
   별도 로직을 새로 만들어 "시뮬레이터에서 본 결과가 실제 응답과 다르다"는 불일치를 발생시키지
   않는다.
3. 실제 통화/채팅 세션 상태(`booking_context`, 대화 히스토리 등)에는 어떤 부수효과도 남기지
   않는다 — 격리된 세션으로 실행된다.
4. 실 LLM 호출이 발생하므로 응답에 소요 시간(지연)이 표시되어야 하며, 프론트엔드에 "실제 LLM을
   호출하므로 시간이 걸릴 수 있습니다" 안내와 로딩 상태 UI가 있어야 한다(NFR8, 비용·지연 명시
   원칙).
5. 프론트엔드 `settings/ai-assistant/docs` 페이지의 "IntelliDecision 정책" 탭(Story 1.18)에서
   유형을 클릭하면 해당 유형의 대표 예시 발화로 시뮬레이터를 즉시 실행하는 바로가기가 제공된다
   (§5.3 유형별 연결 투명성).
6. 시뮬레이터 실행은 실제 RAG trace 로깅(`self_service_rag_matched`, Story 1.24)과 동일한
   필드를 프론트엔드에도 노출해, "사전 예측"(시뮬레이터 결과)과 "사후 실측"(실제 통화 로그)을
   운영자가 나란히 비교할 수 있게 한다.
