## Story

**As a** 개발자,
**I want** `google-generativeai` 의존을 저장소·venv에서 완전히 제거하고 실서버 통합 검증으로
booking/self_service/링백 경로가 정상 동작함을 확인하고,
**so that** Epic 6(Gemini SDK 마이그레이션)을 안전하게 종료할 수 있다.

## Acceptance Criteria

1. `google-generativeai` 패키지가 `requirements-ai.txt`에서 제거되고 venv에서 uninstall된다.
2. 저장소 전체에서 `import google.generativeai`가 실제 코드에 존재하지 않는다(grep 0건,
   docstring 역사적 언급 제외).
3. 실서버(사용자가 기동한 프로세스)로 chitchat 응답을 재현해 `call_data_record_*.log`
   원본 로그와 API 응답을 cross-check한다(coding-standards.md §6).
4. 실서버로 self_service Tool-calling(설정 조회) 경로를 재현해 `self_service_tool_start`/
   `self_service_tool_done` 로그로 실제 함수 호출이 발생함을 확인한다.
5. 실서버로 링백 가사 생성 API를 호출해 `used_llm: true`로 실제 LLM 응답이 사용됐음을 확인한다
   (2026-07-27 `gemini-2.0-flash` 404 수정의 실서버 검증 겸함).
6. thinking 비활성화 이후 chitchat 응답 지연을 다중 샘플로 재측정해 2026-07-24 베이스라인
   (9.6~9.75초)과 비교한 리포트를 남긴다(실구현은 Epic 4로 이관, 이번엔 측정만).
