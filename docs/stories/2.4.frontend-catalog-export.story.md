## Status

Done

## Story

**As a** 관리자,
**I want** AI 도우미 설정(카탈로그·Screen Graph)을 파일로 다운로드하기를,
**so that** 현재 구성을 검토하거나 백업·버전 관리할 수 있다.

## Acceptance Criteria

1. `설정 > AI 도우미` 도움말 화면에 "설정 다운로드" 버튼이 추가되어, 현재 활성 버전의 카탈로그+Screen Graph 설정을 JSON(또는 YAML) 파일로 다운로드할 수 있다.
2. 다운로드 파일에는 함수 화이트리스트 이름(문자열)만 포함되고, 실제 Python 콜러블 참조나 민감 정보는 포함되지 않는다(보안 — 파일이 유출되어도 코드 실행 경로가 노출되지 않아야 함).
3. 신규 REST 엔드포인트 `GET /api/settings/ai-assistant/catalog-config/export`를 추가한다.

### Completion Notes

- **DRY 리팩터링**: Story 2.1 마이그레이션 스크립트가 자체적으로 가지고 있던 "정적 `_CATALOG`/`_SCREEN_REGISTRY` → JSON 직렬화" 로직을 `settings_catalog.export_static_snapshot()`/`screen_graph.export_static_snapshot()`로 추출해 두 모듈이 공유하게 했다(마이그레이션 스크립트도 이 함수를 호출하도록 리팩터링) — 중복 로직이 드리프트할 위험을 제거.
- **폴백 설계**: DB에 활성 버전이 없을 때(마이그레이션 미실행 환경 등)도 export 엔드포인트가 실패하지 않고 즉석 정적 스냅샷을 반환하도록 해 다운로드가 항상 성공함(`*_source` 필드로 출처 구분). 카탈로그/Screen Graph 각각 독립적으로 출처가 결정된다(하나만 DB에 있고 다른 하나는 없는 혼합 상황도 테스트로 검증).
- **보안(AC2)**: `export_static_snapshot()`/DB `config_json` 모두 `get_fn_ref`/`update_fn_ref`가 문자열(화이트리스트 이름)로만 직렬화되며 실제 Python 콜러블은 절대 포함되지 않음을 테스트로 명시적으로 검증.
- 프론트엔드 다운로드는 별도 Content-Disposition 헤더 없이 `apiJson()`으로 JSON 본문을 받은 뒤 브라우저에서 Blob+`<a download>`로 파일 다운로드를 트리거하는 방식(백엔드 변경 없이 기존 REST 관례 유지). 다운로드 직후 출처(DB 버전 또는 기본값)와 버전 번호를 화면에 표시해 관리자가 무엇을 받았는지 즉시 확인할 수 있게 함.
- 업로드(import) 기능은 의도적으로 본 Story 범위에서 제외 — Story 2.5에서 구현 예정(프론트엔드 안내 문구에도 명시).
