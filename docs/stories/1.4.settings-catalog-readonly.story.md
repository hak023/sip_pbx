# Story 1.4: 설정 카탈로그 구축 (읽기 전용 등록)

## Status

Draft

> **시퀀싱 정정 안내**: 본 Story는 원래 PRD 초안에서 Story 1.7의 일부였으나, "온보딩 체크리스트(구 1.4)가 아직 없는 카탈로그에 의존"하는 순서 오류를 SM 리뷰에서 발견하여 **본 Story로 앞당겨졌다**(PRD v0.3, 2026-07-14). 카탈로그의 **쓰기(자동설정 실행) 기능**은 Story 1.8에서 별도로 다룬다.

## Story

**As a** 테넌트 관리자,
**I want** (간접적으로) AI가 내 서비스의 모든 설정 항목이 무엇인지 이미 알고 있기를,
**so that** 이후 온보딩 안내·설정 조회·자동설정 기능이 특정 항목 몇 개에 국한되지 않는다.

## Acceptance Criteria

1. `settings_catalog.py`에 **7개 설정 도메인**(persona, ai-escalation, call-control, chat-relay, contacts, general, integrations) 각각의 **조회 함수**·필수/옵션 스키마·destructive 여부가 등록된다(변경 함수·자동설정 실행은 Story 1.8 범위).
2. `list_domains()`, `get_domain_schema(domain)`, `get_domain_value(domain, owner)` 3개 조회 API가 카탈로그를 통해 동작한다.
3. 카탈로그에 등록되지 않은 도메인 조회 시 명확한 오류(빈 스키마 또는 "미등록 도메인")를 반환한다.

### Integration Verification

- **IV1**: 카탈로그의 조회 함수는 각 도메인의 기존 서비스/라우터 함수를 오직 읽기(read-only)로만 호출하며 부작용이 없다.
- **IV2**: 7개 도메인 각각에 대해 최소 1개 필드의 조회 테스트가 통과한다(카탈로그 커버리지 검증).

Architecture 문서는 7개 도메인 중 **3개만 확인**했고 나머지 4개는 후보만 나열했다. 이 Story의 첫 작업은 나머지 4개를 실제로 검증하는 것이다.

## Dev Notes

### Previous Story Insights

Story 1.1~1.3은 감지·라우팅·매뉴얼 RAG를 다뤘다. 본 Story부터는 **자동설정/조회 계열 기능의 기반**을 만든다 — 이후 Story 1.5(온보딩), 1.6(조회 Tool), 1.8(자동설정)이 모두 이 카탈로그 위에 쌓인다.

### 신규 설정 도메인 등록 규칙 (향후 유지보수 원칙)

신규 설정 페이지/필드가 추가될 때 `_CATALOG`에 등록하지 않으면 AI가 해당 항목을 전혀 인식하지 못한다(FR11). 이 규칙을 모듈 docstring에 명시한다.

### Technical Constraints

- **NFR4 관련**: 이 Story에서는 `destructive` 플래그만 등록하고 실제 제외 로직 집행은 Story 1.8에서 구현한다(관심사 분리).
- 각 도메인의 `get_fn`은 **반드시 `owner` 파라미터를 받아야 한다** — 다른 테넌트 데이터 유출 방지(§Architecture Security Integration 원칙).

## Testing

### Testing Standards

- **Test file location**: `tests_new/test_settings_catalog.py`
- **Framework**: pytest
- **필수 테스트 케이스**:
  1. `list_domains()`가 정확히 7개 도메인명을 반환
  2. 7개 도메인 각각 `get_domain_value(domain, owner)`가 실제 값을 반환(왕복 테스트, IV2)
  3. 미등록 도메인 조회 시 오류 반환(AC3)
  4. `get_fn`이 예외를 던지면 `{"error": ...}` 형태로 흡수되어 반환됨(부작용 없음 확인, IV1)
