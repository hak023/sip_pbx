# Story 1.10: IntelliDecision (탐색성/실행성 발화 구분 응대)

## Status

Done

## Story

**As a** 테넌트 관리자,
**I want** 내가 기능을 잘 몰라서 물어보는 것인지, 이미 명확히 바꿔달라고 요청하는 것인지에 따라 AI가 다르게 응대하기를,
**so that** 잘 모를 땐 충분한 설명과 함께 다음 행동을 제안받고, 확실히 원할 땐 불필요한 왕복 없이 빠르게 확인 후 실행되기를 바란다.

## Acceptance Criteria

1. 탐색성 발화(예: "AI가 모르는 질문 받으면 나한테 전화하게 해줄 수 있어?")에는 매뉴얼 참고 정보 기반 설명 + 사전 준비사항 + "필요하면 말씀해 주세요"류 제안으로 응답하고, 이 턴에서 `update_self_service_setting` Tool을 호출하지 않는다.
2. 실행성 발화(예: "AI가 에스컬레이션 안 하도록 설정해줘")에는 "[항목]을 [값]으로 설정할까요?" 형태로 즉시 확인 발화를 하며, 매뉴얼에 부작용 정보가 있으면 함께 안내한다. 사용자가 긍정하면 그때 Tool을 호출한다.
3. 두 유형 판단은 LLM이 최종 결정하며, 발화 패턴 기반 힌트(예: 종결 어미)는 시스템 프롬프트에 참고 신호로만 제공되고 강제 게이트로 사용되지 않는다(`.github/copilot-instructions.md`: "의도 분류는 키워드 매칭보다 LLM 판단을 우선한다").
4. 판단 근거를 사후 확인할 수 있도록 힌트 값과 실제 Tool 호출 여부가 `call_data_record`에 로깅된다.

  `"disabled"`를 선택해 문제가 되었음). `tools.py`의 도구 설명에 허용값(`hitl`/`transfer`/`none`)을
  명시한 예방 조치가 실제로 효과가 있음을 확인했다.
- 참고: 2턴 응답의 `old_value`가 직전 재초기화한 `"hitl"`이 아니라 `"none"`으로 나타난 경미한
  타이밍 불일치가 관찰되었다(값 검증 로직과는 무관, PersonaService 캐싱/저장 경로 관련 추정).
  실제 최종 저장값은 어느 쪽이든 유효값(`none`)이므로 기능적 영향은 없으며, 본 Story 범위 밖의
  별도 관찰 사항으로 남겨둔다(추가 조치 불필요 — 결과값 자체가 이미 올바름).
- **결론**: Story 1.10의 핵심 수정 사항(escalation_mode 값 검증)이 실서버에서 정상 동작함을 최종
  확인했다. 본 Story는 이로써 **완료**된다.
