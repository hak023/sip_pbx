## Story

**As a** 셀프서비스 AI 도우미 프롬프트를 유지보수하는 개발자,
**I want** 시스템 프롬프트의 번호 붙은 규칙이 코드에서 자동으로 번호가 매겨지기를,
**so that** 새 규칙을 추가·삭제할 때마다 이후 모든 번호와 교차 참조를 손으로 다시 세지 않아도 된다
("프롬프트 번호 재조정 함정"이 Story 1.15/1.16에서 2회 반복 발생했던 문제의 근본 해결).

## 배경

Story 1.18은 IntelliDecision 유형 A~I의 메타데이터를 `intellidecision_policy.py`로
데이터화했지만, 실제 프롬프트 산문(`_SELF_SERVICE_SYSTEM_PROMPT_TEMPLATE`/
`_TOOL_USAGE_INSTRUCTION`)은 회귀 위험 때문에 하드코딩된 번호 목록으로 그대로 남겨뒀다
(Story 1.18 Dev Notes "의도적 범위 축소" 참고). 이번 Story는 그 남은 부분 — 실제 번호
매기기와 "유형 C(7번)" 같은 교차 참조 — 를 데이터 기반 자동 렌더링으로 전환한다.

## Acceptance Criteria

1. `prompt_rules.py`에 `_BASE_RULES`/`_TOOL_RULES` 정적 리스트로 기존 18개 규칙이 등록
   순서대로 보존되어 있다(내용·순서 모두 기존과 동일 — 의미상 회귀 없음).
2. `render_base_prompt_rules()`는 `_BASE_RULES`를 1번부터 자동 번호를 매겨 텍스트로
   조립하고, `render_tool_prompt_rules()`는 `len(_BASE_RULES)+1`번부터 이어서 번호를 매긴다.
3. 규칙 텍스트 내 교차 참조(`유형 C(<<REF:type_c>>번)`)는 렌더링 시점에 실제 번호(7)로
   자동 치환되며, 렌더링 결과에 센티널 토큰(`<<REF:...>>`)이 남지 않는다.
4. `{fallback_message}` 같은 외부 template placeholder는 렌더링 과정에서 훼손되지 않고
   그대로 보존되어(리터럴 중괄호), 호출측(`self_service_agent.py`)의 `.format()`이 이후
   정상적으로 채울 수 있다.
5. `self_service_agent.py`의 `_SELF_SERVICE_SYSTEM_PROMPT_TEMPLATE`/`_TOOL_USAGE_INSTRUCTION`이
   하드코딩된 번호 목록 대신 `prompt_rules.render_*()` 호출 결과를 사용한다.
6. 기존 self_service 관련 회귀 테스트 전체(224건)가 그대로 통과하고, 신규
   `test_self_service_prompt_rules.py`(7건)가 통과한다.

## Dev Notes

- **서식(공백/들여쓰기) 차이는 허용**: 이 프롬프트는 LLM 입력이지 사람이 읽는 문서가
  아니므로, 번호 폭 변화에 따른 연속줄 들여쓰기 정렬은 완벽히 재현하지 않았다(코드
  가독성과 유지보수성을 우선). 실제 테스트로 확인한 결과 no 회귀(224건 전체 통과)이며,
  기존 테스트 어디에도 프롬프트 문자열을 정확히 assert하는 케이스가 없음을 사전에 grep으로
  확인했다(회귀 리스크가 낮다고 판단한 근거).
- **센티널 토큰 방식 선택 이유**: `<<REF:key>>`를 `str.replace()`로 치환하는 방식을 택하고
  `str.format()`은 전혀 사용하지 않았다 — 규칙 텍스트 안에 `{fallback_message}` 같은 외부
  placeholder가 이미 있어서, `.format()`을 이 모듈 내부에서 호출하면 `KeyError`가 나거나
  외부 placeholder를 실수로 소비해버릴 위험이 있었다.
- **교차 참조는 현재 1개뿐**(`general_length_limit` → `type_c`)이지만, 향후 새 규칙이
  다른 규칙을 번호로 참조해야 하면 동일한 `<<REF:key>>` 패턴을 재사용하면 된다 — 이것이
  이번 Story의 핵심 가치(번호 재조정 함정의 구조적 해결)다.
- Story 1.18의 `intellidecision_policy.py`(유형 메타데이터)와 이 모듈(`prompt_rules.py`,
  실제 프롬프트 산문)은 현재 별도 모듈로 유지한다 — 유형 메타데이터의 `intent_types` 필드로
  느슨하게만 연결되며, 완전히 통합(유형 레지스트리에서 프롬프트까지 단일 소스로 생성)하는
  것은 이번 범위를 넘어선다(과설계 방지, "능력 레지스트리 결정 지원 리포트"의 축소 원칙과
  동일 정신).
