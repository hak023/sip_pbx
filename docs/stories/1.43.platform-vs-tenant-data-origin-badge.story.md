# Story 1.43: 플랫폼 공통 vs 테넌트 데이터 배지 UI

## Status
Review

> 상세 배경·설계 방향: [Epic 4 계획 리포트](../reports/2026-08/2026-08-06_epic4_platform_maturation_and_ux_transparency_planning.md) §5(FR35-C).

## Story
As a 테넌트 관리자,
I want 화면에 보이는 지식·정책 항목이 "우리 플랫폼이 모든 테넌트에 공통으로 제공하는 고정
콘텐츠"인지 "내가 업로드한 테넌트 전용 데이터"인지 구분해서 보기를,
so that 무엇을 내가 바꿀 수 있고 무엇은 플랫폼 표준인지 혼동하지 않는다.

## Acceptance Criteria
1. `/ai-agent` IA(Story 1.36) 및 `settings/ai-assistant/docs` 하위 화면에서 `intellidecision_policy.py`
   유형 A~I 항목처럼 테넌트 업로드와 무관하게 항상 존재하는 항목에 "플랫폼 공통" 배지가 붙는다.
2. `knowledge_documents`(Story 1.26)로 업로드된 테넌트별 항목에는 "테넌트 데이터" 배지가 붙는다.
3. 배지 판별 로직은 프론트엔드에서 데이터 출처(API 응답의 `source`/존재 여부)로 결정하며, 신규
   백엔드 필드 추가가 필요하면 최소한으로 한다(기존 API가 이미 구분 가능한 필드를 갖고 있는지
   먼저 확인 — Story 1.31/1.38의 "이미 있는 데이터로 충분한가" 우선 확인 패턴 적용).
4. 배지는 시각적으로만 구분하고 기능적 차이(수정 가능 여부 등)는 기존 로직을 그대로 따른다.

  이미 출처 구분자**라서 신규 백엔드 필드가 전혀 필요 없음(AC3 충족). 유일한 예외는 policy 탭 내
  각 유형 카드 하단의 "지식베이스 사례"(Story 1.40) 섹션으로, 이건 같은 탭 안에서도 실제로
  테넌트 업로드 데이터(벡터 검색 결과)를 보여주므로 배지를 분리해서 붙임.

  항목 라벨에도 "(플랫폼 공통)"/"(테넌트 데이터)" 짧은 표기 추가(AC1 범위 충족).
