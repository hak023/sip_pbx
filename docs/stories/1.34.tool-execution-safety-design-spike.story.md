## Story

**As a** 임의의 외부 REST API를 업로드해 AI가 실제로 조작하게 하려는 테넌트 관리자,
**I want** 실행 가능한 Tool이 안전하게 승인·실행·되돌리기 가능한 구조로 설계되기를,
**so that** 신뢰도가 검증되지 않은 외부 API를 AI가 함부로 실행해 되돌릴 수 없는 피해를 주지
않는다.

## Acceptance Criteria

1. 업로드된 OpenAPI 스펙의 엔드포인트 중 읽기 전용(GET)은 기본 활성화되고, 쓰기 메서드(POST/
   PUT/PATCH/DELETE)는 **테넌트 관리자가 명시적으로 승인**한 엔드포인트만 실행 가능한 상태로
   저장하는 데이터 모델(승인 상태 컬럼/테이블)을 설계한다.
2. 실행 전 상태를 기록해 되돌릴 수 있는(undo) 메커니즘 설계 — Story 1.17 Undo Tool 패턴(가장
   최근 변경의 old_value를 재적용)을 일반화할 수 있는지, 아니면 별도 스냅샷 저장이 필요한지
   설계 스파이크로 결정한다.
3. 실행 실패(4xx/5xx, 타임아웃 등) 시 사용자에게 명확한 실패 사유를 안내하고 재시도/폴백
   정책을 정의한다(묵살 금지).
4. 이번 Story는 **설계 문서·데이터 모델 스파이크**만 포함하며, 실제 실행 엔진 구현은 Story 1.35에서
   진행한다(범위 분리로 리스크 점진적 감소).

- 이 Story는 리서치(§3.1 GoEx "undo/damage confinement")와 Epic 2의 화이트리스트 원칙을 그대로
  계승하는 것이 핵심이다 — 완전히 새로운 보안 모델을 발명하지 말 것.
- 보안 리스크(SIP 본인확인 등)는 PRD 범위 밖이지만, "임의 외부 API 실행"은 이 프로젝트의 첫
  "테넌트가 지정한 임의 시스템에 쓰기 작업을 수행"하는 기능이므로 신중하게 설계할 것.

### 구현 완료(2026-08-06)

- **스키마**: `knowledge_documents.approved_methods_json`(DDL+마이그레이션, DEFAULT=`["GET"]`) +
  `tool_execution_log`(Undo 스냅샷 저장) 실제 dev DB에 적용 확인(`PRAGMA table_info`).  
- **승인 API**: `PATCH /api/knowledge-base/documents/{id}/approve-methods` 신규,
  `update_approved_methods()`(DB 헬퍼) 신규 — GET은 항상 포함, 알 수 없는 메서드는 조용히 무시.
- **정책 모듈**: `tool_execution_policy.py`에 승인 검사헬퍼(`is_method_approved`/
  `validate_execution_request`), 실패 안내 문구 상수, 재시도/타임아웃 정책 코드화.
- **Undo 스파이크 결론**: Story 1.17 패턴 재사용 불가 확정 — `tool_execution_log.pre_state_json`으로
  실행 전 GET 스냅샷을 저장하고 역호출하는 방식.
- 단위테스트 12건(정책 헬퍼 8건 + DB 승인 CRUD 4건) 전체 통과.
