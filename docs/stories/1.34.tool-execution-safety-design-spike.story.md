## Story

**As a** 임의의 외부 REST API를 업로드해 AI가 실제로 조작하게 하려는 테넌트 관리자,
**I want** 실행 가능한 Tool이 안전하게 승인·실행·되돌리기 가능한 구조로 설계되기를,
**so that** 신뢰도가 검증되지 않은 외부 API를 AI가 함부로 실행해 되돌릴 수 없는 피해를 주지
않는다.

## Acceptance Criteria

1. 업로드된 OpenAPI 스펙의 엔드포인트 중 읽기 전용(GET)은 기본 활성화되고, 쓰기 메서드(POST/
   PUT/PATCH/DELETE)는 **테넌트 관리자가 명시적으로 승인**한 엔드포인트만 실행 가능한 상태로
   저장하는 데이터 모델(승인 상태 컬럼/테이블)을 설계한다.
2. 실행 전 상태를 기록해 되돌릴 수 있는(undo) 메커니즘 설계 — Story 1.17 Undo Tool 패턴(가장
   최근 변경의 old_value를 재적용)을 일반화할 수 있는지, 아니면 별도 스냅샷 저장이 필요한지
   설계 스파이크로 결정한다.
3. 실행 실패(4xx/5xx, 타임아웃 등) 시 사용자에게 명확한 실패 사유를 안내하고 재시도/폴백
   정책을 정의한다(묵살 금지).
4. 이번 Story는 **설계 문서·데이터 모델 스파이크**만 포함하며, 실제 실행 엔진 구현은 Story 1.35에서
   진행한다(범위 분리로 리스크 점진적 감소).
