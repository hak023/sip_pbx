# Story 1.3: 서비스 이용 매뉴얼 RAG 연동

## Status

Done(2026-07-20/21 `master-qa.md` Branch B로 실서버 검증까지 완료)

## Story

**As a** 테넌트 관리자,
**I want** 사용법을 자연어로 질문하면 정확한 안내를 받기를,
**so that** 문서를 직접 찾아볼 필요가 없다.

## Acceptance Criteria

1. 고객 친화적 매뉴얼 콘텐츠(신규 작성)가 `doc_type=self_service_manual`로 ChromaDB에 색인된다.
2. 셀프서비스 세션의 RAG 검색은 `owner` 필터 + `doc_type=self_service_manual`로 제한된다.
3. 매뉴얼에 없는 질문은 "제가 알지 못하는 내용" 안내로 폴백한다(기존 `RESPONSE_UNKNOWN_NEEDS_FOLLOWUP` 패턴 재사용).

### Integration Verification

- **IV1**: 기존 `knowledge` doc_type 검색 결과에 `self_service_manual` 문서가 섞여 나오지 않는다(테넌트 고객용 RAG와 완전 분리).
- **IV2**: 기존 RAG 검색 성능(지연)이 신규 doc_type 추가로 저하되지 않는다.

## ⚠️ Story 준비 중 발견된 사실 (SM 사전 조사)

PRD/Architecture는 "RAG 검색을 `doc_type=self_service_manual`로 제한"이라고만 서술했으나, **실제 코드를 확인한 결과 이 제한 방식에 중요한 제약이 있다**:

`src/ai_voicebot/ai_pipeline/rag_engine.py`의 `RAGEngine.__init__()`은 `doc_type_allowlist` 파라미터를 **생성자 시점에 한 번만** 받는다(인스턴스 전체에 고정, `self._doc_type_allowlist`). **검색 호출(`.search()`)마다 동적으로 바꿀 수 있는 파라미터가 아니다.** 현재 메인 RAG 엔진 인스턴스는 `src/ai_voicebot/factory.py`에서 `config`의 `doc_type_allowlist`로 한 번 생성되어 테넌트 고객 질의 전체(`question` intent 등)에 공용으로 쓰인다.

**결론**: 셀프서비스 세션이 메인 RAG 엔진 인스턴스를 그대로 쓰면 `self_service_manual` doc_type만 검색하도록 제한할 방법이 없다(AC2 위반 위험). **별도의 경량 `RAGEngine` 인스턴스**(동일 `embedder`/`vector_db`, 단 `doc_type_allowlist=["self_service_manual"]`로 생성)를 셀프서비스 전용으로 만들어 사용해야 한다.
