# Story 1.9: 자동설정 변경 이력 프론트엔드 페이지

## Status

Draft

## Story

**As a** 테넌트 관리자,
**I want** AI가 최근에 무엇을 바꿨는지 화면에서 확인하기를,
**so that** 대화로 변경한 내용을 신뢰하고 검증할 수 있다.

## Acceptance Criteria

1. `sip-pbx/frontend/app/settings/ai-assistant`(가칭) 신규 페이지에서 최근 자동설정 변경 이력이 목록으로 표시된다.
2. 각 항목은 변경 도메인·필드, 이전값→새값, 변경 시각, 관련 call_id를 표시한다.
3. 기존 설정 페이지 컴포넌트/레이아웃 컨벤션을 따른다(CR3).

### Integration Verification

- **IV1**: 신규 페이지 추가가 기존 `settings/*` 라우트의 네비게이션·레이아웃에 영향을 주지 않는다.

## Dev Notes

### Previous Story Insights

Story 1.8에서 `self_service_config_changes` 테이블과 이중 로깅이 이미 구현되어 있다. 본 Story는 그 데이터를 **읽기만** 하면 된다 — 이번 Epic에서 유일하게 신규 REST 엔드포인트가 필요한 Story(다른 Story는 모두 기존 서비스 레이어 직접 호출로 충분).

### File Locations

```
src/api/routers/self_service.py (신규, 또는 기존 라우터에 엔드포인트 추가)
sip-pbx/frontend/app/settings/ai-assistant/page.tsx   # 신규
```
[Source: [architecture#source-tree](../architecture/self-service-ai-assistant-architecture.md)]

### Technical Constraints

- **CR3**: 기존 `settings/persona` 등의 Next.js App Router 컨벤션(`'use client'`, `useState`/`useEffect` 데이터 로드 패턴)을 그대로 따른다.
- 이 Story만 예외적으로 신규 REST 엔드포인트가 필요하다 — Architecture 문서의 "신규 엔드포인트 없음" 원칙에 대한 유일한 예외이며 사전에 문서화되어 있다.

## Testing

### Testing Standards

- **Test file location**: `tests_new/test_self_service_config_changes_api.py`(백엔드), 프론트엔드는 수동 검증(기존 프로젝트에 프론트 자동 테스트 관행 부재 — Dev가 발견 시 기존 관행 따름)
- **Framework**: pytest(백엔드)
- **필수 테스트 케이스**:
  1. `owner` 필터가 정확히 적용되어 다른 테넌트 이력이 섞이지 않음
  2. 정렬(`changed_at DESC`)이 올바름
  3. 페이지 렌더링 시 기존 `settings/*` 네비게이션에 회귀 없음(수동 확인)
