## Story

**As a** 신규 테넌트 관리자,
**I want** 업로드한 OpenAPI 스펙에 정의된 API를 AI가 실제로 호출해 설정을 바꾸거나 값을 조회해
주기를,
**so that** 지식만 안내받는 게 아니라 실제로 그 시스템을 대신 조작해주는 AI 비서를 쓸 수 있다.

## Acceptance Criteria

1. Story 1.34에서 승인된 엔드포인트에 대해, LangGraph Tool-calling 3단계 폴백 구조(booking_agent.py
   패턴)에 연결 가능한 동적 Tool이 런타임에 생성된다 — 엔드포인트 경로/메서드/파라미터 스키마를
   기반으로 Gemini function-calling 스키마를 자동 조립한다.
2. 실행 시 실제 HTTP 요청을 수행하고(인증 헤더는 업로드 시 등록한 값 사용), 응답을 자연어로
   요약해 사용자에게 전달한다. **이때 "어느 시스템으로 보낼지"(base_url)와 "어떻게
   인증할지"는 반드시 업로드 시점에 캐프처되어 DB에 영속화되어야 하며(2026-08-06 추가),
   이 값이 없으면 실행 자체가 불가능해야 한다(목적지 없이 추측해서 실행하지 않음).
3. 쓰기 실행 전에는 반드시 확인 발화(기존 2턴 확인→실행 패턴, Story 1.8)를 거친다.
4. 실행 결과는 Story 1.34에서 설계한 undo 메커니즘으로 기록되어, "방금 한 거 취소해줘" 요청에
   대응 가능해야 한다(Story 1.17 Undo Tool과 동일한 사용자 경험).
5. 기존 SIP PBX 테넌트(owner 9001/9003)의 하드코딩 카탈로그 기반 자동설정(Epic 1/2)은 이 Story로
   대체되지 않고 그대로 유지된다(신규 경로는 **업로드 기반 신규 테넌트**를 위한 추가 경로).
6. **(2026-08-06 신규)** OpenAPI 스펙의 `servers[0].url`을 자동 추출해 업로드 폼 기본값으로
   제안하되, 테넌트가 직접 override 가능해야 한다(스펙에 servers가 없거나 사설 IP인 경우 대비).
7. **(2026-08-06 신규)** 인증 정보(API 키/Bearer 토큰 등)는 업로드 폼에서 입력받아 DB에 저장되되,
   응답·로그에는 절대 평문으로 노출되지 않아야 한다(OWASP).

### 실서버 IV 검증 결과(2026-08-06) — 메타데이터 누락 버그 발견·수정

- 가상 "Demo Order API"(OpenAPI, GET/orders+POST/orders) 업로드 → `PATCH /api/knowledge-base/
  documents/{id}/approve-methods`로 POST/DELETE 승인 → 응답 `approved_methods: [GET, DELETE,
  POST]` 정상 확인(AC1).
- **버그 발견**: 승인 직후 `GET /api/knowledge-base/documents` 목록 응답에서 해당 문서의
  `approved_methods` 필드가 누락(응답 모델에 필드 자체가 없었음)되는 것을 발견 — DB 계층
  (`_row_to_dict`)은 이미 올바르게 매핑하고 있었으나 API 라우터 계층(`KnowledgeDocumentItem`/
  `_to_document_item()`)에서 누락된 것을 확인.
- **수정**: `KnowledgeDocumentItem`에 `approved_methods: List[str] = []` 필드 추가,
  `_to_document_item()`이 `record.get("approved_methods")`를 매핑하도록 수정. 기존
  DB 계층 단위테스트(32건) 재실행 그대로 통과.
- **재검증(브라우저, Story 1.37 카드 UI와 통합 검증)**: 같은 가상 문서를 업로드해

  확인(Story 1.37 IV와 동일 세션에서 통합 검증). 테스트 문서는 검증 후 삭제해 운영
  데이터에 영향 없음.
