# Story 1.5: 온보딩 체크리스트 안내

## Status

Draft

## Story

**As a** 테넌트 관리자,
**I want** 아직 설정하지 않은 항목이 있으면 AI가 먼저 알려주기를,
**so that** 놓친 초기 설정 없이 서비스를 온전히 활용할 수 있다.

## Acceptance Criteria

1. `get_onboarding_checklist` Tool이 **설정 카탈로그(Story 1.4)의 조회 함수**를 사용해 미완료 항목(예: 페르소나 미등록, 지식베이스 미업로드, 알림 미설정)을 판별해 목록으로 반환한다.
2. 셀프서비스 세션 시작 시 미완료 항목이 있으면 AI가 먼저 안내하고, 사용자가 원하면 바로 해당 항목의 자동설정 Tool(Story 1.8)로 이어간다.
3. 모든 항목이 완료된 테넌트는 체크리스트 안내를 생략하고 일반 질의응답으로 진행한다.

### Integration Verification

- **IV1**: 체크리스트 판별 로직이 설정 카탈로그의 조회 함수만 사용하며 별도 완료 여부 저장소를 새로 만들지 않는다(단일 진실 소스 원칙).
- **IV2**: 체크리스트 안내가 기존 셀프서비스 진입 인사말(Story 1.2) 흐름 뒤에 자연스럽게 이어지고 응답 지연을 유의미하게 늘리지 않는다.

  - [ ] 미완료 항목이 있으면 안내 후 사용자 응답에 따라 Story 1.8의 자동설정 Tool로 자연스럽게 연결(LLM 프롬프트 지시로 처리, 별도 하드코딩 라우팅 불필요)

## Dev Notes

### Previous Story Insights

Story 1.4에서 `settings_catalog.list_domains()`/`get_domain_value()`가 이미 구현되어 있다. 본 Story는 이를 소비하는 첫 번째 기능이다. Story 1.2의 `self_service_agent_node` 골격에 온보딩 체크리스트 호출을 추가한다.

### File Locations

```
src/ai_voicebot/self_service/onboarding.py    # 신규 — 미완료 판정 로직
src/ai_voicebot/self_service/tools.py         # 신규(또는 기존 파일에 추가) — get_onboarding_checklist Tool
src/ai_voicebot/langgraph/nodes/self_service_agent.py  # 기존 파일(Story 1.2/1.3) 수정
```

### Technical Constraints

- **IV1**: 완료 여부를 캐싱하거나 별도 DB에 저장하지 않는다 — 매번 카탈로그를 통해 실시간 조회(단일 진실 소스).
- **IV2**: 체크리스트 조회가 7개 도메인 전체를 매번 순회하므로, 도메인 수가 늘어나도 지연이 커지지 않도록 병렬 조회(`asyncio.gather` 등)를 고려— 단, 각 `get_fn`이 동기 함수라면 순차 호출도 무방(실제 지연 측정 후 결정).

## Testing

### Testing Standards

- **Test file location**: `tests_new/test_self_service_onboarding.py`
- **Framework**: pytest
- **필수 테스트 케이스**:
  1. 미완료 항목이 있는 테넌트 → 체크리스트에 해당 항목 포함
  2. 모든 항목 완료된 테넌트 → 빈 체크리스트 반환(AC3)
  3. 체크리스트 조회가 카탈로그 조회 함수만 호출하고 별도 저장소를 만들지 않음(IV1, 코드 리뷰 기준)
  4. 체크리스트 안내 포함 세션의 첫 응답 지연이 NFR1 기준 내(IV2)
