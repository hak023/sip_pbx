# Story 1.7: 이용 통계 조회 Tool

## Status

Done(2026-07-20/21 `master-qa.md` Branch E로 실서버 검증까지 완료)

## Story

**As a** 테넌트 관리자,
**I want** "이번 달 AI가 몇 번 응대했어?"를 물어보면 답변을 받기를,
**so that** 대시보드를 열지 않고도 운영 현황을 파악할 수 있다.

## Acceptance Criteria

1. `get_self_service_stats` Tool이 기간(이번 주/이번 달)별 통화 수, 평균 confidence, HITL 발생 건수를 반환한다.
2. 응답은 기존 통계 소스를 재사용하며 별도 집계 로직을 새로 만들지 않는다(NFR3).
3. 지원하지 않는 기간·조건 질의는 "정형화된 질의만 가능합니다" 안내로 폴백한다(MVP 범위 명시, Brief §Out of Scope 반영).

### Integration Verification

- **IV1**: 통계 Tool 호출이 기존 통계 데이터 소스의 정합성을 깨지 않는다(읽기 전용 접근만 수행).

## ⚠️ Story 준비 중 발견된 사실 — PRD 가정 정정

PRD는 "`StatisticsCollector`/CDR 등 기존 통계 소스 재사용"이라고 서술했다. **코드 확인 결과 두 소스의 성격이 다르다**:

| 소스                                                                                                | 스코프                                                                                                | 셀프서비스(테넌트별) 적합성                                   |
| --------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| `src/events/statistics.py::StatisticsCollector`                                                     | **전역 프로세스 싱글턴**(`get_active_call_count`, `get_event_counts` 등) — owner/테넌트 파라미터 없음 | ❌ 부적합 — PBX 전체 통계(운영 대시보드용), 테넌트별 분리 불가 |
| `src.common.call_record_db.get_call_records_page(owner=..., limit=..., offset=...)`                 | **owner 파라미터 지원**(`src/api/routers/metrics.py::_count_unresolved_calls`에서 실제 사용 확인)     | ✅ 적합 — 테넌트별 통화 이력 조회 가능                         |
| `src/api/routers/metrics.py`의 평균 confidence 계산 로직(`_avg_confidence` 유사 함수, 라인 80 부근) | 확인 필요(owner 스코프 여부 미검증)                                                                   | 🔶 재검증 필요                                                 |

**결론**: `get_self_service_stats`는 `StatisticsCollector`가 아니라 **`src.common.call_record_db.get_call_records_page(owner=owner, ...)`를 기반으로 기간 필터링 + 집계**를 수행해야 한다. HITL 발생 건수 소스는 `src/api/routers/hitl.py`를 추가로 확인해야 한다(Dev 작업 시 재검증).

## ✅ Task 0 재검증 결과 (2026-07-15)

| 항목                   | 확정된 소스                                                                                                                                                                                                                                                                                                                                                                                                                                                    | 비고                       |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------- |
| 통화 수 / AI 응대 건수 | `call_record_db.get_call_records_page(owner=, since=)` → `total`, `is_ai_handled` 카운트                                                                                                                                                                                                                                                                                                                                                                       | 신뢰 가능, PRD 가정과 일치 |

| HITL 발생 건수         | `src/api/routers/hitl.py`의 `HITLService._hitl_request_fifo`는 **프로세스 메모리에만 존재하는 일시 구조**로(통화 종료 시 소멸) 이력 조회에 부적합함을 확인. 대신 각 통화 종료 시 `call_insights_buffer.py`가 저장하는 **`call_insights.json`의 `ai_unhandled_resolved_by_hitl_count`** 필드가 유일한 영속 소스임을 확인 — `metrics.py::_count_unresolved_calls`와 동일한 `recordings_dir` 조회 패턴으로 합산                                                   |
