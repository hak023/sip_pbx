# Story 1.44: 응대 유형 탐색기(IntelliDecision × 실제 채팅 통합)

## Status
Draft

> 상세 배경·UI 미리보기(검토 필요): [Epic 4 계획 리포트](../reports/2026-08/2026-08-06_epic4_platform_maturation_and_ux_transparency_planning.md) §5(FR35-D), 와이어프레임은 리포트 본문 참고.

## Story
As a 테넌트 관리자,
I want 유형 A~I별 질문 예시를 골라 어떤 지식·hop이 활용될지 먼저 투명하게 확인한 뒤, 바로 이어서
실제 AI와 대화할 수 있기를,
so that AI 응대 방식을 신뢰하고, 필요하면 데이터를 조정해 응대를 바꿀 수 있다는 통제감을 가진다.

## Acceptance Criteria
1. 유형 A~I 9개 탭이 있고, 각 탭에는 해당 유형의 `trigger_examples` 목록이 선택 가능한
   리스트로 표시된다.
2. 각 질문 예시 옆에 `rag_enabled`/`requires_tool`/`rag_source_scope`(하이브리드 여부 포함)
   기반 배지가 표시된다.
3. 질문을 선택하면 `knowledge_base_simulate.py`(Story 1.32)를 재사용해 실제 벡터 검색을
   실행하고, 매칭 문서·hop 경로를 사람이 읽는 카드 UI로 보여준다. **LLM 응답 텍스트는 생성하지
   않는다**(Story 1.39/1.40 "시뮬레이션 금지" 원칙 계승, 카드에도 "이건 예측이며 실제 답변은
   실제 대화에서 확인하라"는 문구 명시).
4. "이대로 실제로 물어보기" 버튼을 누르면 `useActiveSmsDockStore.getState().openThreadFromCall()`
   (Story 1.39 패턴)로 실제 채팅 패널이 해당 질문과 함께 열린다.
5. 실제 채팅 패널에서는 기존과 동일하게 추가 질문을 계속 입력할 수 있다(신규 멀티턴 상태 관리
   코드 불필요 — Story 1.39 컴포넌트 재사용).
6. 백엔드 신규 API는 최소화한다 — 기존 `/intellidecision-policy`, `/knowledge-base/simulate`
   엔드포인트에 필드 추가가 필요한 경우만 신규 파라미터를 추가한다(신규 엔드포인트 추가는
   최후 수단).
