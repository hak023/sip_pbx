### Completion Notes

- **Branch L 4건 실서버 검증**: 백업→수정→업로드(검증+diff)→활성화→대화 확인→롤백 순서로 진행해 원본 상태를 오염시키지 않았다. L2(Screen Graph nav_hint 변경)는 가운데점(·) 유무로 즉시 반영된 데이터 변화를 확인(LLM이 대괄호 마커 문구 자체는 자연스럽게 생략하나 실질적 변화는 반영됨, Story 2.5 IV2와 동일 패턴). L3(화이트리스트 미등록 함수명 거부)는 명확히 PASS — `import` 응답 `ok=false`와 구체적 오류 메시지, 활성 버전은 전혀 변하지 않음(원자성 확인). L4(롤백)도 정확히 원래 문구로 복원됨.
- **L1에서 중대한 새 발견(결함③)**: `persona.writable_fields`에서 `description`을 제거한 뒤 해당 필드 변경을 시도해 거부되는지 관찰하려 했으나, 2턴째(긍정 응답) 턴이 **수정하지 않은 원본 v2 카탈로그에서도** 간헔적으로(원인 규명 전 초기 재현율 이미 6/6) Gemini가 빈 candidate를 반환해 관찰 자체가 불가능해졌다. 동일 시점 대조군(chat-relay.message_ai_reply_enabled)은 즉시 성공해, 문자열 값 필드에만 국한된 현상임을 확인하고 결함③로 문서화했다. 메커니즘 자체(DB writable_fields 변경 즉시 반영)는 Story 2.2 단위테스트로 이미 코드 레벨 검증되어 있어 L1을 "미통과"가 아닌 "대체 필드로 간접 검증"로 판정.
- **결함③ 확정 절차**: (1) persona 도메인 6회 재현 시도 6/6 실패, (2) 동일 시점 chat-relay 대조군 즉시 성공으로 "시간대 클러스터링" 가설 배제, (3) 카탈로그를 전혀 수정하지 않은 원본 v2에서도 동일 재현되어 Epic 2와 무관함 확정, (4) chat-relay의 또 다른 문자열값 필드(message_ai_reply_prefix)도 동일하게 실패하고 같은 도메인의 boolean 필드는 성공해 "문자열값 포함 여부"와의 상관관계를 추정.
