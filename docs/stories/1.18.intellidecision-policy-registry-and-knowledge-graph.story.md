## Story

**As a** 셀프서비스 AI 도우미를 유지보수하는 개발자·운영자,
**I want** IntelliDecision 유형(A~I) 판단 기준을 코드가 조회 가능한 데이터로 갖고, Screen Graph가
도메인의 쓰기 가능 여부까지 2-hop으로 알려주기를,
**so that** 새 유형 추가 시 프롬프트 번호 재조정 함정을 겪지 않고, AI가 쓰기 불가능한 도메인에서
존재하지 않는 변경·되돌리기 능력을 안내하는 환각을 구조적으로 줄일 수 있다.

## Acceptance Criteria

1. `intellidecision_policy.py`에 유형 A~I 9종이 `code`/`name`/`summary`/`trigger_examples`/
   `requires_tool`/`requires_writable_domain`/`related_types` 메타데이터로 등록되어 있고,
   `list_intent_types()`/`get_intent_type(code)`로 조회 가능하다.
2. `applicable_types_for_domain(domain, writable=...)`는 `requires_writable_domain=True`인
   유형(B/D/E/G)을 `writable=False`인 도메인에서는 제외하고 반환한다.
3. `knowledge_graph.py::traverse(domain, max_hops=2)`는 1-hop(Screen Graph 화면 정보)에 이어
   2-hop(writable 여부 → 적용 가능 IntelliDecision 유형)까지 조회한다. `max_hops=1`이면 2-hop
   필드는 비워둔다.
4. `format_decision_hint(domain)`은 화면이 등록된 도메인에 한해 "조회만 가능"/"조회·변경·되돌리기
   모두 가능" 한국어 힌트를 반환하고, 미등록 도메인은 빈 문자열을 반환한다.
5. `self_service_agent.py::_format_screen_guidance()`가 기존 1-hop 화면 안내 문구에 이어
   `format_decision_hint()` 결과를 시스템 프롬프트 `{screen_guidance_section}`에 추가로 주입한다
   (RAG 히트 → related_domain → 화면(1-hop) → 결정 힌트(2-hop) 순서로 확장).
6. 기존 프롬프트 산문(`_SELF_SERVICE_SYSTEM_PROMPT_TEMPLATE`/`_TOOL_USAGE_INSTRUCTION`)은
   변경하지 않는다(회귀 위험 최소화 — 이미 검증된 응대 품질 유지, CR 원칙).
7. 신규 단위 테스트(`test_self_service_intellidecision_policy.py`,
   `test_self_service_knowledge_graph.py`)가 모두 통과하고, 기존 self_service 관련 회귀
   테스트(26건+)가 그대로 통과한다.
8. `GET /api/settings/ai-assistant/intellidecision-policy`가 유형 A~I 9종을
   code/name/summary/trigger_examples/requires_tool/requires_writable_domain/related_types
   형태로 반환한다(축 C-1, 읽기 전용).
9. `frontend/app/settings/ai-assistant/docs/page.tsx`에 "AI 의사결정 로직" 탭이 추가되어
   위 API 응답을 카드 목록으로 렌더링하고, Tool 필요/쓰기 가능 도메인 필요 배지를 표시한다.
10. "AI 의사결정 로직" 탭에 "표 보기"/"그래프로 보기" 토글이 있어, 그래프 모드에서는
    유형 A~I를 순수 SVG(신규 npm 의존성 없이)로 원형 배치하고 `related_types` 관계를
    선으로 그려, `requires_writable_domain` 여부를 노드 색으로 구분한다(축 C-2).

## Dev Notes

- **범위 축소 결정(의도적)**: 리서치 §4 축 A의 완전한 목표(프롬프트 산문 자체를 레지스트리에서
  자동 렌더링)는 이번 Story에서 구현하지 않았다. 기존 프롬프트는 이미 여러 Story(1.15/1.16)를
  거치며 실서버로 검증된 응대 품질이라, 레지스트리 도입과 동시에 프롬프트 렌더링 방식까지 바꾸면
  회귀 위험이 커진다(coding-standards.md의 CR 원칙). 이번 Story는 레지스트리를 **조회 가능한
  데이터 소스**로 우선 확립하고(축 C 시각화·축 B 필터링에 즉시 재사용), 프롬프트 산문의 완전한
  데이터 기반 렌더링은 후속 Story로 남긴다.
- **축 B "스마트 판단" 반영 방식**: 사용자 요청("AI 응답 시 연결된 홉으로 확장되어
  IntelliDecision이 수행되도록")에 따라, 단순히 화면 정보만 보여주는 것에서 그치지 않고 도메인의
  writable 여부를 프롬프트에 명시적 힌트로 노출했다(Anthropic "투명성" 원칙 — 판단 근거를
  데이터로 드러냄). 이로써 LLM이 유형 B/E(실행·되돌리기)를 판단할 때, 애초에 변경 불가능한
  도메인(`contacts`, `general` 등)에서는 그 가능성을 프롬프트에서부터 배제할 수 있다.
- `applicable_types_for_domain()`은 `settings_catalog.domain_writable_fields()`가 이미
  화이트리스트(Epic 2 `_UPDATE_FN_REGISTRY`) 기반이므로, DB 카탈로그 설정이 바뀌면(핫 리로드)
  이 판단도 자동으로 최신화된다 — 별도 캐시 불필요(기존 Epic 2 원칙 재사용).
- Full GraphRAG·그래프 DB·LLM 자동 엔터티 추출은 이번에도 채택하지 않았다(리서치 §3.3/§5 결론
  재확인 — 노드 규모가 작고 관계가 이미 알려져 있음).
- **축 C-1 구현**: 리서치 §4 축 C의 1단계(저비용 정적 표) 권고를 그대로 따라, 신규 API·신규
  페이지를 만들지 않고 기존 `settings/ai-assistant/docs` 페이지(Story 1.12와 동일 패턴)에
  5번째 탭만 추가했다. `GET /intellidecision-policy`는 순수 조회 전용이라 실제 응대 로직에는
  전혀 영향이 없다(단방향).
- **축 C-2 구현(사용자 승인 후 같은 세션에서 이어서 진행)**: 리서치 §4 축 C-2가 제안한
  `react-force-graph` 등 신규 npm 패키지는 도입하지 않았다 — 노드가 9개뿐이라 force-directed
  레이아웃이 불필요하다고 판단해 순수 SVG + 고정 원형 배치(삼각함수 계산)로
  구현했다. 이로써 번들 크기 증가·라이선스 검토 없이 저비용으로 시각화를 완성했다.
  `npx tsc --noEmit`/`npx eslint` 모두 통과 확인. 브라우저 자동화 클릭 검증은 이미 기록된
  전역 WebSocket 재연결 가능성 이슈(2026-07-20 메모 참고, 이 페이지에 국한 문제가 아니라
  앱 전체적 문제)로 인해 자동화 도구에서 시간 초과 된 것을 확인함 — 정적 검증(타입/린트)로
