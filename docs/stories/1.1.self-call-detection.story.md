## Story

**As a** 테넌트 관리자,
**I want** 내 번호로 전화하거나 문자를 보내면 시스템이 이를 인식하기를,
**so that** 이후 셀프서비스 전용 응대를 받을 수 있다.

## Acceptance Criteria

1. 발신측(caller_number)과 착신측(owner)의 정규화된 값이 동일하면 `ConversationState.is_self_service_session=True`가 세팅된다.
   [Source: [prd#story-11](../product/self-service-ai-assistant-prd.md), FR1]
2. 동일 owner가 아닌 일반 통화/문자는 플래그가 세팅되지 않는다(`False` 또는 미설정).
3. 판별 로직과 판단 근거(정규화된 caller/owner 값, 판정 결과)가 `call_data_record`에 로깅된다.
   [Source: [prd#story-11](../product/self-service-ai-assistant-prd.md), FR1]

### Integration Verification

- **IV1**: 기존 일반 고객 통화/문자 시나리오에서 `is_self_service_session`이 항상 `False`로 유지되고 기존 응답이 동일하게 생성됨을 회귀 테스트로 확인한다.
- **IV2**: `classify_intent`/`route_utterance`가 플래그 유무와 무관하게 예외 없이 실행됨을 확인한다(본 Story는 플래그를 세팅만 하고 아직 라우팅 분기는 만들지 않음 — 분기는 Story 1.2 범위).
- **IV3**: 플래그 판별 로직 추가로 인한 세션 시작 지연이 50ms 이내임을 측정한다(순수 문자열 비교이므로 사실상 <1ms 예상, 테스트로 명시적 검증).

### 핵심 통합 지점 (아키텍처에서 검증됨 — 반드시 준수)

PRD는 최초 "SIP 레이어(`call_manager.py`)에서 감지"를 가정했으나, 아키텍처 문서에서 코드를 추적한 결과 **다르게 확정**되었다:

```
[음성]  rag_processor.py → self._agent.process_utterance(caller_number=self._caller_id, ...)
[문자]  sip_message_ai_reply.py → agent.process_utterance(text, caller_number=from_peer, ...)
                                         │
                                         ▼
              agent.py :: ConversationAgent.process_utterance()
              ← 두 채널이 공통으로 거치는 유일한 지점, 여기서만 감지 수행
```

- `caller_number`는 `process_utterance()` 내부에서 이미 `kwargs.get("caller_number") or kwargs.get("_caller_number") or ""`로 계산되어 있다.
- `_persona_owner`는 `kwargs.get("callee") or self.owner`로 이미 계산되어 있다.
- **이 두 로컬 변수를 그대로 `is_self_service_session()`에 전달하면 되며, SIP 트랜스포트 코드는 전혀 수정하지 않는다.**

[Source: [architecture#enhancement-scope-and-integration-strategy](../architecture/self-service-ai-assistant-architecture.md)]

## Testing

### Testing Standards

[Source: [architecture#testing-strategy](../architecture/self-service-ai-assistant-architecture.md)]

- **Test file location**: `tests_new/test_self_service_detection.py`
- **Framework**: pytest (기존 프로젝트 표준)
- **커버리지**: `is_self_service_session()`은 외부 의존성 없는 순수 함수이므로 100% 분기 커버 목표
- **필수 테스트 케이스**:
  1. `caller_number == owner` (정규화 후 동일) → `True`
  2. `caller_number != owner` → `False`
  3. `caller_number`가 `sip:1004@host` 형태, `owner`가 `1004` → 정규화 후 `True`
  4. `caller_number`가 빈 문자열 → `False`
  5. `owner`가 빈 문자열 → `False`
  6. 둘 다 빈 문자열 → `False`
  7. `;` 파라미터 포함(`1004;user=phone`) → 정규화 후 비교 정상 동작
  8. 성능: 100회 반복 호출이 50ms 이내(IV3)
  9. `SELF_SERVICE_ENABLED=0` 설정 시 다른 조건이 모두 참이어도 `False` 반환(킬스위치 검증)
- **통합 테스트**: `agent.py::process_utterance()` 호출 시 `invoke_state["is_self_service_session"]`이 올바르게 세팅되는지 확인(모킹된 caller_number/owner 조합으로 인바운드/아웃바운드 양쪽 검증)
- **회귀 테스트**: 기존 intent 분류 관련 테스트 스위트가 필드 추가 후에도 그대로 통과하는지 확인(IV1, IV2)
