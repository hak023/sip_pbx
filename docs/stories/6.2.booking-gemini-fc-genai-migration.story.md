## Story

**As a** 개발자,
**I want** `booking_gemini_fc.py`의 Gemini 네이티브 Tool-calling을 `google.ai.generativelanguage`
(`glm`, protobuf 기반)에서 `google.genai.types`(pydantic 기반)로 재구현하고,
**so that** `google-generativeai`(deprecated) 의존을 제거하면서 booking/self_service의
Tool-calling 3단계 폴백 구조(`coding-standards.md` §4)와 멀티턴 상태 관리는 회귀 없이 그대로
유지된다.

## Acceptance Criteria

1. `_json_schema_to_glm_schema()`가 `_json_schema_to_genai_schema()`로 재작성되어
   `genai_types.Schema`를 반환하며, 2026-07-21 `Any` 타입 오분류 버그 수정 로직(타입 정보 없는
   필드 → STRING, `properties` 있으면 OBJECT)을 동일하게 유지한다. [Source: architecture §4.1]
2. `_langchain_tools_to_glm_tool()`이 `genai_types.Tool`/`genai_types.FunctionDeclaration`을
   반환하되 함수명·시그니처는 하위 호환을 위해 유지한다.
3. `FunctionCall`/`FunctionResponse`의 `args`/`response`가 protobuf Struct가 아니라 일반
   Python dict임을 실제 SDK로 확인한 뒤, `struct_pb2`/`ParseDict` 기반 직렬화 코드를 제거하고
   단순 dict 정제 로직으로 대체한다.
4. `build_booking_generative_model()`/`invoke_booking_model_with_gemini_fc()`가
   google-genai의 stateless 호출 방식(모델 객체가 아니라 매 호출 `config.tools`로 전달)에
   맞게 재설계되되, **호출부(`booking_agent.py`, `self_service_agent.py`)의 코드는 한 줄도
   수정하지 않는다**(CR1 — 두 함수의 반환값/파라미터는 호출부에서 항상 opaque하게만
   전달되므로 내부 표현을 자유롭게 바꿀 수 있음을 활용).
5. `test_booking_gemini_fc_schema.py`가 `genai_types` 기준으로 이식되어 전부 통과한다.
6. 실제 Gemini API 호출로 2라운드 Tool-calling 루프(function_call 발생 → FunctionResponse
   피드백 → 최종 자연어 응답)가 정상 동작함을 확인한다(추측 금지, 실제 응답으로 검증).

## Dev Notes

- 이 Story는 Story 6.1(`LLMClient`)이 노출한 `llm_client._client`(`genai.Client`)와
  `llm_client.model_name`(문자열)에 의존한다. Story 6.1 완료가 선행 조건.
- `Content(role="function", ...)`로 FunctionResponse를 보내는 방식은 기존 `glm` 코드와 동일하게
  유지했다(Gemini 백엔드가 이 role을 그대로 허용, 실 API 검증으로 확인).
- google-genai의 `FunctionDeclaration`에는 `parameters_json_schema`(원본 JSON Schema를 그대로
  전달하는 필드)도 있어 커스텀 `_json_schema_to_genai_schema()` 변환을 완전히 생략할 수도
  있었으나, 2026-07-21에 이미 검증된 `Any` 타입 처리 로직을 그대로 유지하는 것이 리스크가 더
  낮다고 판단해 기존 변환 방식을 유지했다(향후 별도 스파이크로 재검토 가능).
