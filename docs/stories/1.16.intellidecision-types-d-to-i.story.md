# Story 1.16: IntelliDecision 유형 D~I — 대화 수리·복구 패턴 6종 추가

## Status

Done (2026-07-23 코드/문서 반영 완료, 2026-07-28 실서버 IV3 검증까지 완료)

## Story

**As a** 테넌트 관리자,
**I want** 설정 변경 대화 중 정정·되돌리기·모호한 요청·여러 설정 동시 요청·지원 안 되는 요청·
반복 요청을 AI가 자연스럽게 처리해 주기를,
**so that** 대화가 불필요하게 왕복하거나 오작동(잘못된 도메인 변경)하지 않고 매끄럽게 진행된다.

## 배경

`docs/reports/2026-07/2026-07-23_intellidecision_enhancement_research.md` 리서치에서, 이
저장소에 이미 검증된 `INTENT_TAXONOMY_RESEARCH.md`(Dialogflow/Alexa/Rasa/Just AI/ISO 24617-2
근거)의 "대화 제어·복구(repair)" 개념이 일반 고객 응대 경로(`classify_intent.py`)에는
`affirm/deny/repeat/clarification` 등으로 이미 구현되어 있으나, 셀프서비스 세션은
`classify_intent` 자체를 스킵하고 자체 시스템 프롬프트(유형 A/B/C)로만 응대해 이 인프라를
전혀 재사용하지 못한다는 공백을 발견했다. 코드(`self_service_agent.py`) 재검토 결과, 확인
발화 중 정정·되돌리기·모호성 해소·일괄 처리·범위 외 이유 설명·반복 요청 6가지 상황이 명시적
규칙 없이 LLM의 임의 판단에만 맡겨져 있었다.

## Acceptance Criteria

1. **유형 D(정정)**: 유형 B 확인 발화 중 사용자가 다른 도메인/필드/값으로 정정하면, 단순
   취소가 아니라 새 대상으로 재확인 발화를 이어간다.
2. **유형 E(실행 취소/Undo)**: "방금 바꾼 거 되돌려줘"류 요청에 대해 가장 최근 변경 내역을
   조회(`get_last_self_service_change`)한 뒤 확인 발화 → 긍정 시
   `undo_last_self_service_change` Tool로 이전 값으로 되돌린다. 변경 이력이 없으면 그렇게
   안내한다.
3. **유형 F(모호성 해소)**: 대상 도메인/기능이 불명확한 발화("그거 설정 좀 바꿔줘")에는 짐작하지
   않고 먼저 되묻는다. 단, 직전 대화에서 명확히 유추 가능하면 되묻지 않는다.
4. **유형 G(일괄 처리)**: 한 발화에 여러 설정 변경이 섞여 있으면 항목별로 따로 묻지 않고 한 번에
   묶어서 확인하고, 긍정 시 각 항목을 순차적으로 Tool 호출한다.
5. **유형 H(범위 외 설명)**: 제외 목록 등으로 거부된 요청에는 Tool이 반환한 구체적 사유를
   그대로 인용해 설명한다("정책상 제한"처럼 뭉뚱그리지 않는다).
6. **유형 I(반복 요청)**: "다시 말해줘"류 요청에는 새 내용을 지어내지 않고 직전 AI 발화를
   간결히 요약해 다시 안내한다.
7. D/F/G/H/I는 Tool 호출 없이 프롬프트 규칙만으로 구현되어 기존 유형 A/B/C와 동일하게 별도
   분류 LLM 호출을 추가하지 않는다(NFR1 지연 예산 보호).
8. 유형 E만 신규 Tool 2개가 필요하며, 기존 `self_service_config_changes` 이력 테이블(Story
   1.9)을 그대로 재사용해 신규 DB 스키마 변경이 없다.

- 리서치 보고서의 우선순위 표(D/F 높음, 능력 레지스트리 높음, E 높음, I 낮음, G/H 중간)를

- 유형 E(Undo)는 새 DB 스키마 없이 기존 `self_service_config_changes`(Story 1.9, old_value
  컬럼 보유)를 그대로 읽어 "가장 최근 변경의 old_value로 재적용"하는 방식으로 구현했다 —
  `apply_self_service_setting()`을 그대로 재사용하므로 제외 목록 검사·감사 이중 기록 로직도
  자동으로 동일하게 적용된다(새로운 보안 경로를 만들지 않음).
- `_coerce_value()`는 필드명 기반으로 boolean 여부를 판단하는 기존 함수를 그대로 재사용해
  undo 시에도 DB에 문자열로 저장된 `old_value`("True"/"False")를 올바른 타입으로 복원한다.
