# Story 8.1 — MCP 게이트웨이 기반 + 동적 GET Tool 노출

## Status
Done

## Story
테넌트 관리자(owner)가 OpenAPI 스펙을 업로드하면, 해당 문서의 GET 엔드포인트가  
MCP 클라이언트(Claude Desktop, VS Code Copilot 등)에 Tool로 자동 노출되어  
자연어로 외부 REST-API를 조회할 수 있다.

## Acceptance Criteria
- AC1: `python -m src.mcp_gateway.server --owner {owner}` 가 오류 없이 stdio MCP 서버로 기동된다
- AC2: MCP 클라이언트 연결 시, 해당 owner가 업로드한 OpenAPI 문서의 GET 엔드포인트가 Tool 목록에 표시된다
- AC3: Tool 호출이 기존 `execute_api_endpoint()`를 통해 실제 외부 API를 호출하고 결과를 반환한다
- AC4: `owner` 파라미터는 MCP 클라이언트에 노출되지 않는다(서버 내부에서 CLI 인자로 고정 주입)
- AC5: 업로드된 문서가 없으면 Tool 목록이 비어있고 서버는 정상 기동을 유지한다
- AC6: 기존 REST API(포트 8000)/SIP(포트 5060)/WebSocket(포트 8001)에 아무런 영향이 없다
- AC7: `fastmcp` 미설치 시 `ImportError`가 사용자에게 명확한 안내문과 함께 출력된다

## Dev Notes
- `build_dynamic_tools_for_owner()`는 `src.booking.database.get_db`를 사용하므로  
  서버 기동 전 `DB_PATH` 환경변수가 설정되어야 한다(기존 `start-all.ps1`과 동일).
- LangChain StructuredTool의 실제 비동기 함수는 `.coroutine` 속성에 있다.  
  plain async def로 만들어진 경우(`_make_tool`이 직접 반환한 경우)는 Tool 객체 자체가 callable.
  두 경우를 `hasattr(lc_tool, "coroutine")`으로 구분해서 처리한다.
- FastMCP의 `mcp.add_tool(fn, name=, description=)`은 함수의 `__signature__`를  
  JSON Schema 생성에 사용하므로, `_strip_owner_param`이 시그니처를 정확히 수정해야 한다.
- Story 1.51에서 이미 `build_dynamic_tools_for_owner()`가 GET Tool을 항상 포함시킨다.  
  쓰기 Tool(POST/PUT/DELETE)은 Story 5.2에서 별도로 노출한다.
- 선행조건: Story 1.51 Done ✅, `knowledge_document_endpoints` 테이블 존재 확인.
- 이 Epic은 음성 턴테이킹 Epic 5(Story 5.1~5.4)와 별개다 — MCP 게이트웨이 전용 Epic 8.
