# Story 3.2: 5초 SLA 초과 원인 자동 태깅

## Status

Done(구현 + 단위 테스트 완료, 실서버 트래픽 기반 검증은 다음 세션)

> 참조원: [voice-latency-turn-taking-prd.md](../product/voice-latency-turn-taking-prd.md) FR2, NFR1

## Story

**As a** 운영자,
**I want** 응답 지연이 5초를 넘으면 어느 구간(캐시/RAG/LLM/TTS/RTP) 문제인지 자동으로 태깅되기를,
**so that** 매번 로그를 수동으로 파고들지 않아도 원인을 즉시 알 수 있다.

## Acceptance Criteria

1. Story 3.1의 구간별 계측값(T0~T5) 기준으로 `response_latency_total_sec > 5.0`이면
   `response_latency_sla_exceeded` 이벤트가 기록된다. [Source: PRD FR2]
2. 이벤트에는 가장 소요시간이 큰 구간이 `suspected_stage`(cache/rag/llm/tts/rtp_queue/unknown) 필드로
   태깅된다. 특정 임계값(예: 해당 구간이 전체의 50% 이상 차지) 기준을 명시적으로 정의한다.
3. 원인 판별이 애매한 경우(여러 구간이 비슷하게 긴 경우) `unknown`으로 태깅하되, 전체 구간별 값은
   반드시 함께 남는다(완전한 실패 대신 부분 정보 제공).
4. 5초를 초과하지 않는 정상 케이스에서는 이 이벤트가 발생하지 않는다(불필요한 로그 노이즈 방지).
