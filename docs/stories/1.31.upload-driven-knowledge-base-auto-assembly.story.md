## Story

**As a** 신규 테넌트(다른 시스템을 운영 중일 수도 있는) 관리자,
**I want** API/Tool 정보·매뉴얼·화면 설명이 담긴 상세 데이터를 업로드하기만 하면,
**so that** 이 시스템(SIP PBX 셀프서비스)에 종속되지 않은 채로 (1) 이용 매뉴얼 Q&A, (2) AI가 변경
가능한 설정 목록, (3) 화면 안내 3종의 지식베이스가 자동 구성되어 AI가 곧바로 응대할 수 있다.

## Acceptance Criteria

1. 업로드된 문서(Story 1.26의 `knowledge_documents`, 특히 `OpenApiSpecAdapter`로 파싱된 API/Tool
   스펙과 일반 매뉴얼 텍스트)로부터 다음 3종을 자동 추출·생성하는 파이프라인이 구현된다:
   - (a) 매뉴얼 Q&A: 업로드된 자유 텍스트에서 질문-답변 쌍을 추출(기존 `manual_indexer.py` 태그
     파싱 패턴을 일반화하거나, LLM 기반 Q&A 추출 — 구체 방식은 Task 1 스파이크에서 결정).
   - (b) AI 변경 가능한 설정 목록: OpenAPI 스펙의 쓰기 가능 엔드포인트(PUT/PATCH/POST 등)를
     "설정 항목" 형태(라벨/허용값/writable 여부)로 매핑. 실제 실행부(get_fn/update_fn 콜러블)와의
     결합은 이번 범위에서 하지 않는다(Non-Goal, 아래 참고).
   - (c) 화면 안내: 업로드 데이터에 화면/메뉴 설명이 포함되어 있으면 `knowledge_graph.py`의
     `document`/`api_endpoint` 노드로 등록되어 Screen Graph 스타일 안내에 활용 가능해야 한다.
2. 이 자동 구성은 **도메인 비종속**이어야 한다 — SIP PBX 전용 키워드/도메인 이름을 하드코딩하지
   않고, 업로드된 데이터의 구조(태그·섹션 제목·OpenAPI 필드명)만으로 동작해야 한다.
3. 자동 구성 결과는 Story 1.23(지식베이스 현황 탭)에서 조회 가능해야 한다(문서 수·Q&A 수·설정
   항목 수·화면 노드 수).
4. **명시적 Non-Goal(참고사항 반영)**: 업로드된 "AI 변경 가능한 설정 목록"이 실제 시스템의 진짜
   쓰기 동작과 정확히 매칭되어 실행되는 것은 이번 Story의 범위가 아니다 — 지식베이스 구성과
   Q&A/화면 안내 응대까지만 보장하며, 실제 Tool 실행 매칭은 후속 과제로 명시적으로 이연한다.
5. 기존 SIP PBX 테넌트(owner 9001/9003 등)의 하드코딩 카탈로그/Screen Graph 기반 응대는 회귀
   없이 그대로 유지되어야 한다(자동 구성은 새 데이터 소스에 대한 **추가** 경로이지 기존 경로의
   대체가 아니다).

## Dev Notes

- "참고사항: 업로드되는 데이터 기반 동작해야 하고 실제 동작사항은 달라도 됨 — 해당 매칭은 추후
  고려 사항이며 도메인 독립사항이 우선" — 사용자가 명시적으로 우선순위를 구분했으므로, Tool
  실제 실행 매칭에 시간을 쓰지 말고 지식베이스 구성 자동화에 집중할 것.
- 도메인 비종속성 검증 방법: SIP PBX와 무관한 가상의 API 스펙(예: 이커머스 주문 관리 시스템)을
  샘플로 넣어 지식베이스가 구성되는지 스파이크로 직접 실행 확인할 것(코드에 SIP PBX 키워드가
  섞여 들어가면 이 검증에서 드러난다).
