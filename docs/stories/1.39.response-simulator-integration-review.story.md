- 2026-08-05: 사용자 추가 요청으로 방향 확정 — "통합할지 재검토"가 아니라 **시뮬레이터를 삭제하고

## Story

**As a** AI 도우미의 실제 응대를 직접 확인하고 싶은 테넌트 관리자,
**I want** 별도 시뮬레이터가 아니라, 실제 SIP MESSAGE 파이프라인을 그대로 타는 채팅 패널을 통해
내가 직접 나에게 메시지를 보내 실제 AI 응답을 받아보기를,
**so that** 시뮬레이션 결과와 실제 동작이 다를 위험 없이, 진짜 응대 결과를 신뢰할 수 있다.

## Acceptance Criteria

1. 기존 "응답 시뮬레이터" 탭/UI(Story 1.27/1.32에서 구현된 시뮬레이터 화면 및 관련 프론트엔드
   진입점)를 완전히 제거한다. 백엔드 시뮬레이션 API(`knowledge_base_simulate.py`)는 다른 Story
   (1.38/1.40)에서 재사용하는 부분(예: `hop_path` 직렬화 로직)이 없는지 확인 후, 화면에서 더 이상
   호출되지 않으면 제거하거나 미사용 상태로 남긴다(무리하게 코드 삭제하다 다른 기능을 깨뜨리지
   않도록 확인 후 정리).
2. 평소에는 수신 메시지가 있을 때만 나타나는 `GlobalSmsDock` 컴포넌트를, 신규 IA의 "응대 투명성"
   섹션 내에서 **상시 활성화 상태로 노출**한다 — 테넌트 관리자가 자기 자신의 내선/전화번호로 직접
   메시지를 입력해 전송할 수 있어야 한다(현재는 수신 시에만 열리는 `useActiveSmsDockStore` 상태
   전환 로직을 이 화면 진입 시 강제로 활성화하는 방식 검토).
3. 메시지 전송은 `frontend/app/chat/page.tsx`가 이미 사용하는 테넌트 소유자 스코프 전송 로직을
   그대로 재사용한다 — 별도의 "테스트 전용" API/세션을 새로 만들지 않는다(NFR10 — 실제
   `chat-relay`/`self_service_agent` 경로 그대로 사용, `caller_number == owner` 규칙 계승).
4. 전송된 메시지와 AI 응답은 일반 SIP MESSAGE 흐름과 동일하게 `self_service_decision_log`/
   `call_data_record`에 기록되어, Story 1.38의 순서도 UI에 그대로 나타난다.
5. 음성 세션에는 이 변경이 영향을 주지 않는다(Non-Goal 유지, 채팅 세션 한정).
