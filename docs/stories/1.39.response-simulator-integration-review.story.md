## Story

**As a** BMAD 프로세스를 운영하는 개발팀,
**I want** Story 1.38(순서도 UI)이 실제 대화의 투명성을 충분히 제공하는지 검증한 뒤, 응답
시뮬레이터를 유지·통합·축소할지 결정하기를,
**so that** 중복된 투명성 도구 두 개를 유지보수하지 않고 사용자에게 가장 효과적인 하나의 경험을
제공한다.

## Acceptance Criteria

1. 채팅(SIP MESSAGE) 세션 한정으로, 실제 대화 응답과 함께 Story 1.38의 투명성 패널(순서도+
   hop_path+RAG 매칭 근거)을 실시간 노출하는 것이 기술적으로 가능한지 스파이크로 검증한다.
2. 가능하다면: 시뮬레이터의 "임의 질문 실행" 기능은 유지하되, 결과 표시 UI는 Story 1.38의
   순서도 컴포넌트로 통합한다(중복 UI 제거).
3. 불가능하다면(예: 실시간 파이프라인에 UI 갱신 훅을 넣는 것이 barge-in 등과 충돌 위험이 큼):
   시뮬레이터를 "사전 검증 전용 도구"로 명시적으로 재정의하고, 대신 시뮬레이터 자체에 Story 1.38
   순서도 컴포넌트를 임베드해 사전 검증 시에도 동일한 투명성 경험을 제공한다.
4. 음성 세션의 실시간 투명성 노출은 이번 범위에서 제외한다(Non-Goal, 리스크가 검증되지 않은
   TTS/barge-in 상호작용 — Story 4.2 선례 참고).
5. 결정 사항은 결정 지원 리포트(옵션 A/B 비교)로 문서화하고 사용자 승인을 받은 뒤 구현한다.
