## Story

**As a** 개발자,
**I want** Story 7.1의 관측 데이터를 근거로 튜닝/보조 판단/대체 모델 중 하나의 방향을 결정하고
싶다,
**so that** Story 7.3 구현이 추측이 아닌 데이터 기반으로 진행될 수 있다.

## Acceptance Criteria

1. Story 7.1의 관측 로깅(구현 후 최소 실통화 QA 샘플 수십 건 또는 1~2주 운영 데이터)을 근거로
   Smart Turn v3.2의 실제 오판 빈도·패턴을 정리한다.
2. 아래 세 방향 중 하나(또는 조합)를 결정한다:
   - (a) 파라미터 튜닝만으로 충분(예: 최소 분석 길이, 재판단 대기시간 조정)
   - (b) 애매한 경우에만 보조 LLM 판단 레이어 추가
   - (c) 대체 모델(Vogent Turn) 검토
3. 결정된 방향의 상세 설계를 작성한다(파이프라인 삽입 지점, 기존 필터와의 관계, 리스크).
4. `config.yaml`의 `smart_turn.*` 설정과 실제 코드를 연동하거나, 연동하지 않기로 결정했다면 그
   사실을 명시적으로 문서화한다(FR15).
5. Architecture 문서(§2.4)에 상세 설계가 반영된다.
