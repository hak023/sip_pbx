## Status

## Story

**As a** 테넌트 관리자,
**I want** 내 번호로 걸려오거나 내가 건 통화 이력을 자연어로 물어보기를,
**so that** 통화 이력 화면을 직접 뒤지지 않아도 원하는 통화를 바로 찾거나 통계를 알 수 있다.

## Acceptance Criteria

1. `search_call_history_by_keyword(owner, keyword)` Tool이 owner 소유 통화 중 `call_summary`에 키워드가 포함된 통화를 찾아 발신번호·통화시각·요약을 반환한다(FR15-1).
2. `get_top_caller(owner, period)` Tool이 기간("today"|"week"|"month") 내 발신번호별 통화 건수를 집계해 상위 번호(들)를 반환한다(FR15-2). 미지원 기간은 명확한 폴백 메시지를 반환한다.
3. `get_missed_calls_today(owner)` Tool이 오늘 걸려온 통화 중 응답(AI/사람 모두)되지 않은 것으로 판정된 통화의 발신번호·시각 목록을 반환한다(FR15-3). "미응답" 판정 기준은 Task 0 조사로 확정한다(현재 코드 조사 결과: `has_recording=False AND is_ai_handled=False`가 유력 후보 — 실제 통화 데이터로 재검증 필요).
4. 3개 Tool 모두 새로운 벡터 임베딩 파이프라인 없이 기존 `call_record_db.get_call_records_page(owner=...)`만 재사용한다(NFR5, Story 1.7과 동일 원칙).
5. `self_service_agent_node`의 Tool 목록에 3개가 추가되고, 시스템 프롬프트에 사용 안내가 포함된다.

## Dev Notes

### 설계 결정: RAG가 아닌 구조화 검색 채택 이유

브리프·사용자 요청은 이 기능을 "RAG를 통해 통화 이력에 접근"한다고 설명했으나, 코드 조사 결과
통화 이력은 이미 SQLite `call_records`에 구조화되어 있고 요약 텍스트(`call_summary`)까지 저장되어
있다. Story 1.11(Screen Graph)이 Full GraphRAG 대신 경량 정적 레지스트리를 택한 것과 동일한
원칙("코드베이스 규모에 맞지 않는 과잉 인프라 도입 지양")에 따라, 새 벡터 임베딩 파이프라인을
구축하지 않고 **Tool-calling + 구조화 검색/집계**로 구현한다(PRD NFR5). "가장 많이 전화한 번호"
같은 집계 질의는 애초에 벡터 유사도 검색으로 풀 수 있는 문제가 아니라 구조화 질의가 정답이라는
점도 이 결정을 뒷받침한다.

### Previous Story Insights

- Story 1.7(`stats.py`)이 이미 `call_record_db.get_call_records_page(owner=..., since=...)`를
  owner 스코프 통계 조회의 신뢰할 수 있는 소스로 검증했다 — 본 Story는 동일 함수를 재사용한다.
- PO/QA 리뷰(2026-07-15)에서 발견된 "owner는 LLM이 무엇을 보내든 세션 owner로 강제 오버라이드"
  패턴이 `self_service_agent.py::_run_self_service_tool_loop()`에 이미 구현되어 있으므로, 본
  Story의 Tool 3개도 `owner`를 첫 인자로 받기만 하면 자동으로 이 보안 장치의 적용을 받는다
  (별도 코드 추가 불필요, IV3).
