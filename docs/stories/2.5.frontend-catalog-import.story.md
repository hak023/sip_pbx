# Story 2.5: 프론트엔드 설정 업로드(검증·적용·롤백)

## Status

Done

## Story

**As a** 관리자,
**I want** 편집한 설정 파일을 업로드해 반영하고, 문제가 있으면 이전 버전으로 되돌리기를,
**so that** 코드 배포 없이 안전하게 설정을 조정할 수 있다.

## Acceptance Criteria

1. 업로드 UI에서 파일 선택 → 서버 검증(FR19) → 미리보기(diff: 무엇이 바뀌는지) → 확정 적용의 흐름을 제공한다.
2. 검증 실패(필수 키 누락, 미등록 함수명 참조, 타입 오류 등) 시 구체적 오류 메시지를 보여주고 기존 설정은 변경되지 않는다(NFR7).
3. 적용 성공 시 즉시 반영되며(FR20), 화면에서 "현재 적용 버전"과 "이전 버전 목록"을 볼 수 있고 과거 버전으로 롤백하는 버튼을 제공한다(FR21).
4. 업로드·롤백 이벤트는 감사 로그(누가/언제/어떤 버전)로 남는다.

### Integration Verification

- **IV1**: 검증 실패 케이스(의도적으로 잘못된 함수명 참조)를 업로드해도 실제 카탈로그 동작이 전혀 바뀌지 않음을 확인한다(원자성 검증, 보안 핵심 시나리오).
- **IV2**: 업로드 직후 재시작 없이 대화 테스트(`/api/self-service/test/converse`)로 변경된 라벨/화면 안내가 즉시 반영됨을 확인한다(FR20 실증 — "진짜 동적"인지 기능 체크, 사용자 요청 대응).

### Completion Notes

- **감사 로그 설계 결정**: 별도 audit 테이블을 만들지 않고, 이미 버전 이력 자체가 `uploaded_by`/`note`/`created_at`(업로드 시점)을 갖고 있다는 점을 활용해, 마이그레이션으로 `activated_at`/`activated_by`(활성화·롤백 시점) 2개 컴럼만 추가 — "누가/언제 업로드했는지"와 "누가/언제 현재 버전을 활성화(또는 롤백)했는지"를 명확히 구분해 기록.
- **원자성(IV1) 구현**: `import` 엔드포인트가 카탈로그·Screen Graph 둘 다 검증을 먼저 끝낸 뒤 **둘 다 통과해야만** `save_new_version()`을 호출한다 — 하나라도 실패하면 어떠한 DB 쓰기도 일어나지 않음을 단위테스트로 명시적으로 검증(`save_new_version` 모킹 호출 기록이 빈 리스트임을 확인).
- **2단계 흐름**: `import`는 검증+diff 미리보기만 하고 비활성 버전으로 저장할 뿐(아직 반영 안 됨), 별도 `activate` 호출로만 확정 적용된다 — 이 둘을 같은 엔드포인트로 "신규 업로드 확정"과 "과거 버전 롤백"을 모두 처리한다(Story 2.1이 `activate_version()`을 이 두 용도로 겸하도록 설계해둘 것을 그대로 활용).
- **즉시 반영(FR20) 원리**: `activate` 엔드포인트가 별도로 `invalidate_cache()`를 호출하지 않아도 된다 — `catalog_config_loader.get_cached_config()`가 자체적으로 활성 `version_no` 변경을 매 호출마다 감지해 캐시를 갱신하도록 Story 2.2에서 이미 설계되어 있었기 때문(추가 구현 불필요, Story 2.2 설계의 재사용성 확인).
- **프론트엔드**: Blob 다운로드(Story 2.4)로 받은 JSON 파일을 그대로 재업로드할 수 있도록 `{catalog, screen_graph}` 탐난 형식을 그대로 사용. 검증 실패/미리보기/확정 적용/버전 이력/롤백 UI 모두 구현.
- **미확인(보류)**: ~~IV2("업로드 직후 재시작 없이 대화 테스트로 즉시 반영 확인")는 이번 신규 엔드포인트 코드를 적재한 서버가 아직 실행 중이 아니므로(코드 변경 후 재시작 필요) 사용자 승인 후 다음 재시작에서 검증 예정(프로젝트 규칙: 포트 충돌 가능 프로세스는 사용자 승인 필수). 단위테스트만으로는 "로직이 올바르다"는 것까지만 검증되고, "실제 운영 서버에서도 정말 즉시 반영되는지"는 미확인 상태임을 명시.~~ **(2026-07-21 해결)** 사용자가 서버를 재시작한 후 실제 운영 서버로 IV2를 직접 검증함 — 아래 QA Results 참고.
