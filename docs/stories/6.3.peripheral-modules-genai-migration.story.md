## Story

**As a** 개발자,
**I want** `google.generativeai`를 직접 사용하는 나머지 모듈(knowledge/ 4개, call_history.py,
ringback_service.py)을 `google-genai`로 전환하고,
**so that** `LLMClient`/`booking_gemini_fc.py`(Story 6.1/6.2)에 이어 저장소 전체에서
`google-generativeai` 직접 의존을 제거할 수 있다.

## Acceptance Criteria

1. `knowledge/entity_extractor.py`, `hallucination_checker.py`, `qa_extractor.py`,
   `summarizer.py`의 지역 `import google.generativeai as genai` + `genai.types.GenerationConfig`
   가 `from google.genai import types as genai_types` + `genai_types.GenerateContentConfig`로
   전환된다. 이 4개 모듈은 모두 `self.llm.model.generate_content(...)`(Story 6.1의
   `_GenAIModelAdapter`)를 호출하므로 어댑터 자체는 이미 전환되어 있어 로컬 임포트/설정 클래스
   명만 바꾸면 된다.
2. `api/routers/call_history.py`(`generate_unhandled_draft`)와
   `services/ringback_service.py`(`_call_llm`, `_call_llm_style_line`)는 `LLMClient`를 거치지
   않고 자체적으로 `genai.GenerativeModel(...).generate_content_async(...)`를 호출하므로,
   `google.genai.Client(api_key=...).aio.models.generate_content(model=, contents=)`(비동기
   네이티브 클라이언트)로 전환한다.
3. 응답 파싱 코드(`response.text`, `resp.prompt_feedback` 등)는 기존 `getattr` 기반 방어적
   접근이라 필드명이 google-genai와 동일함을 실제 API 호출로 확인한 뒤 변경 없이 유지한다.
4. 저장소 전체(`src/`)에서 `import google.generativeai`가 더 이상 검색되지 않는다(docstring/
   주석의 역사적 언급 제외).
5. 4개 knowledge 모듈은 실제 `LLMClient`를 통해, `call_history.py`/`ringback_service.py`
   패턴은 최소 재현 스크립트로 실 Gemini API 호출까지 검증한다.
6. `tests_new/unit` 전체 회귀(사전 무관 결함 3건 제외)가 통과한다.

## Dev Notes

- knowledge/ 4개 모듈은 자체 SDK 클라이언트를 만들지 않고 `self.llm`(전달받은 `LLMClient`
  인스턴스)의 `self.llm.model.generate_content(...)`을 호출하는 구조라, Story 6.1에서 이미
  `_GenAIModelAdapter`로 전환되어 있었다 — 이번 Story는 로컬 `import`와 `GenerationConfig`
  클래스명만 바꾸면 되는 저위험 변경이었다.
- `call_history.py`/`ringback_service.py`는 `LLMClient`를 거치지 않고 독립적으로 SDK를
  호출하는 코드라 별도 전환이 필요했다. `google-genai`는 동기 `client.models`와 별개로
  `client.aio.models`(비동기)를 제공하며, 기존 `generate_content_async()` 사용 패턴과 1:1
  대응된다.

## ⚠️ Story 범위 밖에서 발견한 기존 결함 (수정하지 않음, 별도 확인 필요)

`ringback_service.py`의 `_call_llm`/`_call_llm_style_line`가 사용하는 모델명
`"gemini-2.0-flash"`가 **이 계정에서 이미 폐지(404 NOT_FOUND)** 되어 있음을 실 API 호출로
확인했다(에러: `This model models/gemini-2.0-flash is no longer available`). 이는 SDK
마이그레이션과 무관하게 **이전부터 존재했던 결함**이다(2026-07-24 세션 인계 리포트의
"모델 교체 우회 시도 → gemini-2.0-flash 폐지 404" 기록과 일치). 본 Story는 SDK 계층 치환만
범위로 하므로 모델명 변경은 하지 않았다 — 링백 가사/스타일 생성 기능이 현재 실제로는 항상
실패하고 있을 가능성이 높으며, 별도 Story/버그 리포트로 다뤄야 한다.
