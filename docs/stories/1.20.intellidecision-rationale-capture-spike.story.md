## Story

**As a** 셀프서비스 AI 도우미를 유지보수하는 개발자,
**I want** IntelliDecision 판단 근거(유형·근거 요약)를 캡처하는 3가지 후보 방식을 실제 API로
검증하고 하나를 선택하기를,
**so that** Story 1.21(구현)이 지연(NFR6)·신뢰성 리스크가 가장 낮은 방식으로 곧바로 착수될 수
있다(재시도/완화책 없이 실제 페이로드로 사전 검증 — copilot-instructions.md 금지 사항 5 준수).

## Acceptance Criteria

1. 아래 3개 후보 방식 각각에 대해 **실제 Gemini API 호출**(mock 아님)로 최소 5회 이상 스파이크
   테스트를 수행하고, 성공률·추가 지연(ms)·구현 복잡도를 표로 기록한다.
   - (a) 구조화 출력(`response_schema`) 병행 — Tool-calling 결과와 함께 `matched_type`/
     `reasoning_summary` 필드를 한 번의 호출로 받는 방식이 현재 사용 모델(`config.yaml`
     `gemini.model`)에서 실제로 지원되는지 확인한다.
   - (b) 센티널 태그 후행 파싱 — 파싱 실패율과, 파싱 실패 시 원본 태그가 사용자 응답에 노출될
     가능성을 실제로 재현해 측정한다.
   - (c) 경량 별도 분류 호출 — 추가 왕복으로 인한 지연 증가량(ms)을 실측한다.
2. 스파이크 결과를 근거로 **하나의 방식을 최종 선택**하고, 선택하지 않은 방식의 기각 사유를
   명시적으로 기록한다(추측이 아니라 위 실측 데이터 기반).
3. 선택된 방식이 NFR6(추가 왕복 지연 없음 또는 최소화)를 충족하는지 정량적으로 확인한다.
4. 선택된 방식이 실패(파싱 실패, 스키마 거부 등)했을 때 **사용자에게 보여줄 응답 생성 흐름에
   영향을 주지 않는지**(FR30 요구사항) 실제 실패를 강제로 유도해 확인한다.
5. 결과를 `docs/reports/YYYY-MM/`에 스파이크 검증 리포트로 남기고, Story 1.21의 Dev Notes에
   최종 선택된 방식과 근거를 인용한다.

## Dev Notes

- **왜 스파이크부터 하는가**: 2026-07-21 Story 1.14에서 "재시도로 증상만 가리지 말고 실제
  페이로드/스키마를 직접 출력해 검증하라"는 원칙(copilot-instructions.md 금지 사항 5)이 실제로
  버그를 찾아낸 선례가 있다. 이번에도 3개 후보 중 어느 것이 실제로 안정적인지 **추측하지 않고
  실측**한다.
- **후보 (b)의 특별 위험**: 2026-07-29에 근본 수정한 "conversation_history 오염발 메타 JSON
  유출" 결함(`docs/reports/2026-07/2026-07-29_conversation_history_pollution_root_cause_fix.md`)과
  구조적으로 매우 유사한 클래스의 리스크다 — LLM이 지시를 무시하고 센티널 형식을 어길 가능성을
  반드시 실측 데이터로 확인해야 한다.
- **후보 (a)의 특별 확인 사항**: 저장소는 `booking_gemini_fc.py`에서 이미 Gemini 네이티브
  Function Calling을 쓰고 있다 — 이번 스파이크는 "동일 호출에서 FunctionCall과 구조화 텍스트
  출력을 동시에 요청 가능한가"를 현재 SDK(`google-genai`) 버전으로 직접 확인해야 한다(문서만
  보고 가능하다고 가정하지 않는다, Story 6.1/6.2에서 SDK 마이그레이션 시 여러 차례 "문서와 실제
  동작이 다름"을 겪은 교훈 재적용).
- 이 Story는 **코드를 프로덕션에 반영하지 않는다**(스파이크 스크립트만, `scripts/` 하위 독립
  파일). Story 1.21에서 선택된 방식만 실제 구현한다.

## QA Results

- **실제 Gemini API(`gemini-2.5-flash`, 운영 모델과 동일) 호출로 3개 후보 모두 검증 완료**.
- (a) 구조화 출력+FunctionCall 동시 요청은 API가 `INVALID_ARGUMENT`로 명시적으로 거부
  ("Function calling with a response mime type: 'application/json' is unsupported") — 문서만
  보고 가능하다고 가정하지 않고 실제 호출로 확인(coding-standards.md 방법론).
- (b) 센티널 태그는 15회 중 0회 성공(0%) — 모델이 부가 지시를 안정적으로 따르지 않는
  현상을 실측으로 확인(2026-07-29 메타 JSON 유출 결함과 동일 클래스 문제 재확인).
- (c) 별도 분류 호출은 3/3 정상 동작했으나 동기 호출 시 평균 0.82초(32~41%) 추가 지연
  확인 — 비동기 백그라운드 실행으로 변형해 채택함으로써 NFR6(사용자 체감 지연 0)을
  동시에 충족하는 대안 확정.
- 상세 결과: [2026-07-29_story_1.20_intellidecision_rationale_capture_spike.md](../reports/2026-07/2026-07-29_story_1.20_intellidecision_rationale_capture_spike.md).
