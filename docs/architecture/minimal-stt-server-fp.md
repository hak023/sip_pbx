## 0. 산정 개요

### 0.1 STT 서버 역할 (본 FP 범위)

[minimal-stt-profanity-architecture.md](./minimal-stt-profanity-architecture.md) §2.2·§3 기준, STT 서버가 **단독으로** 담당하는 역할만 본다.

| 경로 | 설명 |
|------|------|
| **호 세션** | AI Runtime → STT (호 ID·발신번호·화자 매핑·채널 바인딩) |
| **RTP** | WTIMS → STT **직연** (AI Runtime 미경유) |
| **전사** | STT → AI Runtime (interim/final·화자·타임스탬프) |

| §1 연관 기능 | STT 기여 |
|--------------|----------|
| **#1 폭언·욕설 감지** | 실시간 전사 텍스트 **공급** (판정은 NLP·LLM·Runtime) |
| **#2 실시간 자막** | interim/final 스트리밍 전사 **공급** |

**물리 전제:** STT **2대 All-Active** (+ TB 1대는 HW·검증, SW 공수에 **0.5 MM** 반영), 노드당 **L40S×1**, 클러스터 **동시 1,250 ASR 스트림** (본편 §3.2).

### 0.2 FP 유형 구분

| 유형 | FP 분류 | 본 문서 표기 |
|------|---------|--------------|
| **트랜잭션기능** | EI(등록·수정·삭제), EO(외부출력), EQ(외부조회) | §1 표 |
| **데이터기능** | ILF(내부 논리파일), EIF(외부 인터페이스파일) | §2 표 — ILF·EIF 열에 점수 부여 |

### 0.3 복잡도·가중치 (기본)

| 유형 | Low | Average | High | 본 문서 기본 |
|------|-----|---------|------|--------------|
| EI (등록·수정·삭제) | 3 | **4** | 6 | Average |
| EO (외부출력) | 4 | **5** | 7 | Average |
| EQ (외부조회) | 3 | **4** | 6 | Average |
| ILF | 7 | **10** | 15 | Average |
| EIF | 5 | **7** | 10 | Average |

### 0.4 구분(변경 규모) 정의

| 구분 | 의미 |
|------|------|
| **신규** | STT 서버·연동 규약 **최초** 구현 |
| **대변경** | 프로토콜·데이터 모델·성능 목표 **전면** 변경 |
| **중변경** | 기존 모듈 **확장** (채널 수·코덱·API 필드 추가 등) |
| **소변경** | 설정·로그·UI(관리) **경미** 조정 |

### 0.5 개발 난이도(연동) 정의

| 난이도 | 의미 | STT 해당 예 |
|--------|------|-------------|
| **소연동** | 단일 프로세스·REST/gRPC 1:1 | 헬스·메트릭 API |
| **중연동** | 2~3 시스템·스트리밍 1종 | AI Runtime 세션 API |
| **대연동** | 실시간 미디어·다중 채널·GPU | WTIMS RTP·ASR 스트리밍 |
| **극대** | 저지연·고가용·부하 임계 | 1,250 스트림 클러스터·All-Active |

### 0.6 MM 배분 원칙

- **기능점수 비율** + **개발 난이도** 가중으로 MM 배분.
- **공통·통합·부하검증** 1.2 MM 별도 (§3).
- 합계 **7.7 MM × 1,300만 ≈ 1.00억 원**.
